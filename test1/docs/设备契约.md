# 设备定义契约 1.1 / 1.2

本规范规定设备 DeviceSpec 的字段组织、引用关系及 apps 的导入边界。与 [参数契约](参数契约.md)、[接口行为契约](schema.md) 配套：参数与逐行为语义仍以两份专项规范为依据；空间接口组织采用本文的统一 interfaces，替代旧 physical_interfaces/process_ports/interface_bindings。历史示例可继续由旧导入器读取，但不能把新旧空间结构同时写入 1.1 定义。

参考完整实例：[Conveyor_aankws/schema.json](../modles/Conveyor_aankws/schema.json)。本规范是项目约定，不是 IEC 认证标准，也不是 JSON Schema Draft 文件。

## 1. 顶层字段

| 字段 | 必需性 | 内容与约束 |
| --- | --- | --- |
| contract_version | 必填 | 1.1 为待接入声明；1.2 为受限接触输送实验，未知版本拒绝 |
| schema_type | 必填 | 固定 DeviceSpec |
| schema_id / device_spec_id | 必填 | 同一稳定非空设备定义 ID，二者一致；不是场景实例 ID |
| version | 必填 | 非空设备定义修订版本，变更契约时更新 |
| device_type | 必填 | conveyor、lift_table、material_source_station、robot_arm、rotary_table、storage_rack、workpiece、workpiece_carrier |
| display_name / description | 必填 | 设备显示名与说明 |
| asset | 必填 | 本版面向 GLB 设备，model_format=glb、model_key；节点名、索引和哈希可补充 |
| params_schema | 必填，可为空对象 | 该设备实际需要的配置参数，不要求复制设备类型模板的全部可选项 |
| interfaces | 必填，可为空数组 | 统一的空间接口；安装、对接、交接使用同一结构 |
| signal_ports | 必填，可为空数组 | 设备/服务的逻辑控制与反馈接口；方向以设备为参照 |
| transport_behaviors | 必填，可为空数组 | 为兼容既有字段保留此名，实际覆盖动作、复合行为、内部机制、服务、被动响应和观测 |
| type_specific_contract | 必填，可为空对象 | 坐标约定、节点绑定、运动关系、容量模型、几何结构等类型专属内容 |
| runtime_contract | 必填 | observation_definitions 和 authorization_definitions 必须存在，可为空；按需补资源、状态和故障策略 |
| runtime_execution_contract | 必填，可为空对象 | 执行器接入、请求协议、路径解释、控制写入权、预览及校准要求 |
| source / references / notes / modeling_status | 建议 | 来源、文档、假设与成熟度；未知参数不得冒充实测值 |

参数值只在定义默认值与场景实例覆盖中维护；实时状态不写入静态定义。动作目标放在动作 arguments_schema 及请求载荷中。工艺路径、设备连接、PLC 变量名称、预留和实际占用属于场景或运行时。

## 2. 参数契约

每个参数必须有 type、required、mutability、description。type 支持 number/integer/boolean/string/enum；mutability 为 stopped_only 或 runtime_setpoint。按需提供 default、min/max、unit、options、required_when。

- enum 需非空 options，默认值必须在选项中；数值应有限，integer 不接受小数，min 不大于 max。
- required=true 表示解析后必须有值，合法 default 可以满足要求；无默认值的必填量需实例明确提供。
- required_when 的 parameter 必须存在，条件为 equals。动作参数也应声明类型和范围。
- 有量纲参数应声明单位；当前校验器不自动推断物理量或换算单位。
- 不能只为方便执行器而擅自增加每类设备都必须填写的参数。Conveyor_aankws 不再声明 speed_tolerance_mps、position_tolerance_m、minimum_gap_m；对应判据/间距由执行器与场景标定，未标定不视为满足。
- *_param 引用 params_schema，不能悬空。类型专属语义约束需由对应校验器或执行器落实，自然语言 validation_rules 本身不会执行。

## 3. 统一空间接口

每个 interfaces 条目必填 interface_id、name、capabilities.snap；interface_id 在设备内唯一。接口仅描述空间连接/吸附，不包含 process 能力、signal_refs、行为引用、物料检测或 PLC 绑定。这些旧字段在本版被拒绝，不能用空数组延续旧结构。

坐标来源三选一：local_frame={position,forward,up}；local_frame_rule 为已声明的参数化坐标规则；local_frame_pending=true 表示等待用户提供，暂不参与吸附和真实执行。长度为 m，方向是正交单位向量，坐标相对设备原点。吸附兼容性由 snap.role 与 snap.accepts 表达；accepts 指对端角色。

```json
{
  "interface_id": "end_negative_x",
  "name": "传送带负向端点",
  "local_frame_pending": true,
  "capabilities": {
    "snap": { "role": "conveyor_end", "accepts": ["conveyor_end"] }
  }
}
```

空间连接记录引用 instance_id + interface_id。吸附成功只表示空间连接成立，不自动启动设备、许可物料交接或接通信号。机械臂抓取点、TCP、物料支承点、库位和检测区域分别属于类型专属模型，而不是空间接口。

### 3.1 输送机的三类结构

| 内容 | 字段位置 | 职责 |
| --- | --- | --- |
| 端点接口 | interfaces | 仅吸附、装配及空间连接 |
| 输送面 | type_specific_contract.conveying_surface | 有效几何、法向、输送方向、驱动速度及接触模型 |
| 工艺观测区域 | type_specific_contract.observation_regions | 入口空间、出口到达、输送面占用等实际观测 |

输送面必须说明 surface_id、node_binding_role、coordinate_space、flow_axis、normal、geometry、contact、drive、material_motion 和 implementation_status。长度、宽度、高度与驱动参数通过 *_param 引用已有参数；不能再保存另一组可编辑尺寸。flow_axis 与 normal 必须正交。驱动信号是输送面执行机制读取的设备信号，不能挂在空间接口上。

当前接触式基线固定 contact.model=moving_surface_contact、material_motion=physics_contact_only：未来引擎以实际表面速度设置接触相对速度；动态物料有碰撞形状、质量、摩擦条件，通过有效支承接触参与物理求解。没有运输任务时，已经运行的输送面仍可带动物料。物料位置只由物理引擎写入，渲染读取结果；禁止动画/任务同时修改同一物料位置。

观测区域必填 region_id、surface_ref、purpose、geometry_status、observation_keys。区域 ID 唯一，surface_ref 必须存在，观测键必须在 runtime_contract.observation_definitions 登记。区域是检测用途，不是隐形挡板，也不直接给物料施加位置约束。入口可接收需要区域检测、载荷兼容和含预留容量共同判断；到达出口、离开本设备和接收方确认是不同事实。

本版先支持 pending 草稿：输送面碰撞体、摩擦与区域体积尚未标定，apps 校验声明并保留数据，不创建物理对象。真实标定结构及引擎接入应另行扩展契约版本，不能将 pending 改成一个未知的 ready 字符串就视为实现。

## 4. 信号契约

信号独立于所有空间接口。signal_ports 每条必填 port_id、direction、value_type、plc_type、description、signal_role、retention。port_id 唯一，direction 为 input/output。类型对应为 BOOL→boolean、INT/DINT→integer、REAL→number。可补单位、默认值、触发语义和写入者。

持续许可、持续状态、请求、结果锁存和采样脉冲必须通过 signal_role/retention/description 明确。信号结构检查不等于运行器已经实现握手或采样。PLC 具体地址保存在实例 bindings 中；一个逻辑输入只能有一个有效写入者。身份编号与场景字符串 ID 由登记表映射。

### 4.1 未来引擎信号管理

runtime_execution_contract.signal_management 声明管理职责：owner=simulation_engine、status=pending_engine、namespace=instance_id/port_id、definition_source=signal_ports、spatial_binding=false、write_policy=single_writer_per_input、plc_mapping=instance_bindings、sampling=simulation_step_snapshot、unknown_policy=invalid_until_provider_ready。

未来引擎依据设备 signal_ports 注册每个实例的具名信号。PLC、人工预览、调度器通过唯一有效写入者通道提交输入，设备行为消费信号快照；驱动、检测和交接服务发布输出。实例逻辑信号 ID 与 PLC 变量名不同，多个实例的同名端口不能串值。未知观测不能用声明默认值冒充已检测结果；BOOL 持续状态、请求锁存、事件序号仍分别遵循协议。

这是一份未来引擎接入契约，不是已实现的信号池；apps 目前只做声明导入、校验和映射编辑。观测区域生成内部事实，再由引擎投影为 part_ready、blocked 等设备输出，不直接在接口上存绑定。

## 5. 行为契约

每条 transport_behaviors 必填：

| 字段 | 约束 |
| --- | --- |
| behavior_id / display_name | 稳定唯一 ID 与显示名 |
| behavior_type | action、composite、service、internal、observer、passive |
| schedulable | 是否可成为生产调度任务；internal/observer/passive 不得为 true |
| executor_ref | 已实现或计划注册的执行器标识，不能仅由行为名猜测 |
| implementation_status | pending_adapter 或 implemented；标记 implemented 不替代实际注册和验收 |
| arguments_schema | 本次调用参数，不作为设备永久参数 |
| trigger | 请求、持续信号、仿真步等触发描述；当前完整保存在 source，触发编译尚未实现 |
| input_signals / output_signals | 已声明的信号引用，并与信号方向一致 |
| condition_contract | preconditions、sustaining_conditions、missing_value_policy=unknown_blocks_execution |
| completion_contract | mode、description、checks、timer_or_progress_is_success=false |

条件为 {id,label,source,key,equals}；source=parameter/observation/authorization。参数条件引用 params_schema；其他条件必须在 runtime_contract 的相应字典登记。自然语言 preconditions/effects 只能作说明，不直接 eval。

completion.mode=observed 时必须有完成检查；continuous 表示持续过程，没有单次完成终点。按物料请求的接收、到达出口、下游交接各自定义成功观测，不以动画计时或进度替代。请求关联、故障、取消、占用释放等语义按设备适用能力声明，不能仅靠一个 done 位证明所有条件。

## 6. 类型专属内容按能力填写

| 类型 | 主要内容 |
| --- | --- |
| conveyor | 输送面几何、方向、驱动动态、容量；只有实际独立驱动时才声明分区 |
| lift_table | 升降轴、平台节点、行程、层高与对接规则 |
| material_source_station | 物料模板、周期、缓存容量、生成及呈现策略 |
| robot_arm | 关节链、节点、轴向、限位、TCP、工具和 IK/FK 配置 |
| rotary_table | 转轴、台面节点、工位表、角度与定位规则 |
| storage_rack | 库位结构、容量、兼容性、预留与确认服务；静态货架不自带搬运能力 |
| workpiece | 几何、质量、抓取/支承参考、被动状态 |
| workpiece_carrier | 槽位、载荷区域、容量、占用及随动模型 |

输送机在本版增加输送面/工艺观测区域的专用字段及引用校验，其他类型结构继续保留扩展内容并检查参数引用；各类可配置参数见参数契约。

## 7. apps 内部字段与兼容性

| DeviceSpec | apps 规范化字段 |
| --- | --- |
| interfaces | spatialInterfaces |
| signal_ports | interfaces（历史内部命名，目前保存的是 SignalPort 列表） |
| params_schema | paramsSchema |
| type_specific_contract | typeSpecificContract |
| transport_behaviors | behaviors |
| executor_ref | executorRef |
| condition_contract.preconditions / sustaining_conditions | preconditions / sustainingConditions |
| completion_contract.checks / mode | completionChecks / completionMode |
| 完整输入 | source，保留协议、资源、元信息等尚未由运行器消费的声明 |

新版入口为 apps/src/domain/normalizeUnifiedDevice.ts，空间结构约束为 apps/src/contracts/spatial.ts，输送面和引擎信号契约在 apps/src/contracts/conveyor.ts，共用校验为 apps/src/validation/contracts.ts。新版拒绝新旧空间字段混写、悬空引用、非法坐标、重复 ID、信号类型/方向冲突及未登记条件来源。

未携带 contract_version 的历史 DeviceSpec 继续使用旧导入器。带 contract_version 的新导入接受 1.1/1.2；1.0 需要显式迁移：去掉接口 process/signal_refs，将工艺几何移入类型专属模型并声明引擎信号管理。包含这些旧字段的已保存统一接口定义也会被拒绝，避免静默丢失工艺语义。

明细面板分别显示空间吸附接口与设备级信号，信号的类型、方向及实例 PLC 映射独立展示。真实信号实时值、三维接口选取、自动吸附、工艺连通推断不属于本次实现。

新版条件已经进入规范化字段，但持续条件监控尚未实现，真实预览对此采用拒绝执行。pending_adapter 也禁止真实执行；MOCK 必须显式标识且不证明任何工艺条件。未来接入后应由执行器完成校准、持续条件监测及请求关联验证，再解除相应限制。

## 8. 契约 1.2：首个可执行实验分支

Conveyor_aankws 0.5.0 通过 runtime_execution_contract.template_ref=conveyor.continuous-contact@1、calibration_ref=conveyor-contact-v1 选择显式实验模板和配置。导入时校验输送面/摩擦/区域的 calibrated 状态及支持的引用，真正执行前还检查类型、参数、水平姿态、单位缩放、无导入偏移和模型资源存在性。修改 implemented 标记本身不构成运行支持。

配置文件位于 apps/src/data/runtime-fixtures。箱体尺寸为 0.10 m、质量 0.2 kg；摩擦 0.6、带面厚度 0.1 m、入口/出口区间与速度容差属于可复现的仿真实验标定，不声明硬件实测。作者参数不新增三个通用必填容差字段。

实际运行使用 RuntimeController/SimulationSession/RuntimeKernel 和 Jolt 接触后端，模板在 beforePhysics 提交表面驱动，在 afterPhysics 发布实际反馈。物料位姿仅由物理求解器产生；模型渲染不对物料做端点插值。运行快照有 tick、有效性和主体/任务关联，不保存到作者初始位姿。

1.2 当前只支持单输送机与单箱体，手动 runTag/speedTag 输入、有限的驱动/支承/到达反馈。完整设备信号声明仍保留，未实现的 PLC 身份、脉冲、交接或复位端口不能写入，不能把默认值当有效运行值，具体清单见 schema.runtime_execution_contract.supported_io。

旧单行为 AnimationAdapter 预览路径尚未连接这个场景会话，因此 preview.real_execution_available 仍为 false，场景实验的可用范围由 scene_execution 表达。持续条件 DSL、外部资源授权和下游交接服务仍未实现。旧项目不会自动升级定义；草稿 1.1 只展示/编辑，使用受支持的新版定义才能启动实验。
