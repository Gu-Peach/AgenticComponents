# 直线滑轨设备契约

设备类型 `linear_rail`，DeviceSpec 格式版本 1.1，设备定义版本 1.1.0。完整定义位于仓库的 `apps/public/scene/S07/contracts/linear_rail.json`。已通过 warehouse.virtual-linear@1 接入场景执行器；尚无通用单设备示意实验模板。

滑轨带动挂载设备沿单一直线轴定位。固定导轨与挂载设备分别拥有几何；轨道对挂载设备根施加位移，挂载设备负责升降、伸缩和载荷支承。S07 中 T1→L1、T2→L2，配对必须双向一致且符合 GLB 层级。

参数包括速度、加速度、位置容差和停稳速度。轴方向、坐标系、挂载设备、移动节点、行程与标定属于实例模型。S07 正向为世界 +X，零点为升降机根的 GLB 初始位姿；可用行程不得由轨道包围盒长度推定。

| 行为 | 参数 | 完成依据 |
| --- | --- | --- |
| move_to_location | target，具名场景端点/格位 | 根据轴与承载点解析出的本次目标到位并停稳 |
| move_to_position | position_m，单位 m | 当前请求接受、挂载设备根实际到位、停稳及载荷支承成立 |
| stop_motion | 无 | 实际停稳与当前请求的停止回执 |

运动前检查目标配置及限位、升降轴停稳、无活动虚拟交接、净空和载荷支承；原子取得轨道与挂载设备资源后重检授权。候选 profile 以局部轴和根旋转解析方向，以平台承载点计算具名目标的轴坐标。运动中保持互锁与支承。超时、取消或失败进入受控停止，未确认停止或载荷处置前保留相关资源。

输入为 target_position、execute、request_id、stop、enable；输出为 actual_position、actual_speed、accepted、busy、done、result_id、error、error_code。请求与反馈关联运行和请求身份；未知观测阻塞执行，计时或旧 Done 不构成完成。

平台交接属于 lift_table@1.2.0 的 accept_material/release_material，transfer_material 保留为兼容入口。虚拟模式使用短距离直线移动，交接要求轨道与平台停稳、端点对齐、容量预留及正确物料身份，完成时验证真实位置、接触支承及库存转移；Handler 仅作可视部件。滑轨不承担独立物料交接。
