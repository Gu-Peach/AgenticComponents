# 八类设备的参数契约与专属结构范式

本规范与 [接口及行为契约](schema.md) 配套，重点规定 params_schema 和 type_specific_contract。schema_id、name、source、asset 等前置信息继续沿用现有 DeviceSpec，不在每个范式重复。以下为建议实施的字段规范及合法 JSON 片段，**不是现有运行器已实现的配置，也不是 JSON Schema Draft 验证文件**。

数值为说明结构使用的示例默认值和编辑范围，不是实测参数或设备认证上限。节点名、坐标、载荷、速度及容差在用于实验前必须校准。模型声明、实例取值和运行观测分别保存。

空间接口遵循 [设备契约 1.1](设备契约.md)，只用于吸附与空间连接，不绑定工艺或信号。设备信号由未来引擎管理；当前只声明契约。

## 一、两类字段如何分工

| 位置 | 内容 | 示例 |
| --- | --- | --- |
| params_schema | 可配置量的类型、默认值、范围、单位、必需条件和修改时机 | 输送速度、平台宽度、槽位行列数 |
| type_specific_contract | 类型特有的结构、关系、算法配置及参数引用 | 关节拓扑、工位表、库位生成规则、运动模式 |
| 场景实例 param_overrides | 该设备实例选择的值 | 此输送机长 3 m，而设备默认 1.6 m |
| 动作请求 | 本次动作的目标 | 目标角度、工件 ID；不反写为设备永久参数 |
| RuntimeSnapshot | 实际值与状态 | 实际速度、剩余容量、当前关节角和装载数量 |

**单一来源：**可配置尺寸和能力上限只在参数定义及实例覆盖中保存权威值，专属结构使用 *_param 引用；总库位、槽位数和世界坐标由编译阶段派生。若保留缓存副本，必须带来源版本并可重新生成。

## 二、参数定义公共范式

下表为本项目的元字段约定，不能直接当作标准 JSON Schema 的 required/enum 语法。

| 元字段 | 必填性 | 规则 |
| --- | --- | --- |
| type | 必填 | number、integer、boolean、string、enum；新增类型需有校验及执行支持 |
| required | 必填 | TRUE 表示所选配置必须有解析后的值；不要求每个实例手填，可使用合法 default |
| required_when | 条件必填参数使用 | 本基线采用 parameter＋equals；条件成立后必须可解析；条件不成立可以省略且不参与执行 |
| default | 可选 | 无 default 的必填参数必须由实例明确提供，否则拒绝进入执行 |
| min/max | 数值参数按需 | 包含边界；需要严格大于零时由语义规则检查；不是从外观推断出的硬件能力 |
| unit | 有量纲数字必填 | 统一 m、s、kg、rad 等，角度输入可使用 °，转换边界显式定义 |
| options | enum 必填 | default 与实例值必须在集合中 |
| mutability | 必填 | stopped_only 或 runtime_setpoint；后者仍需单一控制写入者、界限和有效变更机制 |
| description | 必填 | 描述对象、基准和语义，避免把额定值、命令值和实际值混为一谈 |
| legacy_aliases | 可选迁移信息 | 旧名仅作导入映射，同时提供新旧冲突值应拒绝 |

字段可以按设备能力裁剪。包含某行为时必须满足其参数依赖，不能因为字段在通用库里可选，就省略当前行为实际需要的参数。专属结构的常量列表与字段说明不要求全部出现在 params_schema。

**结构范式：**

```json
{
  "device_type": "conveyor",
  "params_schema": {
    "speed_mps": {
      "type": "number",
      "required": true,
      "default": 0.4,
      "unit": "m/s",
      "min": -2,
      "max": 2,
      "mutability": "runtime_setpoint",
      "description": "目标表面速度；反向是否允许另由能力约束判断"
    }
  },
  "type_specific_contract": {
    "motion_model": {"axis": [1, 0, 0], "axis_frame": "device_local", "speed_param": "speed_mps"}
  }
}
```

这是字段写法示例，不是完整输送机实例。各节范式也只包含本文负责的三个顶层字段；完整 DeviceSpec 还需资产、接口和行为契约。

## 三、八类设备参数契约

### 1. 传送带（conveyor）

后续刚体与输送面关联的字段扩展见本文第六节；当前 JSON 范式仍是已有基线，不代表已支持拟议 1.3 刚体数组。

参考：[已有定义](E:/project/AgenticComponents/test1/docs/scene1/device_specs/conveyor_1.json)。

**params_schema：**

| 参数 | 类型／单位 | 必需条件 | 示例默认值及范围 | 含义／修改时机 |
| --- | --- | --- | --- | --- |
| `speed_mps` | number / m/s | 所选基础配置必需 | 0.4；-2～2 | 有符号目标输送速度；反向还需模式许可；runtime_setpoint |
| `length_m` | number / m | 所选基础配置必需 | 1.6；0.1～50 | 输送面长度；stopped_only |
| `width_m` | number / m | 所选基础配置必需 | 0.35；0.05～5 | 输送面宽度；stopped_only |
| `surface_height_m` | number / m | 所选基础配置必需 | 0.45；0～10 | 输送面相对设备基准的高度；stopped_only |
| `transport_mode` | enum | 所选基础配置必需 | "continuous"；选项：continuous、zoned | 整体驱动或独立分区驱动；stopped_only |
| `allow_reverse` | boolean | 所选基础配置必需 | false；按引用或业务类型校验 | 是否允许反向；还需执行器支持；stopped_only |
| `capacity` | integer | 所选基础配置必需 | 3；1～100 | 允许的同时承载件数，含预留时不得超限；stopped_only |
| `resume_threshold` | integer | 所选基础配置必需 | 2；0～99 | 积压解除后的恢复阈值；stopped_only |
| `stop_point_count` | integer | transport_mode=zoned 时必需 | 4；1～100 | 分区数量；普通模式不据此获得分区驱动能力；stopped_only |
| `accel_time_s` | number / s | 所选基础配置必需 | 0.5；0～30 | 从零到额定速度的加速时间；0表示理想瞬时切换；stopped_only |
| `decel_time_s` | number / s | 所选基础配置必需 | 0.5；0～30 | 从额定速度到零的减速时间；stopped_only |
| `release_gap_s` | number / s | transport_mode=zoned 时必需 | 0；0～60 | 相邻物料出口放行的最小间隔；stopped_only |
| `encoder_pitch_m` | number / m | 可选 | 0.0254；0.0001～10 | 每编码脉冲对应的表面行程；stopped_only |

**type_specific_contract：**

| 板块 | 必需条件 | 必须表达的内容 |
| --- | --- | --- |
| conveyor_geometry | 必填 | 尺寸引用与输送面基准；不重复保存同一尺寸数值 |
| motion_model | 必填 | 方向、速度引用和驱动动态 |
| conveying_surface | 接触式输送必填 | 有效输送面、流向/法向、接触模型与驱动参数/设备信号引用 |
| observation_regions | 工艺观测必填 | 入口、出口、占用区域；引用输送面与已登记观测，待标定不假装可检测 |
| capacity_model | 必填 | 容量计量单位和阈值来源 |
| zone_model | 分区模式必填 | 检测区、独立驱动与区间长度约束 |
| encoder_model | 使用编码反馈时必填 | 测量对象、间距和采样要求 |

**跨字段及执行约束：**

- 接触式输送不使用端点插值推进物料。输送面、物料碰撞体、摩擦和检测区域未标定时阻止真实执行；不强制将这些引擎标定项新增为每台设备的用户参数。

- 0 ≤ resume_threshold < capacity；容量计量单位固定，托盘整托与散件不能混计。
- 分区模式中 stop_point_count ≥ capacity（本例每区至多一个载荷）；产品长度和间隙应适配区间。该条件不单独证明不会碰撞。
- allow_reverse=false 时拒绝负速度；分区反转需要额外定义反向路由与放行规则。
- 普通模式可省略分区参数；有逻辑停留点不代表存在独立分区电机。
- 编码间距、最大速度、物理步与 PLC 扫描必须满足可观测性要求；不能默认任意高速都能数到每个脉冲。

**与当前模型的衔接：**保留 speed_mps、capacity、resume_threshold；将固定尺寸移入可配置参数并以 *_param 引用。旧 default_stop_point_count 不再与参数默认值分别维护。

### 2. 升降台（lift_table）

参考：[已有定义](E:/project/agent/docs/business/SimulationSchema/1.DeviceSpec/lift_table/lift_table_1.json)。

**params_schema：**

| 参数 | 类型／单位 | 必需条件 | 示例默认值及范围 | 含义／修改时机 |
| --- | --- | --- | --- | --- |
| `lift_speed_mps` | number / m/s | 所选基础配置必需 | 0.2；0.001～1 | 主升降速度上限；runtime_setpoint |
| `lift_accel_mps2` | number / m/s² | 所选基础配置必需 | 0.4；0.001～5 | 升降加减速能力；stopped_only |
| `min_height_m` | number / m | 所选基础配置必需 | 0.3；0～10 | 最低允许平台高度；stopped_only |
| `max_height_m` | number / m | 所选基础配置必需 | 2；0.01～10 | 最高允许平台高度；stopped_only |
| `upper_level_m` | number / m | 所选基础配置必需 | 1.8；0～10 | 本示例上层工位高度；stopped_only |
| `platform_length_m` | number / m | 所选基础配置必需 | 1.2；0.1～5 | 平台长度；stopped_only |
| `platform_width_m` | number / m | 所选基础配置必需 | 1；0.1～5 | 平台宽度；stopped_only |
| `max_payload_kg` | number / kg | 所选基础配置必需 | 100；0.1～5000 | 允许载荷上限，需设备依据；stopped_only |
| `position_tolerance_m` | number / m | 所选基础配置必需 | 0.02；0.0001～0.1 | 层高及定位误差界；stopped_only |
| `settle_speed_mps` | number / m/s | 所选基础配置必需 | 0.001；0～0.05 | 到位时允许的剩余速度；stopped_only |
| `transfer_module` | boolean | 所选基础配置必需 | false；按引用或业务类型校验 | 是否有独立辅助横移机构；stopped_only |
| `transfer_speed_mps` | number / m/s | transfer_module=true 时必需 | 0.3；-2～2 | 辅助输送速度；runtime_setpoint |
| `popup_stroke_m` | number / m | transfer_module=true 时必需 | 0.08；0.001～0.5 | 辅助机构行程；stopped_only |

**type_specific_contract：**

| 板块 | 必需条件 | 必须表达的内容 |
| --- | --- | --- |
| lift_motion | 必填 | 主轴、坐标系、行程和节点绑定 |
| height_levels | 层号定位时必填 | 层号与高度参数映射 |
| dock_policy | 交接必填 | 高度与静止条件 |
| transfer | 横移配置启用时必填 | 独立机构和依赖，不复用主轴写入者 |

**跨字段及执行约束：**

- min_height_m < max_height_m；每个工位高度必须位于行程内。
- 主轴与辅助横移轴不能绑定同一受控关节。
- 载荷、平台尺寸和交接口需要联合校验；高度到位不自动证明下游可接收。
- platform_node/lift_axis 为示例映射名，落地前必须匹配实际 GLB/rig；升降轴位置原点与平台基准需标定。

**与当前模型的衔接：**保留 lift_speed_mps、max_height_m，补下限、平台几何和到位阈值。原 height_levels.height_m 可迁为参数引用；不要同时修改两处高度。

## 四、解析、校验与生效顺序

1. 选择设备类型和能力配置；不强制每台设备实现本库全部可选能力。
2. 按 default 与 param_overrides 解析参数，执行类型、单位、枚举和条件必填检查；隐式缺值不得变为零。
3. 解析 *_param 等参数引用；必须指向存在且类型匹配的参数，条件模块停用时不求值其专属引用。
4. 校验几何、模式和跨字段约束，派生区间、库位、槽位、运动范围及坐标。derived_values 中公式是规则说明，实际由确定性生成器实现，不直接 eval 字符串。
5. 检查节点、关节、TCP、接口和产品引用；来源必须与当前场景及资产版本一致。
6. 检查选定行为的参数依赖，生成实例化工艺与 PLC 绑定；声明已有但执行器不支持的模式必须拒绝。
7. 执行真实反馈与物理验收。成功解析 JSON 只能证明语法正确，不证明能运动、可抓取或可完成工艺。

几何参数改变通常需要重建 rig、碰撞体、检测区及派生位置；在运行中默认拒绝此类更改。运行设定值可以改变，但由受控接口提交；设备 params 默认值、PLC 命令与实际观测仍然是不同来源。

## 五、迁移中优先处理的问题

- 传送带：speed_mps 的旧范围只允许正值；只有实际启用反转时才扩展范围。停留点数量与容量分开，区间驱动需要真实实现。
- 升降台：补充平台、行程下限与实际高度基准；层号是动作请求，不作为设备默认目标反复覆盖。
- 物料源：产品类型、周期与缓存大小是参数，buffer_count 是状态；随机种子和暂停计时必须明确。
- 机械臂：统一 speed/payload 含义；TCP 声明必须进入求解，不能只保存在 JSON。当前 urdf 是项目风格配置，不声称是完整标准 URDF。
- 旋转台：工位表定义数量，station_count 作为派生值；新增工位必须校验交接几何。
- 仓储柜：总容量来自布局和单格容量；预留策略不覆盖上层已经选定的库位。
- 物料：质量参与物理执行；抓取区域引用必须真实存在，避免沿用已移除的 physical_interface ID。
- 托盘：槽位数、行列数、间距和边距一致；实际总质量和当前装载数来自 Runtime。

配套的 [JSON 范式集合](parameter_contract_examples.json) 与本页逐类示例来自同一份数据。本次仅提供规范与范式，不自动覆盖已有 DeviceSpec 文件。后续应将这些元字段与条件规则实现为正式验证器，并以正向、缺字段、越界、引用错误和布局矛盾样本验证。

## 六、契约 1.3：刚体、输送面与真实物料的参数扩展

本节与 [004 开发计划](../../apps/docs/development-plans/004-2026-10-30-behavior-and-physics-foundations.md) 第 15–21 章配套，现已实现 Static/Dynamic 盒形代理的受限运行分支，kinematic/convex/compound 尚未支持。两份参数示例的 rigid_body_examples 保存新范式，原 examples 保留历史模板基线。

### 6.1 字段归属

| 位置 | 内容 | 规则 |
| --- | --- | --- |
| params_schema | 用户可配置的质量、尺寸、接触属性等 | 根据设备能力条件必填，使用单位、范围和 mutability |
| type_specific_contract.physics.bodies[] | body_id、motion_type、role、local_pose、collider、材料/质量引用 | 描述结构和绑定，不重复保存同一参数权威值 |
| type_specific_contract.physics.contact_materials | 摩擦、反弹和后端组合规则 | 可引用已有参数或显式标定项；不能无来源补常量 |
| conveying_surface | body_ref、流向、法向、有效输送范围、驱动信号引用 | 运动表面与刚体运动类型分开表达 |
| observation_regions | 区域位置/形状、主体与判定规则 | 只观测，不施加物理约束，不绑定到空间接口 |
| 场景实例/运行初态 | 初始位姿、必要的线/角速度 | 初速度属于场景运行配置，不是接触瞬间给物料附加的永久属性 |

### 6.2 公共刚体结构

bodies 中每项：body_id 在设备内唯一；motion_type 为 static/dynamic/kinematic；role 标识业务用途；coordinate_space=device_local；local_pose 表示刚体参考系相对设备根；collider 表示碰撞代理及局部关系。

- dynamic 必须有可解析的正质量（mass_param 或一种明确的密度派生方式二选一）及惯性/质心策略。不能把质量设为零来表示 static。
- static 不要求质量，固定输送台优先使用此类型；conveying_surface 可在其接触上施加虚拟表面速度。
- kinematic 必须有控制来源、目标位姿/速度更新规则以及已实现的后端能力。类型名称本身不会自动产生机构运动。
- 刚体运动类型、碰撞过滤层与业务角色互相独立。body_ref、材料引用、节点/子形状引用不得悬空。
- 旧单刚体 physics.body_type 通过版本迁移映射至 bodies[0].motion_type；同一版本禁止两套字段各自成为权威来源。

### 6.3 传送带条件参数

| 参数/字段 | 归属 | 必需条件 | 约束 |
| --- | --- | --- | --- |
| length_m / width_m / surface_height_m | 已有 params_schema | 基础输送面 | 沿用既有定义，不再复制尺寸 |
| deck_thickness_m | 拟新增 params_schema 或显式标定来源 | 采用盒形输送碰撞体且无已有厚度来源时 | m，严格大于零，stopped_only；不得从带面高度猜测厚度 |
| surface_friction | 拟新增 params_schema 或标定材料 | 接触输送且当前数据无显式材料参数时 | 非负有限值，无实测来源时标为仿真设定 |
| surface_restitution | 可选参数/标定材料 | 后端需要时 | 通常约定 0–1；不自行假设任何设备通用值 |
| motion_type=static | physics.bodies | 当前固定输送台 | 不因为“表面运动”改为 kinematic |
| flow_axis / normal | conveying_surface | 接触输送 | 单位向量且正交，标明坐标系；后端按声明执行或拒绝不支持方向 |
| body_ref | conveying_surface | 所有接触输送面 | 指向实际承载刚体；需要时进一步指明子形状 |

这些新增参数不是所有八类设备的通用必填字段。若已使用带版本的标定材料/厚度数据，则引用该来源，不同时新增一份独立默认值。body 中心从带面基准与厚度派生；节点名、方向枚举和绑定关系属于结构契约。

### 6.4 engine_block 动态物料

沿用已有物料参数 mass_kg、shape、length_m、width_m、height_m、friction、restitution；shape=box 不要求 diameter_m。初步包围尺寸约为 0.397172 × 0.300000 × 0.490000 m（X/Y/Z），应在实际建模时确认单位并保存来源。

新增的关键内容主要在 physics.bodies，而不是堆叠通用参数：dynamic 类型、碰撞代理、刚体局部偏移、质量引用、接触材料、惯性策略和渲染绑定。真实物料质量未知时不默认沿用实验箱体 0.2 kg；可声明 required=true 且不设 default，目录允许草稿显示，运行前要求实例补齐。

模型原点接近底面，包围盒中心约为局部 [0,0.15,0]。均匀盒代理可用该中心作仿真质心近似，必须记录近似来源。刚体运动后按完整变换恢复模型根位置，不能把刚体中心直接写到模型底部原点。

碰撞代理采用 box/convex/compound 中已支持的一种；初期只开放 box 近似。视觉网格尺寸、代理尺寸与场景缩放必须一致，变更尺寸但 GLB 不缩放的配置应锁定或拒绝。默认方向下物料与 0.5 m 带宽仅有约 0.01 m 总间隙，需要实验验证，不把 capacity 足够当作几何兼容。

### 6.5 校验阶段

1. 结构校验：字段类型、单位声明、引用、坐标系及模板/后端支持范围。
2. 定义校验：默认值若存在必须合法；允许缺少实例需要补填的必需值，标记草稿/待配置。
3. 实例解析：合并默认值与覆盖后检查当前能力全部必需参数。
4. 物理构建前校验：正质量、合法形状/尺寸、刚体偏移、接触材料、受支持运动类型及缩放。
5. 运行验收：实际接触与姿态符合近似约定，检测按主体归属，未配置或失效状态不当作有效反馈。

### 6.6 当前已实现的字段与能力

实际结构以 apps/src/contracts/rigid-body.ts 和两份发布 schema 为准。collider 采用 kind=box 与 length_param/height_param/width_param；可声明 approximation。输送碰撞厚度通过 height_param=deck_thickness_m 表达。local_pose 必填 position、单位 rotation_quaternion；可使用 surface_height_param/thickness_param 的有限高度派生规则，不能同时在可编辑数值中重复保存另一份权威高度。

Dynamic 当前只支持 mass_param 引用正 kg 质量及 inertia=uniform_box。contact_material_ref 指向 physics.contact_materials，材料引用 friction_param/restitution_param。碰撞尺寸参数使用 m，质心位置来自明确的局部绑定，不以模型原点替代。密度派生、真实惯性张量与非盒形代理仍未实现。

engine_block 的 mass_kg 无默认值；结构导入、目录和项目恢复允许此草稿状态，启动时严格要求实例补齐。刚体运动类型、角色和单位不合法时拒绝运行。尺寸与 GLB 目前固定对应，不能只改参数拉伸碰撞代理而不改变模型。

已有 1.2 箱体实验通过独立兼容入口保留；1.3 缺少所选物料或质量时不会静默生成旧箱体。
