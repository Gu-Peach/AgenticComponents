# 节拍、工步和并行放行规则

本规则补充[声明式语言规范](领域语言规范.md)，并作为十二个场景重写的依据。PLC扫描周期、仿真tick、动作周期和生产节拍是不同的时间概念。

| 概念 | 本项目含义 | 控制用途 |
| --- | --- | --- |
| PLC扫描周期 | 后端周期性采样、计算和输出的实现周期 | 后端语义适配，不能直接当生产工序 |
| 仿真tick | 当前执行配置的离散时钟，默认1/60秒 | 统一采样、仲裁、提交、超时与物理推进 |
| 工步/动作周期 | 一次动作从条件门控到结果确认的实际过程 | invoke由契约证据结束 |
| 工位周期 | 一个工位的一组工步完成一个对象的过程 | 通常为seq，内部可含branch/repeat |
| 共同分度拍 | 统一推进一次主线后，各工位停稳处理，汇合后再推进 | seq(advance, par(stations)) |
| 生产目标节拍 | 期望的单位时间产出或周期目标 | 性能指标/约束，不能强制未完成动作提前成功 |

## 1. 工步按证据推进

每个节点有唯一静态ID，每次激活另有run/iteration/request身份。动作触发一次，必须取得匹配的接受、实际完成和清理证据才能让后继成为候选。

一个周期可以包含多个PLC扫描或多个仿真tick。逻辑扫描不等于机械动作结束。delay只表示时间过去，不能用来替代停止、夹持、加工或交接证据。

允许规定最短停留时间，例如已确认工序完成后的观察间隔；也允许规定最大响应时间。两者应与完成条件分别表达。超时是失败或未知状态，不是下一工步的启动许可。

## 2. 并行节点与放行屏障

par激活所有分支候选，全部成功后才汇合。分支内部的seq保留局部顺序。共享设备或容量可能使部分动作排队，par本身不授予绕过互锁的权限。

共同运动的工位采用明确屏障：

```text
全部运动区清空且出口可接收
→ 统一分度并确认实际停稳
→ par(工位1处理, 工位2处理, ...)
→ 全部分支完成、夹持/交接终态确认、机械臂退位
→ 下一拍
```

工位空闲分支只能在“确认该工位无对象”后空操作成功；观测未知不能当作空工位。某个工位故障时应停止接纳并协调取消其他分支，不能为了维持节拍忽略故障。

独立驱动输送段可以采用事件流水：上料、加工、下料分支分别等待当前物料的到位/完成事实。单驱动主线不能因此自动获得独立区段运动。

## 3. 入口、缓冲和出口

批次清单是有限生产任务，尚未放行的对象在外部缓冲区登记。入口提供者必须同时核对实际入口位置、所属设备容量和未提交预留；不能只判断entry空就放入第二件。

操作资源释放不清除实际物料占用。提交搬运/输送前，目标容量和源主体状态必须原子复核。不可利用已经过期的target_available结果越过授权。

出口按实际到达身份接收。多个并行工位共享一个出口时，不应让出口控制器固定等待尚未到来的早序号物料，从而堵住先到物料。S09让每个机床分支负责自己的输送和接收确认，出口设备仍按容量与请求身份互斥。

## 4. 批次填充与排空

计数从冻结清单派生，不能在执行中暗中增加工作。S01采用两工位共同分度，N盘参考过程有N+2次推进，用于填充、工位处理和末端排空。每次推进仍需实际许可与完成反馈，不能按时间自动增加位置。

S02采用固定站位的三盘批组，最后一组允许不足三盘。每组明确入站运动、三个工位par拆垛、清空/退位屏障和空盘出线。它是本轮明确的实验策略，不再宣称已实现任意空闲工位的自适应重派。

S05的返工要求是订单中的布尔字段，DSL通过branch明确选择是否增加一次加工，独立目标记录各件应完成的工序次数。未知质量反馈不会自动被该字段代替；如果以后采用实际质量分支，必须接入单独的质量事实提供者。

## 5. 采样、未知和边界

每tick读取一致快照，先归并有效反馈，处理持续条件和停止，再计算后继候选和资源授权。实际命令提交和物理推进发生在后续阶段。后继最早下一个tick提交，不能依赖源码执行速度。

分支和等待采用T/F/U；未知要等待或失败。repeat的动态库存集合在激活时冻结，已知为空与未知集合区分。集合超过声明上限属于错误，不截断后继续报告成功。

有界count循环为0时不执行动作，但其声明仍属于需要检查的程序。本轮静态接口检查对无法实例化的空集合子树显式报告blocker，不能据此声称该子树全部引用已验证。

## 6. 持续控制的退出

with-control的进入设定、进入确认、持续条件、退出设定和退出确认必须分别绑定。普通失败、父par取消和超时均需执行退出。停止使用当前请求的停止证据，不能要求已经丢失的运行许可重新成立才允许停机。

持续writer与子动作写同一输入时，只有契约明确允许授权委托才可组合。不同并行分支同时占用同一个持续writer应拒绝绑定。实际资源和信号实现尚未接入时保留blocker。

## 7. 本轮检查能说明什么

当前新增前端解析九类控制节点、类型化表达式和源位置，静态检查批次数量、声明引用、契约参数与单位、分支/循环边界、持续控制配置及部分可判定前置条件。

par的分支结构和共享调用设备会被列出；这不是对所有并发交错的穷举。动态集合采用候选对象做接口检查，interface_checks不是实际动作执行次数。实际并行时间重叠、物理可达、死锁、请求去重和完成证据仍需运行器与集成测试。

S01所需advance_pitch以待实现接口登记，不能直接调用现有单托盘transport_carrier_to冒充共同分度。检查报告明确列出proposed_capability及其它运行阻塞项，全部当前程序保持executable=false。

参考架构分层可参见 [Eclipse CIF 文档](https://eclipse.dev/escet/cif/documentation-single-page.html) 中的离散事件模型、时间、并发同步与控制器实现章节；本规范的具体时钟阶段、互锁及批次规则是项目自己的定义。
