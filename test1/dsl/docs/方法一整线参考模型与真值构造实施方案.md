# 方法一：整线参考模型与适用查询真值构造实施方案

## 1. 目标与范围

本方案承接[方法一研究方案](method.md)和[算法改进方案](../algorithm/docs/改进方案与完整验证-v3.md)，用于组织接下来的独立参考模型、标准答案及实验验收工作。

目标是：给定同一份候选 DSL、设备契约、初态、任务规格、环境及查询范围，独立构造允许的整线执行路径，为适用查询提供可复查的真值证据，再用于评价被测算法。参考模型不负责规划新的工艺，不负责几何可达、真实设备验证、PLC 翻译等价或最优调度。

当前工作基础：

- 查询清单包含 27,495 条案例/环境/边界/性质组合；v3 已准入 659 条，525 条标记不适用，26,311 条尚未在 v3 中准入。它们不是独立案例数，也不表示旧参考包的其他结论均错误。
- 已有独立消息通道参考、有限交接内核、顺序计时见证和成功后态证明；尚不能将它们分别通过等同于整线计时真值完整。
- v3、v4 已有实验结果和冻结实现；它们保留用于回归与对照，不用新答案静默覆盖旧统计。
- 默认沿用 [method1-semantics/0.2](../algorithm/specs/method1-semantics-v2.json)。语义补充与变更必须区分：前者明确原有规则，后者需要新版本和受影响查询清单。

## 2. 五步路线与阶段目标

| 阶段 | 核心目标 | 主要交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| P1 性质与查询规范化 | 明确每条查询究竟判断什么 | 性质公式、查询清单、适用性与触发规则、语义问题清单 | 性质有可执行判定及边界示例，未解决语义歧义不进入对应求解 |
| P2 独立整线参考模型 | 独立生成允许的执行路径 | 参考状态、DSL 控制解释、设备/消息/故障转换、监视器 | 顺序与最小并发模型可完整枚举，满足明确的转换规则 |
| P3 按结论生成证据 | 将执行路径或证明转化为可信答案 | 见证、反例、闭合证书、保持性证书、逐查询记录 | 每条确定答案都有适用且可检查的证据 |
| P4 扩大场景与查询覆盖 | 从试点扩展到全部已声明范围 | 分阶段覆盖矩阵、未完成义务、参考模型扩展 | 每个范围有完整覆盖记录，未决不被删除或改写为通过 |
| P5 审核、冻结与重跑 | 形成可用于论文比较的真值版本 | 冻结真值包、审核报告、重跑结果及图表 | 证据可复算，比较口径一致，限制可追踪 |

主依赖为 `P1 → P2 → P3 → P4 → P5`。P2、P3 先在小范围打通，P4 每扩大一类构造都要回到 P2/P3 补模型与证据；P5 的证据检查从第一条答案开始执行，不等到最后才审核。

## 3. P1：统一性质定义与查询范围

### 3.1 阶段目标

把自然语言义务转化为带明确观察时刻、触发条件、量词和时间范围的判定。性质定义是权威依据，不能把被测代码中现有的检查项直接当作完整规范。

### 3.2 实施任务

| 性质 | 需要形式化的判定 | 必须覆盖的边界 |
| --- | --- | --- |
| V01 取料互锁 | 抓取前来源实际静止、物料仍在源区且授权有效 | 授权存在但来源移动；取料前物料被移走 |
| V02 请求关联 | 用于成功确认的结果关联同一已接受请求和当前激活 | 重复激活、旧请求、不同物料 |
| V03 证据有效性 | 消费证据时主体、请求、epoch、age、有效性均符合契约 | 恰好到失鲜边界、重启后旧证据、未知事实 |
| V04 资源互斥 | 冲突资源不同时授予不同所有者 | 不同设备共享区域；writer 与交接区冲突 |
| V05 归属一致 | 物理状态、中心归属和局部账本满足当前交接阶段规则 | 已放置但未提交、工具持有、失败后的部分效果 |
| V06 容量幂等 | 占用与预留不超容量，同一事务不重复提交 | 双请求争抢最后槽位、重复 done/提交 |
| V07 驱动退出 | scope 成功退出蕴含退出写确认和实际停稳 | 已发停止命令但未停稳；实际停止但无有效确认 |
| V08 异常隔离 | 停止未知时不虚报确认终态、不错误释放、不回滚物理事实 | 抓取后重启、放置未提交、停止确认丢失 |
| V09 独立业务目标 | 根节点成功蕴含独立 TaskSpec 目标及清理义务 | 弱化程序终检条件、错误归属、残留授权 |
| V10a 目标可达 | 存在在声明边界内满足业务目标与完成条件的路径 | 失败路径存在但另有成功路径；目标物料串号 |
| V10b 有界响应 | 首次有效接受后，在期限内到达合格响应 | 接受时钟不能被重复反馈重置；停止中不是响应 |

每条性质规范必须包含：实例化参数、观察阶段、触发谓词、判定谓词、时间范围、适用条件、空真规则，以及正例、反例、边界例。特别注意 V06 不能只查容量，V08 不能只查授权是否存在，V03 不能只记录“读过条件”。

查询身份至少为：

```text
case_id + profile + bound_ticks + property_id
+ semantic_version + property_version + input_digest
```

对现有清单逐项登记，显式区分 K=256/1000/3000/10000、nominal/delayed/fault 和试点特殊环境。不得把试点强制停止丢失改名为普通 fault。检查重复查询和缺失引用；适用性修正需保留旧值及理由。

### 3.3 关键语义约束

- accepted、done、stop_ack 是保持型状态，提供者每周期真实重新采样；交付和重复不能刷新原采样时间。
- epoch 重启不意味着物理复位；旧反馈不能关联到新请求。
- 不假设持续刷新一定最终得到新鲜反馈。
- V10a 是存在性问题。fault 环境下存在成功路径，不等于所有故障路径都能成功。
- V10b 的允许响应为确认完成、确认失败/取消，或满足隔离义务的需人工处理状态；stopping、裸故障标志、已发停止命令均不足。
- K 内无违规与无界安全分开表示。任何结论都必须携带范围。

### 3.4 交付与验收

交付 `property-spec.json`、`query-inventory.json`、`semantics-clarifications.md` 及性质边界测试清单。

验收要求：

- [x] 每个已声明性质有可执行、独立于被测实现的判定定义。
- [x] 每条查询具有完整身份、明确范围和适用性。
- [x] 不适用、未触发、窗口不足、模型不支持和求解超时有不同状态。
- [x] 存在语义歧义的查询有阻塞理由，不自动采用有利于通过的解释。

P1 交付及边界测试已落实，见 [P1 验收报告](../algorithm/artifacts/reference-p1/P1验收报告.md)。当前 27,495 条查询中，26,810 条定义已就绪、160 条旧试点查询等待时序映射、525 条保留原不适用声明。这里的勾选表示规范与问题登记通过验收，不表示所有查询已可求解或已有真值；160 条待映射查询在 P2 完成适配前保持阻塞。

## 4. P2：构造独立整线参考执行模型

### 4.1 阶段目标与独立性

读取同样的原始输入，以独立实现构造整线允许的执行路径。可以复用输入格式及参考侧解析器，但不能调用 `acverify.model`、被测后端、归约器或读取被测结果来生成真值。参考侧解析器复用前也要检查其请求绑定、循环激活和并行作用域是否覆盖新增范围。

独立性不仅是文件放在另一个目录：转换逻辑、性质监视器和证据检查应分别实现。双方共享公开语义和原始设备契约是允许的，共享被测转换函数不是独立验证。

### 4.2 状态与转换

参考状态必须显式包含：工艺节点与并行分支、请求及激活身份、设备动作阶段、驱动与许可、物料位置/支承/夹持/业务归属、授权/预留/占用/提交账本、消息及采样时间/epoch、外部事件与故障预算、性质监视器与响应期限。

每个 tick 使用冻结顺序：

```text
外部事件 → 故障注入 → 消息交付
→ 控制器观察与原子仲裁 → 设备阶段推进 → 保持状态重新采样
```

控制结构覆盖 seq、par、branch、repeat、invoke、with-control、await、delay、fail。完整枚举允许的延迟、阶段进展和故障选择，不擅自改变确定的仲裁次序，也不将并行分支简单顺序化。

初版采用朴素的有限状态枚举，保存明确的转换标签、请求身份和时间信息。先不使用新的时钟、偏序或消息语义归约；状态存储优化若用于参考模型，也需单独说明不改变转换集合。

### 4.3 组件连接与模型对应

已有消息通道和交接内核分别提供局部检查。接入整线时补齐：控制器何时提交/接受请求、设备何时改变物理效果、消息何时生效、何时提交归属、失败如何传播、停止未知时保留哪些资源。

为每类具体转换列出“来源契约规则—参考转换—被测模型可观察投影”的对应表。若利用局部证明支持整线结论，必须证明局部模型涵盖实际使用方式及组合干扰；小模型测试通过不能冒充一般精化证明。

终态封闭必须检查未完成请求和监视义务。不能因为根节点失败或某分支进入 attention 就停止探索，从而遗漏其他分支的停止或响应期限。

### 4.4 交付与验收

交付参考模型源码、状态/转换规范、转换对应表及完整小模型图。

- [x] 同一输入重复运行产生一致的规范化图和结果。
- [x] 顺序、双分支竞争、失败取消均能在有限小模型上完整枚举。
- [x] 消息、物料、资源和故障条件均来自声明输入，无默认成功事实。
- [x] 所有未知构造明确拒绝，所有不适用优化均关闭。
- [x] 参考代码的导入与数据访问审计确认未使用被测结果或转换实现。

P2 首版实现与验证见 [P2 验收报告](../algorithm/artifacts/reference-p2/P2验收报告.md)及[转换对应表](../algorithm/docs/P2参考模型与转换对应.md)。360 个语义案例完成装载和具体路径检查，12 个小模型完成闭合复核；原区间的 15 项试点枚举中 7 项闭合、8 项超时。160 条旧试点查询采用新身份迁移，不声称旧同步语义已证明等价。上述验收不等于 P3 真值准入或全部查询已穷尽。

## 5. P3：按结论类型构造真值证据

### 5.1 阶段目标

让每条确定答案都具有足够证据，明确区分存在性、普遍性和有界结论，不从单次成功执行推导所有执行均成功。

| 结论 | 最低证据要求 |
| --- | --- |
| 发现违规 | 从合法初态到违规点的参考反例，含具体故障/延迟选择 |
| 目标可达 | 在 K 内满足独立目标及完成条件的合法计时见证 |
| K 内无违规/目标不可达 | 完整覆盖相应窗口的枚举，或足够强且前提已核对的证明 |
| 有限模型全局成立 | 状态空间真正闭合，或具备初始化与逐转换保持性证明 |
| 参考超时、模型不支持、证据不足 | UNRESOLVED，并记录具体原因 |

闭合证据包含初态、状态集合、转换摘要、边界信息和后继完整性检查。仅有文件哈希或 `closed=true` 标志不足以证明闭合。证明证书记录全部适用前提和版本，检查器重新核对，不信任自报的 `verified=true`。

### 5.2 有界响应和空真

V10b 首次有效接受发生在 t 时，期限为 `t+D`，按已冻结的包含截止 tick 的规则判断。对于 K 内触发的请求，必要时继续到其期限，保持同一环境规则和故障预算；对 K 之后新触发的请求不无限扩展本轮义务集合。输出分别记录触发窗口 K 和实际检查终点。未覆盖完整期限时返回窗口不足。

故障范围、外部事件的声明若不能支持扩展窗口，不假设窗口外无故障；此时保留未决或另建明确范围的查询版本。

没有触发任何请求的安全性质可能形式上成立，但应记录 `trigger_reachability=UNREACHABLE` 与 `vacuous=true`。它不等于 NOT_APPLICABLE，也不能作为已经验证过正常请求流程的证据。触发可达性本身未决时，不擅自判断为空真。

### 5.3 交付与验收

交付逐查询答案、见证/反例、枚举闭合或逻辑证明证书，以及独立证据检查结果。

- [x] 轨迹身份、阶段效果、时间、授权和故障预算均可核查。
- [x] 普遍性结论来自完整覆盖或证明，而不是一条轨迹。
- [x] K、响应窗口、空真和适用假设均在答案中显式保留。
- [x] 篡改轨迹、输入摘要、证明前提或闭合信息会导致检查失败。
- [x] 不读取被测算法输出反填参考标签；冲突进入单独审查流程。

P3 首批证据准入与复核见 [P3 验收报告](../algorithm/artifacts/reference-p3/P3验收报告.md)及[证据规则](../algorithm/docs/P3证据准入规则.md)。新参考语义下已核验 7,807 条答案，其中 4,519 条非空真、3,288 条空真；19,163 条仍未决。旧 P1 查询和旧实验不被覆盖，语义对应完成前不能用于重算旧算法准确率。上述勾选表示证据准入流程通过验收，完整范围覆盖继续在 P4 推进。

## 6. P4：分阶段扩大场景和查询覆盖

### 6.1 阶段目标

按照构造特征逐步扩展独立真值，不直接对所有大模型盲目穷举。范围和资源预算在看被测算法结果前固定，不按其能否求解选择案例。

| 扩展阶段 | 范围 | 本阶段目标与验收 |
| --- | --- | --- |
| A 顺序试点 | S04-P01 及已有变体 | 打通接口绑定、顺序执行、停止确认、请求关联、目标与假成功；适用的试点查询有证据或具体未完成原因 |
| B 最小并发 | 双分支、共享物料、共享容量、区域/writer 竞争 | 完整枚举小模型；合法互斥、不合法交接及失败取消均有可核查路径；不按设备 ID 判断独立 |
| C 故障与外部变化 | 重启、旧/重复反馈、许可丢失、停止未知、外部替换 | 在关键交接阶段逐项覆盖故障；核对部分效果、隔离和时序义务，明确各故障允许的组合及预算 |
| D 十二场景 | 12 个场景、360 个语义案例及其声明环境/查询 | 构造特征覆盖表完整；每个适用查询登记证据状态；缺能力模型的案例明确列出 |
| E 大边界与复杂组合 | 声明的大 K、循环、并发/故障组合 | 优先使用已核查前提的组合证明；否则继续枚举；无法决定的保留未决，不能缩小问题后冒称原查询已完成 |

S04 的静态负例只验证前端错误分类，不送入动态参考枚举；语义变体才进入适用的动态查询。阶段 B/C 的最小模型是诊断和语义验证集，单独登记，不混入原始案例数和正式准确率分母。新增故障/协议变异也需要独立任务规格，不能通过修改目标来使变异通过。

为每条查询记录以下状态之一：未处理、模型待补、语义待定、证据待检查、已认证、窗口不足、求解资源不足、不适用。适用性不是根据求解结果决定；难例不得因未决而从范围清单删除。

### 6.2 交付与验收

交付 `coverage.json`、构造特征矩阵、分阶段运行清单和 `remaining-obligations.json`。

- [x] 声明范围中的案例和查询无漏项、无重复计数。
- [x] 每个阶段的新增语义先通过小模型检查，再批量运行。
- [x] 无法完成的项目具有原因、依赖和下一步措施。
- [x] 证明准入与案例筛选不依赖被测算法是否给出正确答案。

## 7. P5：审核、冻结与重跑实验

### 7.1 阶段目标

将通过检查的证据冻结成可复现真值版本，随后以同一版本评价基线和优化算法。AI 承担技术审核，不声称第三方人工审定；未完成的模型或证明不能靠审核签字消除。

### 7.2 真值记录与冻结包

每条记录至少包含：

```text
query_id, case_id, profile, property_id
semantic_version, property_version, reference_version
input_digest, contract_digest, task_digest
bound_ticks, trigger_horizon, checked_until
applicability, trigger_reachability, vacuous
verdict, scope, assumptions
evidence_kind, evidence_paths, evidence_hashes
checker_version, checker_result, unresolved_reason
```

采用新的版本目录，不覆盖现有 v1/v3 包。冻结记录同时绑定原始输入、参考实现、性质定义和检查器。修改契约或语义后生成新版本，列出失效和需要重算的查询。

### 7.3 审核和分歧处理

1. 重新检查输入、证据和源码摘要，并复算统计分母。
2. 对轨迹逐步核查，对闭合图重新检查后继覆盖，对证明检查全部前提。
3. 将参考模型与被测模型的分歧保存为独立反例；尽量缩小程序、设备和事件集合，但保留原始反例。
4. 判断分歧来自语义歧义、参考错误、被测错误还是范围不一致；保留修订理由，不能默认被测输出正确。
5. 冻结新真值后重跑适用查询；不同算法使用相同目标、环境、K 和性质定义。未来若接入 PLC 对比，也需要先完成相同问题与性质的映射。

### 7.4 报告指标与完成条件

必须分开报告：

- **真值确定率**：适用查询中具有合格参考证据的比例；空真项单列，不能隐藏。
- **触发覆盖**：安全/响应性质中，触发可达、不可达、尚未知各有多少；不把空真当成已覆盖正常执行。
- **算法求解覆盖率**：具有参考答案的查询中，算法给出确定结论的比例。
- **已回答准确率**：算法已回答且具有参考答案的查询中，与真值一致的比例；同时报告全部参考查询中的正确比例。
- **全范围未决情况**：无参考真值与有真值但算法未决分开统计，并按场景、环境、性质和父案例族分组。
- **效率**：同预算覆盖、配对耗时、内存、图规模和重复稳定性；不把超时当作正常完成时间计算加速比。

整体完成必须区分四道门：所有作业有结束记录、所有已准入答案证据有效、声明范围内适用查询真值完整、被测算法全部查询已决定。前三者不保证第四者成立；若算法仍有 UNKNOWN，应作为实验结果保留。
