# 方法一：下一轮重点实验与 PLC 对比实施方案

本方案承接[研究定位](method.md)、[P1–P5 真值构造方案](方法一整线参考模型与真值构造实施方案.md)和[P5 语义对齐方案](P5逐步执行与语义对齐方案.md)，组织下一轮算法改进与对比实验。这里规定待实施任务、交付物和验收条件，不表示新算法或 PLC 基线已经完成。

## 1. 目标、基础与研究边界

方法一的研究对象是设备契约驱动的工艺执行路径验证：给定候选 DSL、设备与工艺契约、初态、独立任务目标、环境和查询，判断允许路径中的条件、请求反馈、资源、物料状态、停止与响应义务是否成立，并给出证据和领域定位。

设备契约提供能力和状态转换知识，DSL 表达候选工艺，验证算法构造和分析转换系统。本轮不搜索新的工艺顺序，不开展空间可达、真实物理安全或最优派工研究；小规模 ST 编码用于建立验证对照，不要求实现通用 DSL→PLC 编译器。

已有基础以[P5 最终报告](../algorithm/artifacts/method1-p5-final/P5最终实验报告.md)、[验收清单](../algorithm/artifacts/method1-p5-final/P5验收清单.md)和[复现说明](../algorithm/README-final-p5.md)为准：

| 基础 | 已有范围与限制 |
| --- | --- |
| 数据集 | 576 个案例，含 360 个语义案例；父案例、变体、性质和多个 K 不作为独立统计样本 |
| 共同评价视图 | 27,495 条查询，26,970 条适用且有参考结论，525 条不适用 |
| 时间窗 | 1,065 条旧窗口不足查询留档，评价视图使用新 ID 的扩展窗口查询 |
| 触发覆盖 | 898 条触发可达性仍待定；性质有结论不等于故障处理已经被触发 |
| P5 运行 | 4,536 个作业完成；none/storage/portfolio 是同语义内部基线和消融 |
| 全量结果 | 0.5 秒下 Portfolio 覆盖率 21.38%，已回答准确率 100%，仍有 21,203 条 Unknown |
| 关键类别 | Portfolio 对违规查询正确决定 56/1,599，对可达目标正确决定 65/1,021 |
| 外部对比 | 尚无准入的 PLC 工具成绩；语义对应依据为条件性源码审核及证据检查 |

下一轮要回答三个问题：未决主要受什么限制；契约能带来什么保持性质的算法收益；相对具有同等设备知识的 PLC 验证流程，求解、建模复用和诊断有哪些可测差异。目标不预设覆盖率或加速比必须达到某个数值，也不要求所有查询都决定。

## 2. 三阶段顺序与并行试点

主顺序为：

```text
R1 瓶颈剖析与预算/规模诊断
  → R2 依据测量确定并验证核心算法机制
  → R3 冻结方法与范围，开展正式 PLC 对比和机制消融
```

PLC 基线的小规模兼容性与语义试点从 R1 同时开始，在 R2 期间完成准入。这里的并行是任务依赖安排；正式性能作业仍串行运行，避免与剖析、开发服务器或其他实验争用机器。

| 阶段 | 核心交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| R1 | 分层瓶颈报告、多预算曲线、规模诊断、PLC 兼容性矩阵 | 能区分主要资源限制和查询类型；形成有测量依据的优化选择 |
| R2 | 一项核心机制、适用性/保持性说明、独立检查及消融开关 | 小模型无决定性结论冲突，见证重放通过，未知范围可回退 |
| R3 | 冻结实验计划、共同语义 PLC 对照、独立评分、分层报告 | 所有计划作业有记录，结论和证据可追踪，未决与不支持保留 |

R1 后即使没有找到适合实施的归约，也要交付诊断和有限收益结论。若 PLC 试点不通过，只能形成内部比较结果和明确的外部对比阻塞项，不能把内部显式搜索命名为 PLC 工具基线。

## 3. R1：瓶颈剖析、预算与规模曲线

### 3.1 先冻结诊断范围

沿用 P5 的新引擎 `src/acverify_v3/`、`acverify-tick/0.3` 语义及已准入查询视图。历史 v3/v4 的结果仅作背景，不与 P5 新语义结果混合比较。源码已变化时，在新目录封存实现和输入，不恢复进旧批次。

开发诊断和正式计时分开。剖析器会增加开销，其耗时不进入性能表。先复用 P5 已固定的分层重复样本，保留原样本清单；如该样本不覆盖所需语法或规模，在运行前按公开的结构规则增加诊断层，不能只挑优化后提升的案例。

按场景、父案例、语义变体及实际 profile 分层，覆盖 seq/par/branch/repeat、外部事件、共享物料/容量和停止未知。试点特殊 profile 保留原名和原故障域。已看过的样本属于回顾性评估；若研究泛化，另行冻结未见场景或模板，不能将旧测试集重新称为盲测。

### 3.2 剖析指标与未决原因

| 维度 | 必须记录的内容 |
| --- | --- |
| 时间分解 | 输入/模型构造、状态复制、后继生成、规范化与判重、性质观察、证据整理和重放 |
| 分支归因 | 消息交付、设备阶段、故障选择、并行协调及其组合产生的候选数 |
| 搜索规模 | 展开状态、生成后继、唯一状态、重复状态、边数和最大 frontier |
| 查询进展 | 首个反例/目标见证时刻、逐性质决定时刻及最终结论 |
| 资源限制 | TIMEOUT、状态/序列化存储上限、采样 RSS 上限、watchdog、模型不支持或执行错误 |
| 语义边界 | K 截断、触发窗口和响应尾窗是否完整、参考触发是否已确定 |

不得将所有 Unknown 记为超时。现有 `STATE_OR_STORAGE_LIMIT` 等合并原因若需细分，应新增观测并验证不改变搜索语义。采样 RSS 不是操作系统硬内存限制；进程峰值若可获取，另列采集方法。

### 3.3 多预算实验

比较 none、storage、portfolio，在同一案例/profile 查询组上使用 0.5、2、10、30 秒搜索预算，各做三次独立进程重复。组内所有查询共享一次搜索预算；不能把每条查询各获一次完整预算与 P5 的组预算直接比较。新方法拆分查询时，全部子任务仍共用组的总预算。

主时间曲线保持 P5 的 20,000 状态、512 MiB 内存参数和相同 K、故障预算、性质/触发窗口。先观察增加时间是否仍受其他上限截断，再在开发集设置独立资源敏感性实验：

- 状态轴候选为 20,000、80,000、320,000；保持其他条件不变。
- 内存轴候选为 512、1,024、2,048 MiB；保持其他条件不变。
- 先确认本机资源和作业成本，再在正式运行前固定取值与停止规则；未执行的档位如实记录，不能按结果临时加档。

时间、状态、内存曲线分别解释，不将同时增加三种资源的结果当作算法收益。记录搜索预算、各阶段耗时、worker 墙钟和父进程墙钟；watchdog 是异常终止保护，不能与搜索预算混用。

多阶段策略共享总搜索预算。需要比较预处理、编码和后端时，另设共同的端到端验证预算，明确包含建模、编码、求解和证据处理；两个预算口径不得混成一张速度表。

重点绘制违规与可达目标类别的正确决定比例，另外展示 HOLDS、UNREACHABLE、空真和触发待定。总覆盖上升时必须说明由哪些类别贡献。

### 3.4 规模实验

先用现有样本建立观察性规模分布，再构造受控规模族。每族固定协议、环境与任务结构，单独改变节点数、并发宽度、物料数、共享资源/容量或时间边界 K；规模档位及生成规则在运行前冻结。

新增规模案例必须具有版本化独立目标和证据来源。能闭合的小模型独立穷举；大模型真值不足时，仅报告运行与求解结果及证据范围，不计算无依据的准确率。新增规模集与原 P5 分母分开。

物料数或节点数变化后通常已是新问题，不能沿用旧查询 ID/真值。增加 K 是语义范围变化；增加求解秒数是计算资源变化，二者分轴呈现。

### 3.5 交付与验收

交付结构分层清单、冻结诊断计划、剖析记录、预算/规模曲线、资源限制表及“测量→机制选择”的决策记录。

验收要求：每个未决类别有明确解释；正式性能记录不含剖析开销；样本、运行顺序和资源上限可复现。收益不足或主要受上限限制也是有效结果，不以调高预算代替核心算法贡献。

## 4. R2：确定并验证一项核心算法机制

### 4.1 按测量选择，不预设全部实现

在[已有 O0–O6 设计](../algorithm/docs/改进方案与完整验证-v3.md)基础上选择一项主机制，必要的表示改进作为辅助。旧设计中的优化不能未经适配就视为已适用于 v0.3。

| 测量指向 | 候选机制 | 必须保留的含义 |
| --- | --- | --- |
| 大量与当前性质无关的状态依赖 | 契约读写/资源依赖驱动的性质切片 | 控制、数据、协议、时间、故障及监视器依赖闭包 |
| 重复组合占主导，局部接口稳定 | 带接口假设的局部摘要/组合验证 | 中间效果、失败/取消、物料归属及停止隔离 |
| 消息与时间选择占主导 | 消息表示压缩或有条件时序抽象 | FIFO、身份、epoch、新鲜度、期限与真实 tick |
| 真实独立交错占主导 | 契约依赖驱动的保守偏序归约 | 可交换性、性质可见中间状态和时间边界 |
| 单状态成本占主导 | 精确状态表示、共享与判重 | 父/兄弟状态隔离、完整键及冲突复核 |

字段读写集合只提供候选独立关系，不直接证明并发分支可删。当前 tick 内固定仲裁不等于任意交错；不能凭设备 ID 不同就实施偏序归约。直接符号后端仅在诊断支持且成本合理时考虑，不要求完成 O3–O6 才能进入论文实验。

核心贡献说明必须回答：契约提供什么信息；算法如何使用；比一般搜索多完成什么分析；适用前提是什么；保留哪些查询；不适用时如何回退。优化目标是同问题、同预算下增加有证据的决定或减少开销，不能仅以改用某求解器作为贡献。

### 4.2 正确性与回退

先在独立可闭合小模型上比较目标/违规可达集合、时刻及监视器输出，再扩展到整线。覆盖旧请求、重启、重复包、共享容量、并行失败、停止未知和 deadline−1/deadline/deadline+1。

精确表示变更应保持状态与转换关系。切片、摘要或抽象应明确是等价保持还是单向保守关系，并分别规定允许输出的结论：过近似中的反例可能需要细化，欠近似中的未发现不能推出安全或不可达。无法证明适用时返回原模型或 Unknown。

所有正向见证均应在未优化语义中具体化并独立检查。见证重放不能证明负向结论；HOLDS/UNREACHABLE 必须依赖完整搜索或适用证明及其保持关系。优化后的负向结论不得仅凭“测试中无分歧”升级为普遍正确。

生产算法不导入参考求解器、oracle/gold 或参考侧答案生成规则来预测结果。新增证明预处理若需要证书，提供独立检查器与前提篡改反例，参考答案只在预测封存后用于评分。

### 4.3 消融与阶段验收

保留同语义 none、storage、portfolio，并加入“主机制关闭/开启”配对。辅助优化存在时单列配置，避免同时改变多个机制后无法归因。仅切换算法，保持工艺、独立目标、契约、故障域和真值一致。

若需要删除保护机制检验模型检错能力，应另建明确版本的缺陷实验；不能把改变被验证系统的实验当作求解器消融。

交付算法说明、适用性检查、保持性论证、实现开关、小模型检查、见证审计和开发/验证集结果。验收要求为决定性结论无未解决冲突、见证全部通过核验、失效前提能拒绝或回退。性能收益如实记录，未获收益的机制不因投入成本而默认进入最终方法。

## 5. 从 R1 开始的 PLC 基线试点

### 5.1 对比对象

| 基线 | 定位 |
| --- | --- |
| B-Rule | 类型、引用和局部规则的辅助对照，不承担完整路径验证 |
| B-FullModel | 同语义未优化转换模型，用于算法归因 |
| B-STVerify | 等价 ST＋同等设备功能块＋相同环境/性质＋外部验证工具链 |
| M-Contract | 契约组合建模、验证义务实例化、所选核心机制及领域来源解释 |

传统 PLC 路线也可以封装请求身份、物料、资源和停止协议。基线应得到这些同等知识；差别在于如何构建验证模型、落实性质和定位问题，不能要求 ST 工具仅凭变量名猜测设备语义。

PLCverif 是候选工具，并非已经选定的通用 IEC ST 前端。其官方文档列出现成 STEP 7 前端及多个后端，需验证所选发行版和共同子集的实际支持范围：[用户说明](https://plcverif-oss.gitlab.io/plcverif-docs/userdocs/)、[前端与后端配置](https://plcverif-oss.gitlab.io/plcverif-docs/userdocs/QuickStart.html)。PLCopen 是规范/指南来源，不列作求解软件。

试点仅使用公开通用语义及项目自建代码；不引入商业厂商软件、厂商捕获数据或行为，不为工具适配扩展应用的厂商方言。若前端要求超出共同通用子集，记录不兼容并评估开放的替代转换链；替代链也必须经过转换和性质映射检查。现有含 LADDER 文本和模板占位符的 test.st 不直接作为通用 ST 基线。

### 5.2 最小共同案例与语义准入

在完整数据集之外先固定小型试点：

1. T0 顺序子流程：输送、停稳、抓放和独立目标。
2. 最小双分支：同物料/资源或最后一个载位的竞争。
3. 典型异常：旧反馈、停止确认丢失、部分物料效果及失败退出。

每类同时有合法负对照与可复查缺陷，选择规则先于试点成绩冻结。优先核对 V01、V02、V04–V09；V03 的年龄/epoch 和 V10a/V10b 的计时在支持确认后逐项准入，不用缩减性质集合掩盖不支持。

共同语义表至少包括：输入采样、PLC 扫描与 DSL 六阶段对应，反馈可见时刻，资源仲裁，请求/物料身份，故障选择及全局预算，超时边界，K、触发截止和响应尾窗，停止与隔离。扫描末尾观察若遗漏阶段内违例，应增加一致的监视器/观察点；未解决前该性质不进入共同评分。

准入证据包括公共状态与事件映射、独立任务目标、正常与故障双向轨迹检查、可闭合小模型的完整后继/性质集合核对，以及已知缺陷的检出和见证重放。有限检查限定其范围，不冒称通用 DSL/ST 等价证明。

### 5.3 工具选择的决策点

R1 交付工具版本、许可证、依赖、语言/FB/计时支持和可运行最小案例矩阵；R2 结束前给出逐案例/逐性质 COMPARABLE、UNSUPPORTED 或 PENDING 结论。

失败项保存原因和适配工作量，不删出支持范围统计，也不算正确检出。工具可用但语义未准入时不能进入速度比较。若没有可准入的 PLC 路径，明确报告 B-STVerify 尚未建立，保留内部实验并限定论文主张。

## 6. R3：冻结方法，开展正式对比与机制消融

### 6.1 两组比较分别回答问题

**算法组：**在同一 v0.3 问题及参考视图上比较 B-FullModel、既有实现优化、所选核心机制及其消融。主要检验性质保持、求解覆盖和资源开销。

**PLC 流程组：**仅在通过共同语义准入的 DSL/ST 子集上比较 M-Contract 和 B-STVerify。单列模型/性质构建、复用和领域诊断，再评价端到端检查效果。

同后端实验用于隔离建模/编码影响，只有双方确实能接入同一后端时开展。跨后端端到端实验另外列出版本、配置与成本，不能将全部差异归因于设备契约。内存参数、硬件与预算可比；显式状态上限与符号约束数并不等价，分别披露工具特有上限。

### 6.2 冻结与执行

运行前固定数据/真值和准入包、源码、方法配置、查询组、预算、资源上限、样本、随机种子、方法轮换顺序、重复次数、统计代码及失败处理。先评估作业数和预计成本，再决定全量与分层重复规模；不能运行后按效果选择预算。

正式性能作业采用单 worker 独立进程，配对块内轮换方法顺序；记录硬件和竞争负载。冷启动与缓存命中分别报告。续跑只恢复同版本未完成作业，保留异常 attempt，不挑选最好的重复替换正式结果。

新批次使用新的输出目录及 manifest。现有 P5 runner 固定方法和预算，并非无需改动即可支持本方案；先实现并验证新计划生成、分组预算、观测与评分适配，再执行。若优化源码使旧准入摘要失效，应建立新实现与原语义的对应审核及新准入包，不能直接移除旧门禁。

独立 gold 不交给 worker。预测封存后评分；分歧先调查，确认后用新版本修复或保留争议，不能迁就算法输出修改答案。

### 6.3 主指标

| 维度 | 指标与解释 |
| --- | --- |
| 支持范围 | 全部请求、可比较、未支持和待准入数量；共同子集大小及选择规则 |
| 正确性 | 已回答准确率、全体适用查询正确比例、确定回答率、Unknown/错误/失败 |
| 关键检出 | 违规查询正确决定比例、可达目标正确决定比例、合法负对照误报 |
| 触发与空真 | 非空真、空真、触发待定及协议构造性质分别统计 |
| 效率 | 建模、编码、求解、重放和端到端时间，RSS/可得峰值，状态或约束规模 |
| 稳定性 | 三次均正确决定的覆盖、重复波动和结论冲突 |
| 复用成本 | 初次建模与协议/设备/绑定变更后的修改范围、人工操作及回归成本 |
| 诊断 | 经标注核对的根因、工艺节点、请求/物料/资源定位和可重放比例 |

Unknown、执行错误和不支持不是安全结论，也不是正确检出。共同子集外的支持缺口另报；不能只展示兼容案例的准确率而省略总体支持范围。

耗时比只在双方共同正确决定的同范围作业上计算，并同时展示全量覆盖与截断；不能把超时上限当正常完成耗时计算加速比。按父案例及场景分组统计配对差值和区间，重复运行不增加独立样本数。

建模成本提供可检查的修改清单、步骤与操作记录；研究者自己的耗时仅支持案例性观察，不据此声称普遍的人因优势。已有 36 组变更任务可作候选，先核对协议替换、绑定和目标变更是否具有可比较含义，再冻结 D-R 子集。

### 6.4 最终交付与验收

交付冻结计划、原始逐作业/逐查询记录、支持与语义映射矩阵、证据审计、预算/规模曲线、内部消融表、PLC 对比表、复用与诊断记录及限制说明。

验收分别检查：作业全部结束；输入与语义准入有效；参考和见证证据有效；评分完整；算法实际决定多少查询。前四项通过不表示第五项为 100%。

只有实测支持时才报告优势。若收益集中在特定性质、环境或规模，结论限定到该范围；PLC 未准入、触发待定和参考语义的条件性可信边界随结果披露。
