# 工艺 IR 0.1 与绑定协议

## 1 四种产物

| 产物 | 权威内容 | 产生阶段 |
| --- | --- | --- |
| ProcessIR | 语义类型值、条件树、结构化控制树；与文本/图形视图无关 | 文本解析或图形编辑 |
| Environment | 场景选择、别名、设备/服务契约引用、登记表、运行策略 | 项目配置 |
| BoundProcess | 所有引用解析后的不可变计划和依赖锁定 | 静态绑定；全部执行阻塞项消除后才可启动 |
| RuntimeSnapshot/EventLog | 激活、请求、证据、实际占用与时钟 | 运行；不能回填 ProcessIR 或作者场景 |

[process-ir.schema.json](process-ir.schema.json) 是 JSON Schema Draft 2020-12 的结构定义；`tools/check_design.py` 提供文本解析/降级、来源映射、IR 结构与部分静态检查的参考实现。它不是 apps 的绑定器或运行器。JSON Schema 不检查物理可达、契约前置条件或安全性。所有对象字段封闭；未来扩展通过版本变化引入，不静默吞掉拼写错误。

## 2 ProcessIR

顶层固定 `ir_version="0.1"`、`language="ac-process/0.1"`，另有 process_id、environment_ref、execution_profile_ref、entry、conditions、nodes。environment_ref 是本地文件路径；其他 ref 都是相应表的精确键，不是任意 JS 路径或字符串表达式。

nodes 采用平坦数组，node_id 全局唯一。seq/par 的 children 有序，repeat/with-control 有一个 child，branch 有有序 cases 和 otherwise。除 entry 外每个节点恰有一个结构父节点；没有不可达节点、共享子树或环。共享逻辑通过未来库实例化实现，不能让两个父节点同时激活一份可变状态。repeat 的静态 child 可重复激活，但每轮状态独立。

| kind | 专属字段 | 语义来源 |
| --- | --- | --- |
| seq / par | children | children 顺序只决定 seq；par 仲裁按稳定 ID |
| branch | mode、timeout、cases[{condition, child}]、otherwise | ordered/exclusive 与三态选择 |
| repeat | count、child | 0..10000，不允许运行中修改 |
| await | condition、timeout | 值 T 才成功 |
| delay | duration | 有界仿真时间 |
| invoke | target_ref、behavior_id、arguments、policy_ref | 实例别名与 DeviceSpec 能力解析 |
| with-control | control_ref、policy_ref、child | 控制配置的进入/持续/退出协议 |
| fail | code | 显式工艺失败 |

duration/timeout 是 `{value:"十进制数词法",unit:"s"|"ms"}`。保留十进制字符串用于精确编译 tick；非负且不超过 86400 s，超时不为零。负数、空串、表达式文本均非法。BoundProcess 只保存计算后的整数 ticks 与来源，不在循环中重新换算。

值的 tagged union：`{kind:"boolean"|"integer"|"number"|"string",value:...}`、`{kind:"quantity",value:0.2,unit:"m/s"}`、`{kind:"binding",binding_ref:"material"}`、`{kind:"index",registry_ref:"subjects",binding_ref:"material"}`。JSON 数字外观不能独自决定语义类型，kind 为权威。number/quantity 的有限性由解析器和语义检查补充；禁止 NaN/Infinity JSON 扩展。

条件的 tagged union：ref(condition_ref)、all/any(operands)、not(operand)、is(read,equals)。read 包含 source、owner_ref、key，按需附 subject_ref、slot_ref、request_node_ref。equals 只允许字面量。命名条件可以引用其他命名条件，但依赖必须无环；编译不能递归 eval 字符串。

设备条件 `{id,label,source,key,equals}` 的导入：解析当前实例为 owner_ref，按契约登记表取得类型/单位及关联策略，再转为 is；label 和原条件 id 存来源映射。布尔默认值不能补成观测。request_scoped 必须关联当前请求；subject 由明确的参数绑定规则取得，不能猜测 `_id` 后缀。

## 3 Environment 与契约扩展边界

本目录示例的 `DesignEnvironment/0.1` 是工艺设计输入，**不是 SceneDocument 或 apps 项目文件**。完整生产环境由 SceneDocument 及契约库生成同等的绑定输入。

| 字段 | 内容 |
| --- | --- |
| mode | 本例固定 design_only，运行入口必须拒绝 |
| scene | id、revision、status；pending 不可运行 |
| profiles | rational step、转换预算、时序策略、暂停与失败策略 |
| bindings | 别名→名义类型、稳定 ID；device 另引用 contract 路径，slot 另引用 owner |
| registries | 版本、键的名义类型、稳定 ID→正 DINT；单射、不可悬空 |
| policies | gate/accept/execute/stop 的整数 ticks，pause 计时规则；均正且有界 |
| controls | 实例、写集合、进入/持续/退出条件、写入者资源及验证状态 |
| providers | 契约引用/规划来源、事实类型、单位、关联、max_age_ticks、实现状态 |
| resources / resource_conflicts | 资源 ID、类型、容量、管理者及状态，以及资源间的对称互斥关系；物料/槽位身份不能丢失 |
| adapters | 参数身份解码与资源/交接协议引用；新增运行适配器是显式待实现项 |
| acceptance | 独立监测判据及其所需证据 |

DeviceSpec 仍是行为参数、条件和完成检查的唯一来源；Environment 不覆盖它的前置条件或把 implemented 改为 true。resources/adapters 是缺少的场景级服务契约提案，不是现行 DeviceSpec 已支持的字段。启用前必须版本化并由正式绑定器验证。示例另提供明确命名的 draft DeviceSpec，不修改现有 robot_arm_1 或伪称旧定义包含新参数。

持续控制是专用入口：绑定已有 runTag/speedTag 等 input 信号与唯一 writer。不得因为 start_conveying 不可调度，就改它的 schedulable 或伪装成离散请求。缺少持续监控、停止证据或信号管理时，with-control 可以保留设计，但 executable=false。

## 4 编译流水线

1. 严格词法与语法 → AST；保留所有源跨度；重复定义拒绝。
2. 降级为 ProcessIR；图形前端跳过词法，但执行同样结构检查。
3. 名称解析、树检查、条件引用/作用域、类型与单位检查；显式解析名义 ID。
4. 锁定场景/设备/服务契约；参数解析、能力开关、schedulable、completion.mode、注册执行器、标定、受支持模式检查。
5. 生成信号角色、请求编码、观测关联和集中资源需求；检查持续控制与动作的写冲突、嵌套资源自锁。并行动作争同一可调度资源允许排队，不能一概静态拒绝；两个持续 writer 争同一端口则拒绝。
6. 生成义务与诊断；所有 real-execution 阻塞项关闭后产生可运行 BoundProcess。设计模式输出带 blockers 的绑定报告，不输出伪可运行计划。

BoundProcess 必需字段：bound_version、process_hash、compiler{name,version,build_hash}、profile、entry、resolved_nodes、dependencies、binding_tables、source_map_ref、obligations、execution_mode、executable。resolved_nodes.invoke 包含 instance_id、device_spec_id、revision、behavior_id、executor_ref、frozen_arguments、protocol_ref、condition_refs、resource_claims、release_checks、timeout_ticks；仍保留源 node_id。

binding_tables 分开保存 instances、signals、observations、resources、identity_registries；逻辑信号的键为 `(instance_id,port_id)`，PLC 地址只是可选投影。目标平台不支持的结构/协议明确报错。PLC 正 request_index 只在持久映射中分配，溢出拒绝新提交，设备确认无在途请求后才可显式建立新 epoch；不能整数环绕后把旧 done 认作新结果。

依赖以 `{kind,id,revision,sha256}` 锁定源程序、IR、环境、设备/服务契约、场景关键绑定、资产/标定、执行器和配置。文件内容哈希使用 UTF-8 文件原始字节；IR 比较使用项目定义的规范 JSON（键按 ASCII 排序、无空白、UTF-8、有限数、正零），不把另一语言默认序列化当跨语言标准。正式实现须对数字规范化提供测试向量。任何依赖变化都要求重新绑定，不能仅比较文件名或人工 revision。

诊断结构：`{code,severity,phase,node_id,instance_id,behavior_id,field_path,source_span,related[],message}`；source_span 为文件相对路径和半开 UTF-8 byte 范围，另附从 1 起的 Unicode 码点 line/column。IR 输入则用 JSON Pointer 定位。一个根因可关联多个调用点，未知值诊断包含 provider/key/age/expected/actual 身份。

## 5 资源及物料提交

独占资源容量为 1；计数容量有正整数上限；slot 和 geometry_zone 许可额外携带身份/几何版本。授权令牌至少绑定 run、activation、request、资源集合、revision、grant_epoch。候选检查可申请性；grant 后再次检查相关 revision 和持续有效前置条件。grant 不是候选前置条件，避免等待自己的授权。

资源管理器一次提交整组授权，同时检查 resource_conflicts 的对称互斥关系；例如输送控制写入许可与机器人取料区域许可不能并存。所有控制源必须经过这一管理者，否则该执行配置不可绑定。持有范围为 invoke 或 with-control 生命周期；composite 子行为继承，不重复申请同一资源。声明为 completion 后释放仍必须满足 release_checks。单纯设备终态不得清空物料占用。

交接服务是物料归属的唯一写入者：

```text
sender_owned → receiver_reserved → in_transfer → receiver_owned
                    ↓                  ↓
           revoke_if_no_effect     quarantine_if_unknown
```

预留不改变 holder。原子提交需匹配 transaction_id、material、sender、receiver/slot、request、版本、离开/进入证据；以版本比较后更新归属、原位占用和目标占用，将预留转换为占用。重复提交返回同一事务结果，不再次加 load_count。事务日志禁止双持有者、负容量或预留与占用重复计数。实际物理支承与业务 holder 可暂时不同，必须显式为 in_transfer；不能当成两个合法持有者。

同一抓放通常包含带面→夹具、夹具→目标载位两个交接。取走后带面占用可释放，夹具持有与目标预留保留；放下确认后转目标占用。异常不做反向“回滚位姿”。物理引擎独占物料位姿，执行器驱动机构，交接服务维护归属，监测器只读三者证据。

## 6 运行记录与验收

event 必含 run_id、event_sequence、tick、phase、node_id、activation_id、iteration_path、event_type、payload，相关事件另带 request_id、resource grants、snapshot revision。请求状态变化、暂停、条件失效、交接提交、清理和 attention_required 都是事件，不能仅有 UI progress。重放从固定初始状态和外部输入重算，比较语义事件；墙钟时间不参与。

独立监测器核对：已接受请求才可成功；结果属于当前请求；无双持有者；occupied+reserved 不超容量；只由授权 writer 写入；实际到位/支承/释放满足目标；停止未知时仍保留隔离。工艺成功要求根节点 succeeded、无活动请求、所有控制退出确认、许可清理完成及 acceptance 全 T。物料的最终实际占用可以保留，它不等于泄漏的执行许可。

## 7 诊断与实施验收矩阵

| 范围 | 正例 | 必拒绝/故障注入 |
| --- | --- | --- |
| 语法与 IR | 九种节点、中文字符串、repeat=0 | 额外 token、重复 ID、空 par、无界循环、未知版本/字段 |
| 类型与关联 | subject 正 DINT、明确单位 | string→integer、slot→material、未登记 key、过期/错主体事实 |
| 图与控制 | 完整单根树、确定性分支 | 环、不可达、共享子树、条件引用环、多 T 的 exclusive |
| 生命周期 | accept→actual evidence→result | 旧 done、无 accept、重复参数冲突、停止超时、恢复后重复 grip |
| 资源 | 同资源串行、独立资源并行 | 同槽双预留、写入冲突、过期 grant、父子重复申请导致自锁 |
| 物理与事务 | 两次交接及最终承载 | 动画结束未到位、夹爪空但物料未落槽、确认重复、掉落 |
| 时钟与重放 | 相同 seed/输入重复一致 | 超时边界、零延迟链、预算耗尽、暂停期间进度变化 |

本次工具只覆盖词法/语法降级、JSON Schema、树/引用、示例参数和登记表，以及这些检查的负例；其余各行是绑定器和运行器的后续验收要求。不能把参考工具的通过数当成多设备运行测试数。
