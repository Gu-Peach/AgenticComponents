# 方法一实验 v2：统一语义、参考核心集与压力集

本版本按四步组织实验，保留 v0.1 代码快照、原始输入、旧答案包和旧实验结果。新增规范为 `specs/method1-semantics-v2.json`，算法模型版本为 `acverify-tick/0.2`。

## 1. 冻结统一规范

- accepted、done、stop_ack 是保持状态；每周期重新采样才产生新时间戳。
- 每个消息流 FIFO，时延在配置区间内选择。旧消息到达不能被改成新采样。
- 已正确接收的确认成为协议状态；后续重复确认不重置接受/执行时钟。物理完成条件仍读取当前状态。
- 提供者重启只改变通信代次、清除源端保持状态并触发对账/停止；不自动复位物料或重试生产。
- V10b 从首次有效接受计时；仅进入 stopping 不合格，必须确认终态或保留必要隔离的人工处理状态。
- 没有“迟早会出现小延迟”的公平性假设。保持型反馈不保证在有效期内到达。

源码、标准答案和实验记录均携带同一语义摘要。旧一次性反馈结果只能作为历史记录，不与 v2 混算。

## 2. 对齐算法与独立参考工具

算法新增保持状态表、周期采样和 FIFO 交付，处理重复、旧身份、过期、代次变化和停止确认丢失。采用接收端兴趣投影：一旦某流的确认已被消费或激活已退役，省略对控制与性质均无影响的后续重复样本；源端状态本身仍保持到退役。

`tools/reference_channel_v2.py` 独立选择绝对交付时刻并穷举有限消息通道，没有导入 acverify。61 个小型配置覆盖正常/延迟/过期、身份不符及确认抑制。测试将其结果与算法的消息通道逐项比较。

这是一组独立、完整的协议核心测试，不是对整条产线的第二套完整求解器。现有顺序参考解释器与逻辑证书另用于业务性质准入；并行和复杂故障的独立全模型证明仍未冒充已完成。

## 3. 核心集与压力集

`experiments/method1-v2/core.json` 由独立证据决定，不根据被测算法能否解出筛选：

- 303 个案例，固定 nominal、3,000 tick，选定 V09 和 V10a，共 606 条有明确参考结论的查询。
- 证书在划分时重新推导，顺序见证重新执行并检查时间/身份；输入哈希和语义摘要冻结。
- “核心”只表示所选查询有答案，不把这些案例的其余 V01–V10 属性伪装成完整 gold。
- 人工及论文 gold 审核仍为 pending；当前是参考认证的工程核心集。

`pressure.json` 覆盖全部 360 个语义案例，可与核心案例重叠；57 个没有完整业务标签的案例不进入业务准确性分母。压力集关注支持范围、状态/内存、超时和覆盖率。216 个预期结构错误在静态检查中单列。

## 4. 冻结并运行

```powershell
python -B tools/build_experiment_v2.py --workspace . --implementation . --output experiments/method1-v2-next
python -B tests/test_semantics_v2.py
python -B tools/run_experiment_v2.py --workspace . --definition experiments/method1-v2 --output artifacts/method1-v2-new
```

必须使用新的输出目录。核心集正常环境比较 full/auto，搜索预算相同；压力集增加 delayed 和 fault。Pilot 的强制 stop_unknown_c1 保留原名，不假装等于普通 fault。所有工作独立进程串行运行，外层看门狗保证每项都有结束记录。

统计同时报告：参考结论、算法结论、正确/错误/未决、已回答准确率和全部核心查询上的覆盖率。UNKNOWN 不能从数据表消失，也不被当成正确。源代码哈希变更、语义摘要不匹配或工作进程失败都会单列。

单次短预算试验用于验证流程，不作为论文最终性能结论。无需保证所有大模型在预算内被解出；必须保证所有实验有结束状态、所有准确性样本有事先冻结的答案。

## 剩余边界

尚未实现任意属性的独立并发/故障参考求解器，也未建立全部 27,495 条查询的最终真值。v2 不做 PLC/ST 生成或优化派工。继续扩充核心集时，应先获得独立证据，再调整准入清单，不按算法结果修改答案。
