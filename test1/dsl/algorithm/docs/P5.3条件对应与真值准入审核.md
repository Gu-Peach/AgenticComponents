# P5.3 条件对应与真值准入审核

本审核面向冻结的 27,495 查询共同视图，以及 `acverify-tick/0.3` 和 `reference-six-phase/0.1` 两个已检查源码版本。审核类型为 AI 技术审核。其依据是逐阶段源码归纳论证、实例前提检查、有限模型双向检查、观察帧边界检查及反向测试，**不是证明助手对任意 Python 程序的机器证明，也不是工业设备安全认证**。

## 1. 结论与使用范围

在下述前提和冻结摘要成立时，允许将 P4 的已认证性质结论用于这一共同视图的算法评价。准入只更改“是否可以比较”的状态，不改变参考 verdict，不扩大原查询的 K、触发截止或反馈/故障范围。

所有 1,080 个案例/环境都必须通过输入对应和前提检查，没有根据求解结果删掉模型。1,065 条旧窗口不足记录继续留档；使用 P4 预先登记的不同 ID 扩展问题比较。触发 Unknown 不妨碍已认证性质结论的分层统计，但不得计为实际故障处理覆盖。

源代码锚点、AST 摘要、域检查、观察帧结果与逐查询来源由 `correspondence-review.json`、`instance-premises.json`、`monitor-boundaries.json` 和 `gold.jsonl` 保存。代码、契约、问题或属性版本变化后必须重新准入。

## 2. 条件性对应命题

令 R 为 P5.2 定义的核心状态对应，H 为按观察点累积的历史：首次触发/违规、首次有效接受、确认响应和按请求记录的超时事件。令 D 为本次登记模型的可达域。

命题：对满足 D 的同一问题实例，两侧初态满足 R；若某状态对满足 R，则每个合法的参考后继可在新引擎中找到对应后继，反向也成立；对应事件使 H 保持一致。因此任意共同查询在规定的 K、C、E 内具有相同的性质意义。

这里的推导依赖已审查源码的规则保持性，而不是“测了若干条轨迹，所以所有轨迹都一样”。机器检查验证源码未变、实例属于 D、输入意义对应及有限反例；一般保持性论证由本审核承担，可信边界单独披露。

## 3. 域 D 与不可省略的前提

1. 初始协议为空，无初始活动请求、授权和未协调恢复状态；节点 ID 唯一，循环有有限次数。
2. 每个位置、物料、设备、资源和参数引用都登记并通过依赖锁。当前实例物料初始位于登记位置，支承有效，交接表为空。
3. 当前初始 run_command 为布尔值，后续唯一写入是进入/退出命令的 True/False。epoch 为非负整数，命令、报文时间和策略按固定整数 tick 解释。
4. 使用登记的能力模板和顺序阶段；reserve_target 的三个声明实参是对应物料、目标和本次请求。两侧预留更新都使用当前请求键，前两个实参对应同一物料与目标。其他模板或任意自定义效果不能套用本结论。
5. 逐任务 cancel 标志初始化后没有可达写入者；声明的取消由全局 abort 驱动。进入隔离意味着已处于全局取消流程。
6. 布尔缓存与 receipts 成对维护；committed 是 commit_records 键集合的派生值。完成身份、隔离授权和未执行物理停止在字段退役时保留。
7. 触发/违规/响应历史为被动观察信息，控制守卫和物理效果不读取它们。搜索器可以读取历史决定查询，但不能用它授权动作。

两处实现对任意外部字典不等价，但不会缩小本次查询范围：

- 若直接构造 run_command=None，Python 短路表达式与显式 `is True` 的三值结果可能不同；D 的布尔初态和唯一写入者排除了该值。
- 若直接在“隔离但仍有停止工作”的 process token 上调用 no_processing，两侧的通用实现可能不同。隔离已经触发全局 abort，后续控制器取消而不提交新动作，所有活动物理动作被停止事件替换；这个谓词在该状态没有可达读取点。它不是一个可忽略的普通输入差异，若以后开放独立恢复/局部取消接口，必须重新审核。

同样，active handoff 与 unspawned 物料的任意混搭不属于 D：当前初态均登记位置，transfer 接受要求源位置成立，所有后续阶段和外部更新只写登记位置。这里没有删除任何原语料模型。

## 4. 初态与每步保持性

### 输入和身份

两侧读取相同原始文件，但独立构造各自运行表示。输入桥比较完整节点、条件、时限、策略、循环、解析实参、模型、环境和资源关系。初始化同样的材料、设备和空协议；缺失循环计数在新引擎中明确解释为 0，对应参考初始的显式 0。

激活键由唯一节点 ID 与数值循环路径形成。actor 和 token epoch 在本次激活内固定；不同请求的键不相同，因此授权键的相等关系与参考的完整 owner identity 相等关系对应。缓存写入和重启/停止清理对应，result-confirmed 明确保留在 R 中，不能只根据“已有结果包”推断。

### 外部事件、故障和报文

按相同事件索引和 tick 判定外部更新。源区域冲突、活动用户、预留、持有与目的容量检查使用相等的世界/授权信息，因此两侧同步等待或更新。

无故障选择、所有活动 token 以及所有在途报文索引逐项对应。每种故障的 count、nonce/stream 修改、采样时间保留、epoch 更新和物料效果保持都相同。故障预算始终全局有效，不在 K 重置。

两侧从相同的有兴趣保持流集合枚举相同延迟笛卡尔积，得到相同采样 tick 与 due。FIFO 只在同一流内阻塞后续包。生成域内的布尔类型、身份、提供者、epoch、新鲜度及兴趣条件相同，因此消费事件和 receipts 相同。边界测试额外枚举布尔证据、停止证据与隔离帧，不能将此测试推广到未登记的任意 IEC 类型。

### 控制与设备

控制器在相同快照上按 eligible、节点 ID、循环路径排序。各组合节点、三值分支、await/delay、策略超时和原子授权/容量仲裁对应。新激活到下一 tick 才可执行。停止计时只在首次进入停止阶段设置，反复全局取消不重置期限。

设备事件日期同为 `start+duration-1`，下阶段从下一 tick 开始。物理阶段前独立检查持续条件，包括接受反馈尚在途的情况。失败时保留已有物料效果、通知故障并排入停止，不继续动作效果。登记模板中的每个位置/支承/归属、夹持、分度/升降、历史/计数、预留和幂等提交操作逐项对应。

当 control 已进入取消，跳过的重复 V04/V05/V06 检查没有遗漏新的相关世界写入：对应 invoke hold-failure 只改变控制/停止调度，之前的物料/授权写入已经检查；驱动减速也不改变这三类性质所读字段。根成功核查独立目标和清理；根失败/隔离等待全部子任务及全部物理事件。

### 退役

仅终态且没有待执行物理事件的 token 被清理。两侧保留同样的 node/path/parent/scope、终态、actor/epoch、授权和完成索引。剩余布尔别名、说明性 reason 和兼容提交列表的值受前述派生不变量约束；删除它们不会改变将来读取的含义。

## 5. 观察及历史对应

V01 在捕获前；V02 在确认动作成功时；V03 在真正消费已知证据时；V04–V06 在状态/阶段微步骤；V07 在正常作用域退出；V08 在失败处理器前后；V09 在根成功时观察。两侧比较同一实际字段与相同条件。未知事实不变成成功，不变成虚构的违规。

H 的基例为空（除初态可观察的占用）。每 tick 的对应观察使首次触发/违规时刻相同，重复事件只保持最早记录。首次有效接受不会因重复反馈重置；成功、确认失败/取消或保留所需许可的隔离在同一时刻构成响应。观察在退役之前完成，故不会丢失已结束请求。

V10b 逐请求核查 `accepted_at<=C` 且截止/观察在 E 内。K 后的新请求可以真实执行，但不会被误算进本查询。截止 tick 先处理交付/确认再判超时；超时发生后，迟到响应不能删除反例。其他性质只读取各自 K 内的历史。

## 6. 结论构造与独立性

新显式搜索保存完整序列化状态，包含时间和被动历史。完整有界前缀可以给出有界安全/不可达结论；当前实现对普遍响应更保守，要求有限模型闭合。超时、资源上限、不完整观察不能推出不存在违规。具体见证必须按原转移重放。

storage 只改变复制与边保存。portfolio 共享总预算，先找见证再搜索；只合并已重放的存在性/违规结论，遇到相反确定结论即拒绝。未证明的 clock/POR 没有参与本轮。

参考真值仍来自 P4 的逻辑/条件证明和独立参考轨迹/图检查。P5.3 先重新检查 P4 证据，再仅补充触发可达性。被测算法输出不参与生成或更改 gold。正式 worker 只接收原始问题和无标签查询，并有读取 oracle/gold 的拒绝检查；评分器在预测冻结后连接真值。

## 7. 尚未覆盖的泛化

本准入不能推出任意自定义契约、未登记恢复逻辑、任意 PLC 程序、连续物理或几何可达性正确。没有真实 PLC 工具映射时，none/storage/portfolio 只能称为算法基线与消融。保持原窗口不足记录和触发 Unknown；按性质真值、触发覆盖、求解覆盖、准确率和效率分别报告。

最终 gate 为有条件的源码审核准入，证据类型和剩余限制会出现在最终报告中，不以“全部小模型通过”替代这份论证，也不冒称外部人工审定或机器验证了全部 Python 语义。
