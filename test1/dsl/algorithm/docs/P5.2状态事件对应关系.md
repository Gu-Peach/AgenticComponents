# P5.2 状态、事件与查询对应关系

本说明给出 `acverify-tick/0.3` 与冻结的 `reference-six-phase/0.1` 之间的条件性对应设计，以及代码实际检查的范围。它是 P5.3 的审核输入，不是证明助手对 Python 实现的全语义证明。

## 1. 前提与独立边界

适用对象为共同评价视图中已绑定的符号模型：有限设备/物料/资源、已登记的能力阶段、正整数策略预算、声明的反馈/物理区间、有限循环和明确外部事件。原始输入须通过冻结的解析、依赖锁和类型检查；目标与候选程序独立。新增设备能力、未登记效果、恢复协议或其他时钟解释不自动沿用本说明。

新引擎位于 `src/acverify_v3/`。它沿用原始输入语法/绑定辅助模块，独立执行控制、设备、消息和监视规则；不导入参考转换函数、性质求值器或真值证书。`alignment_p52/` 是外部对照代码，才允许同时调用两侧。旧 `src/acverify/` 与旧实验不修改。

## 2. 输入对应

`input_bridge.compare_inputs` 分别从新引擎 IR 和参考 DSL 节点提取执行意义，比较：

- 入口与节点 ID、顺序/并发子节点次序、循环次数、分支方式及每个分支条件。
- 条件合取/析取/否定、观察提供者/字段、物料与请求限定、布尔比较值。
- 毫秒/秒到整数 tick 的换算、每个 await/branch/delay 的时间，以及 invoke/with-control 的策略引用。
- 解析后的设备、能力、实参、完整契约模型、资源关系、控制作用域、环境绑定、目标、初态与环境区间。

两侧使用不同输入表示，但实际可执行字段必须对应。只比较节点数量、模型名称或最终图片不满足此要求。

## 3. 状态关系 R

令 `C_s` 与 `C_r` 为 `alignment_p52.relation.canonical` 的两侧投影，定义核心关系：

```text
R(s, r)  iff  C_s(s) = C_r(r)
```

| 新引擎字段 | 参考字段 | 对应要求 |
| --- | --- | --- |
| `world` | `plant` | 全部物料、支承、归属、设备、预留、授权、提交、交接阶段和外部事实对应 |
| `occupancy` / `commit_records` | `ledger` / `commits` | 槽位清单和有效提交身份对应；旧兼容字段 `committed` 是提交键的派生列表 |
| `tasks` | `tokens` | 节点、激活路径、父子/作用域、阶段、actor、epoch、资源与循环位置对应 |
| `new/requesting/running/result_wait` | `ready/waiting_accept/executing` | 名称规范化；保留实际阶段计数、完成标志及确认缓存 |
| `enter_wait/exit_wait/attention` | `entering/exiting/isolated` | 进入/停止时钟、退出原因类别、授权保留和待执行工作对应 |
| `scheduled` | `hardware/start/due` | 事件种类、进入时刻和选定日期完全对应，终态中未完成的停止也保留 |
| `inbox` / `levels` | `mail` / `latches` | 每个包的采样日期、到达日期、FIFO 流、身份、提供者、值与 epoch 对应 |
| `receipts` | `receipts` | 接收时刻与原包保留；result 确认缓存也参与关系 |
| `applied_events/fault_count` | `events_done/faults_used` | 相同事件集合、相同全局故障消耗；不在查询边界重置 |
| `violations/trigger_ticks/uncovered` | `violations/triggered/uncovered_properties` | 性质违规、已触发及未覆盖义务对应；首次时间通过被动历史和轨迹审查 |

循环计数中的“未出现键”仅在新引擎明确按 0 解释时规范化为参考初始化的 0。失败原因的说明文字不决定转移，只保留是否已进入全局取消；请求身份、物料效果和实际停止状态不被擦除。

被省略字段还需要派生/常量不变量：`committed` 必须始终等于 `commit_records` 的键集合；accepted、ack、stop_ack、device_fault 等缓存必须与相应 receipts 对应；当前模型的逐任务 cancel 标志从初始化起保持 False，全局取消由 abort 处理。源码只允许规定的成对写入/清理，未来若增加单独写入者或外部逐任务取消接口，应重新审查关系，不能继续无条件省略这些字段。

新引擎的 `acceptances`、`responses`、`response_violations`、首次违规/触发时刻是被动查询历史，不授权提交或影响设备选择。完整查询对应还需要这些历史与参考轨迹观察序列 H 对应，不能仅凭核心状态 R 就跳过时间查询的证明。

## 4. 单 tick 的保持义务

| 阶段 | 保持思路 | 关键前提/检查入口 |
| --- | --- | --- |
| 外部更新 | 同一时刻、同一事件索引与同一守卫决定是否更新；更新同一物料/epoch/外部事实 | `events.apply_events`：所有源区域冲突、活动请求、预留、持有和目的组容量 |
| 故障 | 无故障分支及每个允许注入位置均对应；克隆保留采样时刻，重启保留物料效果 | `events.faults`：所有队列索引、同一最大次数、重启清缓存、丢停止只抑制确认 |
| 交付 | 相同 due 和 FIFO 阻塞决定可交付包；相同身份/有效性/年龄与兴趣规则决定消费 | `channel.delivery/consume`；请求 nonce 和 epoch 不能被重新解释 |
| 控制扫描 | 相同 tick 快照、激活资格和排序逐节点处理；授权、容量在实际状态再次仲裁 | `model.controller`；检查取消、超时边界、子任务结清、转移预算及根终态 |
| 设备执行 | 进入阶段时选择同一有限日期域；持续条件成立才施加相同阶段效果 | `events.physical`；捕获前观察、每个效果后检查、下一阶段从下一 tick 开始 |
| 源采样 | 同一兴趣流集合的延迟笛卡尔积；每个样本真实使用当期源状态和当前采样时间 | `channel.sampling`；不是给在途旧包改时间戳 |
| 退役 | 仅当任务终态且无待执行物理工作时删除未来不读取的字段 | `model.retire`；隔离资源和完成记录继续可达 |

物理日期满足 `due = start + duration - 1`，报文满足 `due = sampled + 1 + latency`。deadline tick 先交付、控制确认及物理处理，再判响应义务。关节几何、连续物理与真实设备不在此关系内。

状态关系与逐阶段论证须结合源码复核：必须确认投影没有删除未来守卫读取的字段，布尔缓存与 receipts 的关系在重启、停止和重复反馈后仍保持。有限样例通过不能替代这项域与保持性审查。

## 5. 监视器与查询历史

V01 在捕获效果前，V02 在动作成功确认时，V03 在实际消费反馈或已知状态事实时观察。V04–V06 在声明的状态/微步骤处检查；V07 在正常停止作用域退出时核对本次写入、原停止包、采样年龄、身份和实际停稳；V08 比较失败处理器前后的物料与授权；V09 在根成功时核查独立目标与清理义务。

Unknown 保持 Unknown。尤其独立目标为 Unknown 时，V09 记录未覆盖义务，不伪造确定的假成功反例；V10a 只接受目标明确为 True 的根成功。

响应历史遵循以下条件：首次有效接受时间不因重复反馈重置；截止前确认成功/失败/取消，或保留所需授权进入人工隔离，才算响应。进入隔离与根流程完全结束是不同事件，物理停止仍可能待执行。

每条查询单独保留：

```text
K = bound_ticks
C = covered_trigger_cutoff
E = checked_until
D = response_window_ticks
```

扩展 V10b 使用 `C=K, E=K+D`；旧完整窗口口径使用 `C=max(-1,K-D), E=K`，空截止域保留 UNKNOWN。反例需要 `accepted_at <= C` 且违约在 E 内观察到；尾部新请求仍真实执行，但不计入本查询。安全与目标可达性只核查各自 K 内的事件。

`search.explore` 对资源/时间耗尽保留 UNKNOWN，完整有限图才给出当前实现的普遍响应 HOLDS；其他安全/可达查询还可在完整有界前缀上给结论。这个响应策略是保守的，不把未完成尾部当作安全。不同 K 的查询共享搜索时，不能把 K 后的违规投到较小 K。

## 6. 机器检查实际证明了什么

`closed.compare` 对声明的有限诊断逐个枚举两侧全部后继并检查两个方向的集合；同一关系标签下的所有匹配状态组合均继续检查，不能任选一个代表跳过其他内部状态。到达预算或 horizon 返回 LIMIT。完整关闭后，得到的是该有限诊断范围内的对应结果。

诊断覆盖控制节点、能力阶段、并发竞争、外部变化与单/双故障；另将同一诊断的多个 K 和 V01–V10b 查询交给独立参考图检查器及新求解器，比较 verdict、空真和触发。重新引入三种旧缺陷后应被拒绝。

原语料的全量输入绑定和正常时序端点检查提供实例/回归证据；它们没有穷举原语料所有并发故障组合。对整个共同评价范围的准入，仍需 P5.3 审核以上条件性论证、源码锚点和支持域；不能仅用“20 个小模型都通过”代替普遍结论。

## 7. 优化与版本边界

none、storage、portfolio 使用同一 v0.3 转移函数。storage 改变复制和边保存；portfolio 在同一预算中先找具体见证再完整搜索，只有已重放的存在性/违规证据可以合并，矛盾结论必须报错。有限图检查的时间不是算法对比时间。

旧 clock/compact 规则没有覆盖新增的绝对时间、原始包及响应历史，因此新 CLI 不提供 clock/POR 开关；退役逻辑是执行规范的一部分，三种策略都使用它。重新增加归约需要另外证明其观察与查询保持性。

运行结果绑定模型、实现源码、输入、查询 ID 和独立 gate。旧 P5.1 gate 继续描述旧 v0.2，不通过覆盖文件把它变成新版本的“通过”。P5.2 的新 gate 只记录实现和有限验收结果，全范围评分资格在后续审查阶段单独签发。
