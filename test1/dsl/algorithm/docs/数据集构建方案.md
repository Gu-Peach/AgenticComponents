# 十二个场景的工艺执行路径验证数据集方案

版本：设计 0.1。日期：2026-11-01。

对应算法见 [算法构造方案](算法构造方案.md)。本页依据 `algorithm/scene/` 的十二份 GLB 及配图制定建设目标，区分实际检查结果、拟标注语义和计划数量。当前已按本方案构造 72 个父例和 504 个变体的完整候选输入；结构检查通过不等于路径标注完成，独立真值仍待审核。实际交付见 [全量构造说明](../README-corpus.md)。

## 1. 能构建多少数据：先明确计数单位

建议建设 **一个版本化基准，包含五类实验子集**，而不是把十二个场景简单称作十二份完整数据集。

| 计数层级 | 本轮数量/计划 | 含义 |
| --- | --- | --- |
| 原始场景资产 | 已确认 12 组，每组 1 GLB + 1 PNG | 场景来源，不等于完整的行为模型 |
| 候选场景家族 | 暂分 5 组 | 按结构和工艺复用关系隔离划分；相似来源仍需审核 |
| 正常工艺父案例 | 计划 72 个 | 同一场景内不同任务、初态、条件或有限批次的合法候选 |
| D-S 结构/绑定子集 | 72 父案例 + 216 变体 = **288 个候选** | 每父案例安排 3 个结构/绑定缺陷候选 |
| D-V 路径验证子集 | 72 父案例 + 288 变体 = **360 个候选** | 每父案例安排 4 个通过结构检查的语义变体 |
| D-S 与 D-V 去重并集 | 72 + 216 + 288 = **576 个候选案例** | 正常父案例只存一份，两子集通过索引复用 |
| D-X 反例解释子集 | 从 D-V 的确认结果选取，暂不定量 | 不是额外生成的一批独立工艺 |
| D-E DSL/ST 配对子集 | 首期目标 12 对，兼容后准入 | 从已审核案例中选取，不再加进 576 的独立工艺数 |
| D-R 变更复用子集 | 12 个代表父案例 × 3 类变更 = 36 对 | 单独的变更任务，不把前后版本算作独立场景 |

**576 是候选构建目标，不是保证有 576 个有效标注样本，更不是 576 个独立场景。** 结构变体可能重复触发同一问题；语义变体可能被其他契约保护，或者在给定环境中不可触发。入库时分别拒绝、去重或保留为合法/被保护负对照，记录实际数量。

从十二份资产理论上可生成任意多参数组合，但没有科学依据给出“最大能生成多少”。以上规模优先覆盖结构与协议差异，适合首轮可控实验；后续规模曲线另按参数扩展，不靠改名称、换截图或重复随机种子虚增数量。

这里细化并替代 [研究方案](../../docs/method.md) 第 6.2 节的 D-S=240、D-V=120 初始目标；不是把新旧数量累加。原文其他研究边界与子集分类保留。

### 2.1 符号验证模型需要定义什么

当前算法可以直接使用自定义符号场景，不要求提供 GLB、图片、坐标或节点映射。十二个三维场景作为工艺结构的参考来源；验证输入由以下语义信息组成，具体实体与关系按所验证案例的需要定义：

1. **语义实例定义与契约绑定**：定义设备、物料、槽位、符号区域及服务的唯一标识、类型和契约引用。例如 `R1` 绑定搬运能力契约，`C1.exit` 表示输送机出口，`transfer_zone` 表示共享交接资源。
2. **设备/能力模型**：可调用能力、输入输出、类型、前置/持续条件、各阶段与失败效果。
3. **工艺级关系**：物料交接对象、资源冲突、writer 权限、容量、占用与归属规则。
4. **问题数据**：初态、任务目标、有限物料清单、可用槽位与参数。
5. **环境模型**：允许的反馈时延、失效、重复和外部干预；空间条件单独声明。
6. **候选 DSL 与独立任务规格**：工艺可以写错，独立目标和义务不能因此跟着改。

**可选三维映射**：设备、关节和区域到 GLB 节点/几何的映射，仅用于后续三维展示、动作驱动或空间验证，不是本轮算法输入的必填项。缺少映射不构成符号模型不支持；缺少所验证能力的状态转换语义则仍需补齐。

符号场景中的“物料到达出口”“输送带实际停稳”等事实由抽象设备与环境转换产生，不需要运行动画。它们不能默认恒为 true；相应延迟、失效与状态变化仍须按验证范围建模。空间条件若作为外部假设使用，需明确记录，结论不延伸到实际几何可达性。

现有搬运与输送契约优先复用，逐字段核对版本和验证语义覆盖。对于新机床/加工/焊接/堆垛能力，先提供 `abstract_only` 模型开展路径验证，不把它伪装为已接通的原生设备动作。

### 3.1 DSL 表达限制

ac-process/0.1 的 `repeat` 不会自动选下一件物料、下一个槽位，也不会自动搜索下一工序。多物料案例使用显式 `material_1/material_2` 与不同节点，必要时离线模板生成有穷源码并记录生成器版本。有限循环重复同一绑定必须符合设备的循环业务，不可用 repeat 伪装动态迭代集合。

选择可用槽位或路径用预声明 `branch` 和事实条件表达；无法在当前语法表达的动态搜索标为语言扩展需求，不塞进隐式调度器。S03 的闭合几何不等于语言需要无限循环。

组装、焊接、加工、人工确认等能力只有建立了类型化契约和阶段效果后才能成为 invoke；不能仅在文本注释中写一句“加工完成”当作模型。

## 4. 子集构造方法与标签

### 4.1 D-S：结构与绑定，目标 288 个

每个正常父案例生成 3 个不同类别单缺陷候选，总计 216；原父案例 72 个作为合法对照。按场景可用元素轮换缺陷，不要求每个父案例具备所有类别。

| 类别 | 变异例子 | 标签依据 |
| --- | --- | --- |
| 语法/结构 | 缺括号、重复 ID、非法节点树 | 文法/IR schema 与最小定位 |
| 类型/单位 | material 传给 location；速度单位错误 | 名义类型、arguments_schema、单位规则 |
| 能力/方向 | 不存在能力、写只读输出、continuous 直接 invoke | 能力表、接口方向和节点语义 |
| 请求作用域 | 使用未来请求、跨未合流兄弟分支引用 | 支配/作用域规则 |
| 控制授权 | 父子重复独占 writer、缺少继承契约 | 明确的控制/资源绑定规则 |

语义变体如果未通过结构检查，归入 D-S 或拒绝生成，不混成 D-V 的路径检出成功。缺真实执行器属于部署状态，不能作为 D-S 的非法标签。缺验证抽象模型用独立 coverage 集记录，不列作已知逻辑错误。

### 4.2 D-V：执行路径，目标 360 个

每个父案例安排 4 个语义变体，优先覆盖以下四组；具体操作必须满足变异适用条件。正常父案例复用，不复制文件。

| 组 | 候选变异 | 可能被保护的情况 |
| --- | --- | --- |
| M1 顺序/阶段 | 在合法语法内改换步骤顺序、提前退出/跳过检查 | 能力前置条件仍阻挡，变体可能只是等待或受控失败 |
| M2 主体/证据绑定 | 使用另一已绑定物料或语义错误但类型合法的反馈条件 | 请求关联、主体校验可能拒绝结果 |
| M3 资源/交接配置 | 删除候选配置中的一个交接区冲突、错误容量使用、重复交接步骤 | 设备独占或中心事务服务可能仍保安全 |
| M4 完成/异常策略 | 弱化程序 final_goal、错误正常完成条件、允许的策略参数配置错误 | 外层清理/独立停止确认可能保护系统 |

这里变异的是候选工艺、绑定或明确列出的候选控制配置，**不同时改独立契约义务、TaskSpec 和真值判定规则**。若某字段由可信运行器固定而不可配置，不能凭空把该缺陷算成 DSL 可表达错误。

请求 ID 接收、去重、停止后释放等协议实现错误可另建 `protocol-conformance` 诊断轨道：显式替换候选 controller/adapter 规则并锁定正确契约。该轨道用于验证模型/协议检查能力，分别统计，不混成“DSL 源码错误检出率”。其额外样本暂不计入 576。

每个语义变体有四种准入结果：

- `confirmed_violation`：在所给假设、性质和边界下有确认的违例。
- `protected_or_equivalent`：变异被其他保护挡住，或对所测性质等价；可保留为负对照，不能算漏检。
- `unresolved`：求解未决、模型不足或未能独立标注；保留隔离，不混入已知真值准确率。
- `rejected`：结构非法、重复无新语义、不符合变异前提；记录原因，不为了凑数强行入库。

同一个案例可以 V04 安全、V09 违例、V10a 不可达于当前 K；因此 expected 必须按 `(case, property, environment, bound)` 保存，禁止只给整个案例一个“正/负”标签。

### 4.3 D-X、D-E、D-R

**D-X** 从已确认 D-V 反例提取源节点、根因位置、物料/资源/请求、触发条件与最短已知反例；另选合法等待、受控失败、attention_required 作为诊断负对照。多个性质触发同一根因时保持共同 defect_id，不重复当成独立缺陷。最短只在已完成最短性搜索的范围内声明。

**D-E** 首期目标 12 对 DSL/ST 案例，优先从 S04/S03 和有限资源竞争的小模型选取。统一设备抽象、时钟、输入、初态、目标和异常允许范围，映射两端观察点与请求身份；ST 采用有充分保护的功能块。12 对是兼容验证后的目标，不保证各场景各一对。不支持的 PLC 语言/后端子集记录原因，不把未运行结果计作失败。

**D-R** 每个场景选 1 个代表父案例，共 12 个；每个定义三类配对改动：兼容别名/信号绑定变化、能力协议/响应预算变化、任务目标/容量约束变化，共 36 个变更任务。保存哪些文件必须改、影响到哪些性质、重验结论及操作记录。当前候选程序与独立规格必须按变更任务说明分别修改；这不是 D-V 的故障变异。

## 6. 标签如何获得，防止循环自证

1. 人工依据任务说明、契约和语言语义审核 72 个父案例，明确正常完成、允许等待/失败及外部假设；保存未解决歧义。
2. 为每个变异保存 parent hash、改动点、预期影响、独立性质引用，不直接复制“故障名”作为最终标签。
3. 小模型用独立参考探索，在相同状态域、K 和环境下获得真值；只对封闭完整遍历声明有限模型证明。
4. SAT 轨迹在完整模型中重放，并由审核者核对关键事件。候选算法输出本身不能成为唯一 oracle。
5. BMC 的 UNSAT 仅能支持给定 K 内的标签；超时/unknown 不得标“无缺陷”。共享 TransitionIR 的双后端一致也不能排除建模错误，需要手写轨迹和语义边界对照。
6. 多条性质分别标注；增加环境扰动后重新审核对应查询，不沿用 nominal 的目标达成标签。

真值依据分级：人工规范判断、完整有限参考搜索、有界参考结论、独立后端交叉检查、轨迹重放、真实执行复核。保存每项依据，不能把其中任何一种泛化成未观察范围的物理正确性。

图片/GLB 仅有可视化内容时，其对应模型可用于**明确假设下的符号验证实验**；不能用实验结论声称已验证了实际机械臂空间可达或加工质量。

## 7. 划分与泄漏控制

建议先按下面的候选家族划分，后续通过 GLB 来源、几何复用和语义模板审核近重复。S04 与既有 T0 属同一家族；S01/S02/S10 的托盘作业不跨集合随机拆散。通用机器人/输送契约复用是研究目标，可以跨集合；专门的工艺模板及其变体必须成组。

## 8. 验证作业数、规模扩展与指标

### 8.1 案例数不等于运行次数

对 D-V 按实际适用性计算：

```text
jobs = Σ_case Σ_environment Σ_property Σ_bound applicable(case, env, property, bound)
timing_runs = jobs × repeated_measurements
```

若仅为预算估算，假定 360 个候选全部准入、每个 10 条适用查询、3 种环境、3 个 K，则为 **32,400 个作业**。正式 V10 已分成 a/b，且某些性质不适用，所以不能把这个估算当作正式清单；10 只是演算平均值。5 次计时为 162,000 次执行，仍只对应同一批候选案例。

先按 case 支持检查与性质适用性生成 jobs.jsonl，再执行。重复计时采用相同机器/预算、冷暖缓存分开；求解超时须进入覆盖率和资源曲线，不只报告成功作业的平均耗时。

### 8.2 规模实验

选择 S03、S06、S07、S09 的已审核小模型，分别扩大有限物料数量、槽位数量、并发支数、工序节点和时间界限。一次先控制一个变量，再做组合压力组。

扩规模要重新生成明确物料/槽位绑定和独立目标，不是只改计数标签。状态空间超限时记录适用范围；扩展案例作为同父案例的相关规模序列，不计作新增独立场景。空间布局仍取自已有场景或标注为纯符号扩展，不能声称原图片中出现了新增设备。

### 8.3 实验维度

| 实验 | 对比与指标 | 解释边界 |
| --- | --- | --- |
| 结构检查 | B-Rule 与本方案前端：各错误类别检出/误报、定位 | 不和路径求解耗时直接比快慢 |
| 路径检出 | 完整模型与优化模型：逐性质 TP/FP/FN、覆盖率、unknown | 有界标签配相同 K；按父案例/家族分组 |
| 效率 | 构造、编码、求解、重放耗时，内存、变量/约束/状态规模 | 包含切片和缓存构建开销；冷暖分开 |
| 反例解释 | 可重放比例、伪反例率、根因定位、轨迹长度 | 不把多个报警当多个独立缺陷 |
| PLC 配对 | 共同性质支持率、建模/配置成本、验证与诊断 | 同等保护的 ST/FB 与相同 plant/environment |
| 复用/变更 | 修改字段/文件、人工时间、影响性质识别与回归成本 | 记录具体编辑任务，不仅比代码行数 |

若报告二分类准确性，以“违例”为正类，并限定有已审核真值且所用边界一致的查询。未决结果单列 abstention；同时给出全作业支持/完成率，避免只在容易案例上统计高准确率。可对父案例或家族做配对聚合，不将多 K、多种子当独立统计样本。

## 9. 建议落地顺序

1. **S04 先行**：复用 T0，补完整符号状态、独立目标、停带/交接/反馈模型。先建 P01 正常案例及少量单缺陷/被保护对照，不急于生成全量。
2. **S03 与 S06 扩展**：引入有限循环、分支与共享资源并发，验证九类 DSL 节点及切片依赖。
3. **其余场景语义标注**：先复核实例与能力，再批量生成候选；新的加工/仓储能力通过 abstract_only 轨道明确接入。
4. **冻结 72 父案例和准入规则**：只在任务语义可区分、模型齐备后认可数量；无法支持的父案例保持 draft 并调整清单，不能补重复案例凑数。
5. **生成并审核变体**：目标 216 DS 与 288 DV，发布实际准入、被保护、重复、未决数量及原因。
6. **冻结分组与标签**：再开展全模型/优化模型配对、PLC 共同子集和变更成本实验。
