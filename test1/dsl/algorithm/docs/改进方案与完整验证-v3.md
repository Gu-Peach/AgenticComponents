# 方法一：改进方案与完整验证

## 1. 研究范围和验收口径

研究对象是设备契约驱动的工艺执行路径验证，输入为冻结的设备能力、符号场景、候选 DSL、独立任务规格和有限环境模型。空间可达性、真实设备、PLC 翻译等价、学习型派工不属于本次验收。

历史 v2 基线为 576 个静态案例、360 个语义案例，以及 nominal/K=3000 下 303 个案例的 606 条核心查询。v2 的 auto 对 V09、V10a 各回答 168 条，各有 135 条未决。通道层有 61 份有限参考配置；这不等于整线并发/故障真值。

“完整验证”分三道门，必须分别报告：

1. **运行完整**：预先列出的每项作业都有唯一结束记录，错误、超时和不支持也有记录；可恢复运行，不漏项、不重复统计。
2. **证据完整**：每个已准入标签都绑定原始输入、语义版本和本次生成的证书；证书可以重新检查，结论不存在自证循环。
3. **研究问题闭合**：目标案例/环境/性质的独立参考模型覆盖完整，求解结论与它一致，适用前提和实现对应关系有充分证据。

前两项通过不能代替第三项。任何 UNKNOWN 都不能改写为 HOLDS；“有明确隔离状态”也不自动表示完成了业务目标。

## 2. 问题 A：独立并发与故障参考不足

### 2.1 分层构造参考模型

保留通道参考模型，增加一个不导入 `acverify` 的有限交接协议内核。内核显式包含请求阶段、独占授权、目的地容量预留、物理位置、业务归属、工具持有、失败传播和隔离。两个请求在每个阶段交错，并允许在任何活跃阶段发生一次故障。

参考层分别处理：

| 层 | 检查内容 | 可以支持的结论 |
| --- | --- | --- |
| 消息通道 | 周期采样、FIFO、时延、陈旧证据、请求身份 | 给定有限窗口内的可观察时刻集合 |
| 交接内核 | 资源互斥、预留与容量、取放阶段、部分物理效果、失败隔离 | 指定有限内核的全状态不变量与终态集合 |
| 成功终态抽象 | DSL 组合结构与契约成功效果 | 所有成功路径的终态性质；不能单独证明正向可达性 |
| 整线计时参考 | 控制器、通道、设备、外部事件同步积 | 指定 K/profile 下的完整查询真值 |

前三层可以独立实现和穷举。第四层必须建立各层的精化映射及时间对应，不能用前三层测试通过来冒充。若尚未完成，门禁必须明确列出 `whole_line_timed_refinement` 缺口。

### 2.2 故障矩阵

分别覆盖 accepted 前后、抓取后、离源后、放置后、释放后、提交后和停止确认前的故障。每项记录是否保留物理效果、业务归属、预留和隔离。

- 许可丢失：禁止新的执行，停止所有已激活分支。
- 提供者重启：提升 epoch，使旧反馈失效；不回滚物理状态。
- 停止确认丢失：实际停止与证据确认分离，超时进入需处理状态并保留必要隔离。
- 重复反馈：不能再次提交交接或重新设置 accepted 时钟。
- 旧请求/旧 epoch：不能解除当前请求的等待。
- 持续陈旧反馈：没有“最终必有新鲜证据”的隐含公平性。

参考模型与被测模型需分开实现。差分测试只比较相同输入和可观察投影；发现分歧先保留反例，不能按被测输出修改答案。

### 2.3 整线闭合的完成条件

对 360 个语义案例逐一记录 `(case, profile, K, property)`。缺失模型项必须带原因；内核证明只用于满足适用条件的性质。整线计时参考应独立处理 `par`、资源竞争、外部替换、epoch 变化、请求寿命和停止未知。满足以下条件后才可宣称整线真值完整：

1. 对应同步积或可靠抽象的状态空间已闭合；
2. 抽象不变量的初态、各转换保持性和具体到抽象映射已检查；
3. 有界响应包含窗口尾部，不以 K 截断掩盖逾期请求；
4. 正向可达性有可重放的计时见证；负向结论来自穷举或普遍性证明；
5. 无未声明的时间、公平性或物理效果假设。

## 3. 问题 B：普遍性证明与证据准入

### 3.1 替换“单次成功见证推出唯一成功终态”

新增 `success_projection_v3.py`。其状态是任务目标可读取的物料、设备和外部事实。对语法树做成功路径抽象解释：

- invoke：只在“本次调用成功”这一前提下按契约顺序应用全部阶段效果；不把它解释为必定能执行成功。
- seq：依次组合成功后态；任一子节点没有成功路径，则父节点没有成功路径。
- repeat：按有限次数展开，每次请求身份不同。
- await/delay：擦除等待，保守增加可能成功路径。因此不能据此给出 REACHABLE。
- branch：保留所有分支；仅在无并发、无外部变化且条件完全来自稳定 world 事实时求值剪枝。
- with-control：成功进入时驱动生效，成功退出时实际停止且授权释放。
- par：仅对成功效果写集合不相交的子树组合后态；重叠写入拒绝证明，不假定设备 ID 不同就独立。
- fail：无成功后态。当前语言没有捕获失败并继续成功的语法。

令 `Post#(P,s0)` 为这种过近似。若所有具体成功终态均被它覆盖，则：

`∀s∈Post#: Goal(s)` 可推出 V09；

`∀s∈Post#: ¬Goal(s)` 可推出 V10a 的不可达结论。

第二式不需要声称实际存在成功执行。正向可达性仍必须使用独立计时见证。故障部分效果不会偷偷进入成功分支：此项依赖冻结语义中的失败传播规则，应作为明确前提。

### 3.2 结构归纳证明

基础步：成功 invoke 的线性阶段全部执行一次，抽象变换等于这些效果对投影状态的复合；await/delay 擦除只增加路径，fail 不产生成功路径。

归纳步：seq 和有限 repeat 由关系复合保持覆盖；branch 取并集覆盖实际选中分支；with-control 在子树两端加入成功协议的确定效果；par 仅在所有成功写集合互斥时成立，写集合中的自增只读取同一字段，所以交错不能改变成功后态。条件读取可能受到并发影响，因此并发存在时不剪枝。

外部定时写入、未知效果、非线性阶段、恢复/回滚、重叠并发写入、证明展开超限都必须拒绝。证明的适用范围是冻结的符号语义，不是任意控制器实现或连续物理系统。

### 3.3 本次证据直接冻结

新增 v3 核心定义；每条准入查询保存本次重算的逻辑证书、成功终态证明树或计时见证及检查结果，不能只链接旧包。索引记录证据摘要、输入摘要、语义摘要、构造器摘要、原始准入来源与适用前提。

原 v2 保留。存在性和普遍性证据分开标记；当前时间上界不能从无时间的投影证明推出。构造器不得读取被测实验结果。审核器重新读取文件并重算，不信任文件中的 `verified: true`。

## 4. 问题 C：未决率与实验可信度

### 4.1 实验矩阵

全量运行矩阵覆盖 360 个语义案例的 nominal、delayed 和 fault；试点的强制停止丢失使用真实 profile 名称。静态检查覆盖 576 个案例。

性能实验在运行前冻结样本，按场景分层选取案例，并覆盖 par、branch、repeat、外部事件和变体。采用 `full / compact / auto`，隔离状态压缩与时间平移归约的效果。每项使用多个时间预算、3 次独立进程重复；方法顺序以固定种子打乱。K、状态数、内存和 watchdog 明确记录。

另做构造性见证搜索作为补充。它可以缩短存在性查询，却不能把没有发现错误的路径当安全证明。不同搜索策略不得混用分母。

### 4.2 统计指标

- 静态分类混淆矩阵；
- 已回答准确率、覆盖率、全部查询中的正确比例、未决/超时/不支持率；
- 各场景、环境、属性、父案例族分组；
- 求解耗时中位数/IQR、状态/边数、采样 RSS；
- 同预算下共同解出的配对耗时，而非将超时当作正常耗时计算加速比；
- 所有重复均一致回答的稳定覆盖率，以及不同重复的答案冲突；
- 输入/实现/语义冻结一致性与见证重放情况。

重复测量不是增加独立样本数量；近似相同的变体按父案例族分析。主结果保持 UNKNOWN，不把增加预算后回答的结果偷偷替换旧结果。

### 4.3 控制成本

先用低预算全量检查得到覆盖矩阵；再对预先冻结的分层样本做多预算重复消融。若需要提高覆盖率，追加预算形成新批次，并保留前批。预算不足是一种结果，不要求为了得到整齐表格而无限扩展。

### 4.4 优化目标与当前证据

本节是后续求解器的算法设计，不表示这些优化已经实现。现有 `full / compact / auto` 和 v3 结果保持为冻结基线。

v3 在 0.5 秒搜索预算下，对 659 条已准入的 nominal 查询回答 230 条，未决 429 条；已回答部分无参考冲突。24 个抽样案例中有 35 条已准入查询，2 秒预算下三次重复均稳定回答的数量为 full 5 条、compact 6 条、auto 24 条。这支持继续研究归约，但尚不能定位所有超时的原因。

优化目标是在相同输入、语义、K 和总资源预算下，提高**可证明正确的查询覆盖率**，同时降低共同完成查询的耗时与内存。增加预算作为独立实验轴，不作为算法改进。不得通过缩短 K、减少允许故障、缩窄反馈延迟、放宽目标或加入未声明公平性来提高覆盖率。

采用逐性质调度的组合验证流程：

`契约依赖分析 → 可检查的证明预处理 → 有预算的见证搜索 → 保持语义的显式搜索 → 必要时转入可选符号后端`。

其中前三项可以提前回答部分性质；其他性质继续求解。不同算法阶段共用总预算，不给每个阶段额外获得一次完整预算。证明预处理必须另行实现，不能调用参考答案生成器或读取 oracle。

### 4.5 O0：先构造瓶颈剖析器

现有 `backends.explore()` 遍历逐 tick 后继，用规范化序列化结果判重；`model.successors()` 在故障、消息和设备阶段枚举分支；`reduction.compact()`、`clock_key()` 会复制或变换状态。这些是需要测量的候选开销，不能仅根据代码就认定哪个占主导。

在开发集上记录下列数据，剖析运行与正式计时运行分开：

| 维度 | 采集内容 | 用途 |
| --- | --- | --- |
| 时间分解 | 前端/模型构造、后继生成、复制、规范化/判重、性质检查、见证重放 | 区分每个状态成本与状态数量问题 |
| 分支来源 | 故障选择数、消息交付选择数、设备阶段选择数、组合后继数 | 识别真正的组合爆炸来源 |
| 图规模 | 生成后继数、唯一状态数、重复状态数、边数、最大队列长度 | 判断判重与存储优化价值 |
| 协议状态 | 活跃请求数、各流排队样本数、不同 epoch 数、未完成停止数 | 判断消息或失败路径是否占主导 |
| 搜索终止 | TIMEOUT、状态上限、内存上限、单次后继上限、K 截断、响应尾窗不足 | 避免将所有未决都记作超时 |
| 查询进展 | 首个目标见证/反例时刻、每个性质决定时刻 | 决定是否需要调整搜索顺序 |

指标定义：`重复率 = 1 - 唯一新状态数 / 生成后继数`；`状态吞吐 = 展开状态数 / 搜索秒数`。同时记录输入规模和并发宽度。重复率高不自动证明可以删去分支；低吞吐也不自动说明模型规模大。

输出 `profile.json`、按场景/环境/父案例族分组的瓶颈表和所用源码摘要。先做这一步，再决定是否投入高成本的偏序或符号后端。

### 4.6 O1：状态表示、判重与持久化搜索

**目的：**优先降低单个后继的复制、编码和存储成本，保持原来的状态集合与转换关系。

1. 将不随运行变化的设备定义、契约、节点和资源关系移入只读模型表；运行态保存整数索引与可变值。物料身份、请求身份、epoch 和隔离归属不得省略。
2. 将状态分为 world、tasks、feedback、monitor 等不可变分块。转换只替换发生变化的分块，其他分块共享。禁止在共享列表或字典上原地写入；先做“修改后继不改变父状态和兄弟状态”的测试。
3. 对状态构造规范元组作为精确判重键，避免在搜索内反复生成大段 JSON；JSON 仍用于导出与诊断。使用摘要作索引时，对摘要冲突执行完整键比较，不能只凭哈希相等合并。
4. 复用现有终态字段清理规则；要进一步删除 completed 记录、旧请求、阶段证据或 attention 状态，必须完成未来读取分析。attention 不是可随意清理的普通终态。
5. 显式搜索默认保存唯一状态、每个状态的一条见证父边和统计计数。只有使用完整图导出或图上 SMT 查询时才保存全部边，避免在只需见证重构的运行中积累重复边。
6. 增加检查点：保存待扩展队列、已见状态、最短距离、父指针、已决定性质、累计预算和输入/模型/版本摘要。恢复只允许完全相同的 K、profile、性质语义和实现版本；提高 K 时不能把原来被截断的边当作已检查。

**验收：**在能够完整穷举的小模型上，新旧状态投影及带标签转换关系相同，所有性质结论相同，所有输出见证可在旧模型中重放。正式测试中分别报告状态数不变时的吞吐、耗时和内存；这一优化不以减少状态数量为成功标准。

### 4.7 O2：按性质求解的预处理与搜索组合

#### 4.7.1 分别维护查询结果

为每个性质维护 `UNDECIDED / WITNESS / PROOF / BOUNDED_CLEAR / NOT_APPLICABLE`，并保留结论范围。一个见证只能决定它对应的存在性或违规查询。

| 查询 | 可以提前决定的证据 | 不能据此决定的结论 |
| --- | --- | --- |
| V09：成功是否满足目标 | 假成功反例；可靠的成功后态证明 | 一条正常完成路径不能证明 V09 |
| V10a：目标是否可达 | K 内目标见证；覆盖所有成功路径的不可达证明 | 没找到见证不等于不可达 |
| V01–V08：安全/协议性质 | 违规反例；适用的保持性证明或完整搜索 | 不相关性质的反例不能决定本性质 |
| V10b：有界响应 | 到期仍无有效响应的轨迹；完整窗口证明 | 正在 stopping、K 截断或裸故障标志不能当作已响应 |

保留现有结果枚举的语义，不用一个全局 `success` 标志替代逐性质结果。当前 `search='witness'` 在发现任意目标或违规后可停止，后续应允许配置 `target_properties`，避免无关见证消耗预算后提前终止目标查询。

#### 4.7.2 可检查的证明预处理

生产侧单独实现三类初始规则：必经最终条件蕴含任务目标；无生产者的初始阻塞条件；线性成功效果/不相交并发效果的成功后态过近似。每条规则输出前提、适用版本、推导节点和结论，并由证书检查器重新检查。

这与参考侧成功后态证明在数学思想上可以相近，但被测实现不能导入 `tools/success_projection_v3.py`、`build_standard_answers.py` 或 oracle 文件。若使用与参考核心相同的定理家族，实验必须单列“定理预处理回答”与“状态搜索回答”，并在小模型独立穷举和新的反例变异上检查，不能把同一定理的两次运行包装成两个独立正确性来源。

第一版只准入前提明确的规则；未知效果、外部时序变化、共享写入并发或不支持的表达式均回退到搜索。证明“所有成功终态满足目标”不等于证明存在成功执行。

#### 4.7.3 有预算的见证优先搜索

在 development 集比较少量预先声明的预算配比，例如：预处理最多 5%，见证搜索最多 15%，完整搜索获得剩余预算；另以 0% 见证搜索作对照。未使用的预算归还完整搜索，比例在 validation 前固定，不按 test 标签调参。

候选启发式为“剩余工艺节点数、未满足目标原子数、接近响应期限的请求数”。对 V10a 优先探索目标接近的分支；对 V09 优先探索弱终检条件、交接未提交等可能反例。**启发式只改变搜索顺序，不删除分支**，不假设它是可采纳的最短路估价。

见证阶段可以偏向短延迟或零故障分支寻找存在性，但后续完整搜索仍必须覆盖原 profile 的全部允许选择。阶段预算耗尽且没有证据时，结果仍为 UNDECIDED。

缓存只按输入、契约、任务目标、profile、K、语义、实现和证明规则版本的摘要命中。单独报告冷启动与缓存命中结果，不能将缓存运行混入首次求解效率。

### 4.8 O3：消息流表示与等价归约

**目的：**缓解保持型状态每周期采样带来的队列复制和消息交付分支增长。

第一步只压缩表示：以 `(activation, request, device, subject, epoch, kind)` 分流，使用不可变共享的样本队列；相同有效载荷的连续采样可用区间段存储，但逻辑上保留每个采样时间、交付区间和 FIFO 次序，读取后继时能逐样本精确展开。这一步不减少语义选择。

第二步才研究语义归约。为消息状态构造包含接收者阶段、采样年龄、可交付区间、FIFO 阻塞关系和故障预算的签名。只有证明两个消息状态对所有未来接收决策及被检性质产生相同结果，才允许合并；证明不了则保持原队列。

以下快捷处理禁止直接使用：

- 仅保留最新样本：旧样本可能阻塞新样本的 FIFO 交付。
- 直接丢弃过期样本：虽然它不能确认请求，但它的交付时间仍可能影响后续样本。
- 给重复包刷新时间戳，或认为周期刷新保证最终收到新鲜证据。
- 不区分当前/旧 activation、epoch 或物料身份。
- 删除重复注入机会却保留原故障计数结论：注入可能消耗共享故障预算，改变其他故障的可达性。

**验收：**独立通道枚举中，不只比较首次可观察时刻，还比较接受时钟、最终协议状态和相关监视器输出；扩展 ready/delay/max_age 的边界组合，加入重启、旧请求、重复包和丢失停止确认。随后在小型整线模型上比较全部终态/违规集合与有限时刻可达性。

### 4.9 O4：有条件的时间跳跃与时钟归约

现有 `clock_key()` 适用于无绝对时间外部事件的完整 BFS，不能因为启用了新搜索顺序就无条件复用。增加带权时间跳跃后，按累计真实 tick 距离探索，使用 Dijkstra 或等价的分桶最短路；发现更短代表时重新松弛并扩展，不能仅按宏步数量保留首个状态。

对状态 s，计算可能改变控制或性质的最早 tick：

`b = min(下一次任务可执行、阶段最早变化、消息可交付/必须交付、样本失鲜、外部事件、门控/接受/执行/停止期限、V10b 期限、K)`。

只有证明 `tick+1 ... b-1` 内状态除时钟外不会改变、没有性质变化、没有允许的故障注入或消息/阶段选择时，才折叠这段等待。到达 b 时按冻结的六阶段顺序执行普通 tick，不跨过边界直接提交动作效果。边的权重记录真实经过的 tick 数。

第一版限制在没有活跃采样流、没有可注入故障、没有待分支的设备阶段的静止等待段。只要周期采样或任何活跃阶段允许故障，通常只能推进一个 tick；禁止为了制造大跳跃而关闭这些选择。带外部事件时先保留绝对 tick，不直接启用现有时间平移键。

证明义务是被折叠区间内的停顿等价，以及性质监视器的时间等价。V10b、超时和采样失鲜都对时间敏感，不能仅证明物料位置不变。验证后方可扩展到能够解析批量生成样本的等待段。

**验收：**保留每条宏边的时间跨度和跳跃理由；重放时恢复逐 tick 轨迹。对 `deadline-1 / deadline / deadline+1`、K 边界、FIFO 最迟交付、epoch 重启和同 tick 外部事件做差分检查。

### 4.10 O5：契约依赖驱动的偏序归约

**目的：**仅消除可证明等价的独立交错，不把任意并发当作独立。

对每个待执行转换实例化 `R(a), W(a), C(a), O(a)`：分别表示实际状态字段的读集合、写集合、资源/容量冲突集合，以及对查询可见的变化。契约中的 `$device/$material/$source/$target` 必须解析为实例字段；还需补充协议、控制器与环境的隐式依赖。

初步独立条件包括：

`W(a) ∩ (R(b) ∪ W(b)) = ∅`，且对称条件成立；不存在相同资源、声明冲突资源、共享容量池、物料归属、同一消息流或同一请求依赖。全局 abort、故障计数、父节点完成、writer 与区域冲突、仲裁顺序、转换次数预算及性质监视器也参与判断。

上述集合条件只是候选筛选。实际删分支还必须证明：

1. a、b 不相互启用或禁用；
2. `a;b` 与 `b;a` 的状态、经过时间和相关观察等价；
3. 对性质可见的中间状态不被遗漏；
4. 循环条件保证被推迟的转换不会永久失去探索机会；
5. 有界响应和 K 的结果保持。

当前控制器在 tick 内按固定次序仲裁，设备阶段又可能同 tick 更新，因此不能凭空加入另一种调度顺序，也不能把两个独立设备“本 tick 完成/不完成”的四种组合压成一种。第一版只生成依赖图和潜在可交换转换统计；选择语义中确实存在的独立交错，再实现带完整适用检查的保守 persistent-set 搜索。任何条件不明则展开全部后继。

首轮仅对可证明保持的无时间安全/可达查询开放；V10b 默认关闭，直到提供带时间的保持性证明。报告必须记录每个性质实际启用了哪些归约，不能把一张经过不适用归约的图用于所有性质。

**验收：**独立模型对照包含不同设备但共享物料/容量、writer 与交接区、全局故障预算、并行失败取消以及同 tick 抢占。完整搜索与归约搜索的目标/违规可达性必须一致，反例必须能在原始模型重放。

### 4.11 O6：可选的直接符号求解后端

只有 O0 证明剩余瓶颈主要来自有限计时/故障选择的显式枚举，并且 O1–O5 仍不足时，再实施此项。

现有 `graph_bmc()` 对已经生成的显式图做 SMT 查询，仍需先支付图构造成本，不能将它称为直接符号 BMC 或扩展性改进。拟新增后端直接编码：

`Init(S0) ∧ ∧(t=0..K-1) T(St, Et, St+1) ∧ Query(S0..SK)`。

状态域显式有限化；`Et` 包括允许的延迟、交付、故障及事件选择。T 必须保持扫描阶段顺序、仲裁规则、物理阶段效果、周期采样、FIFO、epoch、故障预算和期限。消息槽位上界若截断合法队列，不能从 UNSAT 推出不可达或安全；应证明上界足够，或返回不支持。

采用增量深度求解，共享已编码前缀，每个性质使用独立 assumption literal。SAT 结果解码并在原 tick 模型重放；UNSAT 只说明所编码且完整覆盖的 K 内不存在目标/违规，不能宣称无界安全。V10b 的触发尾窗需扩展搜索或限制已覆盖触发集合，并明确报告范围。

该后端仍是被测算法，不能同时担任其自己的独立答案来源。第一版只支持小型顺序与双分支程序，不支持的构造回退显式搜索；多案例性能收益必须实测。

### 4.12 调度流程、模块与实施顺序

统一调度流程如下，其中所有结果都附带性质、K、profile、适用假设、证据和输入摘要：

```text
verify(case, queries, total_budget):
    model = load_and_freeze(case)
    pending = applicable(queries)
    deps = instantiate_dependencies(model)
    for proof in production_precheck(model, pending, capped_budget):
        if certificate_checker.accept(proof):
            publish(proof); pending.remove(proof.query)
    run_targeted_witness_search(model, pending, capped_budget)
    publish_only_replayed_witnesses()
    for compatible_query_group in group_by_reduction_requirements(pending):
        choose enabled optimizations using explicit applicability checks
        resume or start exact search within the remaining shared budget
        publish evidence-backed per-query results
    return decided results plus UNKNOWN with precise limit/unsupported reasons
```

以下是**规划新增**的模块，不是已有实现；现有文件只承担调度或适配：

| 模块 | 设计职责 | 主要接入点 |
| --- | --- | --- |
| `src/acverify/profiling.py` | 分阶段计时、分支归因和图规模计数 | `model.py`、`backends.py` |
| `src/acverify/state_store.py` | 不可变状态块、精确键、碰撞复核、父边 | `backends.py`、`reduction.py` |
| `src/acverify/checkpoint.py` | 带版本和预算摘要的搜索恢复 | `backends.py`、`budgets.py` |
| `src/acverify/query_plan.py` | 逐性质结果、兼容查询分组和预算分配 | `pipeline.py`、`properties.py` |
| `src/acverify/precheck.py` | 生产侧证明规则，禁止读取 oracle | `query_plan.py` |
| `src/acverify/certificates.py` | 证明对象、前提核查及诊断位置 | `precheck.py`、`diagnostics.py` |

时间跳跃、启发式搜索、时钟键和偏序归约不能默认任意叠加；维护明确的兼容矩阵。特别是现有时钟键只允许其已验证的搜索条件，宏步需使用真实 tick 距离，偏序必须按性质启用。

### 4.13 优化实验与通过标准

新增实验版本使用同一份冻结输入、参考核心、K、profile 和硬件记录。开发/验证/测试按场景族及父案例划分，变体跟随父案例；现有全量结果已经被观察过，应称为回顾性评估。若需要未见场景泛化结论，另外冻结新的场景族或案例，不能将旧 test 重新称为盲测。

对照包含旧 full、旧 compact、旧 auto，以及 O1 单独、O1+O2、逐步加入 O3/O4/O5；生产侧定理预处理单列开关。只有出现有意义收益的模块才进入最终组合。保留多预算及至少三次独立进程重复，分别记录纯搜索预算与包含预处理/编码的总验证预算；组合算法的主比较必须总预算一致。

| 维度 | 验证方式 | 通过标准 |
| --- | --- | --- |
| 语义保持 | 能闭合的小模型做完整/优化差分；时限边界和故障变异 | 决定性结论零冲突；见证全部重放通过 |
| 判重可靠性 | 故意制造摘要冲突、共享状态写入、请求/epoch 混淆 | 不错误合并，不污染父/兄弟状态 |
| 证明可靠性 | 篡改前提/输入/证明；制造未知效果与共享并发写 | 必须拒绝或回退，不能输出无证据肯定结论 |
| 求解收益 | 同预算稳定覆盖率、每性质决定时刻、未决原因 | 优先提高稳定覆盖；全部已回答结论仍与适用参考一致 |
| 效率收益 | 共同回答子集的配对时间、内存、状态与边数 | 报告分布及父案例族差异，不只报告平均值 |
| 组合回退 | 不适用 profile、绝对事件、时间敏感性质 | 自动关闭不适用优化，保持范围声明 |

不预先承诺某个覆盖率或加速倍数。可以把“开发集覆盖率提高至少 10 个百分点，或共同解出查询的配对耗时中位数下降至少 20%”设为是否继续投入的工程筛选目标，但它们不是已取得的结果，也不替代统计不确定性分析。最终论文按真实测试数据报告，包括无收益或退化的场景。

优化求解器可以减少 UNKNOWN，但不能凭计算速度补出缺失的独立真值。第 2 节的整线参考模型与精化证明仍单独推进；只有它们也通过后，才能宣称整线并发/故障的完整验证。


## 5. 审核与自动门禁

审核由 AI 执行，明确写 `reviewer_type=AI_technical_review`。不声称独立第三方人工审定，也不把“尚无人签字”作为唯一阻碍。

机器门禁检查：证据可重算、输入不漂移、查询不重复/不缺失、阶段结果相容、未决单列、算法未读取 oracle、性能测量期间源码不变、图表来自同一冻结结果。负测试包括篡改证书、修改输入、未知效果、并发写冲突、陈旧/重复反馈和审核计数篡改。

最终报告必须同时给出 `execution_complete`、`evidence_integrity`、`whole_line_truth_complete`、`all_queries_decided`。前两项可以通过而后两项仍失败。若整线精化尚未完成，报告具体剩余义务，不用“人工审核待完成”掩盖。
