# P3 证据准入规则

## 1. 真值对象与可信边界

P3 的答案针对冻结的 `reference-six-phase/0.1` 符号参考问题。每个新查询绑定源查询 ID、案例、profile、K、性质版本、性质规范摘要、参考模型摘要、输入摘要及响应窗口。旧 P1 查询与旧实验标签不被覆盖。

`certification/` 与 `reference/` 分开：前者检查证据，后者是 P2 的可信转换语义核心。新增检查器不会改变 P2 的源码指纹。检查器不导入被测 `acverify`，不读取其实验结果填答案，但它仍信任经过固定版本审查的 P2 语义；这不是第三套物理仿真，也不是设备或 PLC 实现精化证明。

`trusted-kernel.json` 固定参考源码、规范和独立解析器版本。变更这些文件后，必须重新审查受影响的规则并版本化，不能自动重建哈希来绕过拒绝。

## 2. 轨迹证书

轨迹包含真实初态、每个 tick 的状态和转换事件。检查器从冻结初态出发，重新生成每一步的允许后继，核对状态和事件均匹配，并检查 tick 增量。伪造一个 `verified=true` 不会绕过检查。

- V10a：K 内的根成功、独立目标与清理义务同时成立，可给出 REACHABLE。
- 安全性质：K 内合法路径上的明确违规，可给出 VIOLATED。
- V10b：必须匹配声明的触发范围和响应期限，不能把窗口外的违约挪进原查询。
- 一条未发现违规的路径不能证明 HOLDS；一条没有成功的路径不能证明 UNREACHABLE。

候选路径有两种选择方式：无可选故障且选择最小允许时长/延迟；或者先让 accepted 新鲜到达，再选择允许但过期的 result/stop 延迟。选择路径不是修改环境范围，后续必须逐步检查所选路径确实属于原参考模型。

## 3. 有界图与闭合图证书

证书给出状态集合、全部边和 coverage_bound。检查器不信任生产者自报的闭合标志，而是逐状态重算合法后继的多重集合，并验证所有列出的状态从初态可达。

- tick 小于 coverage_bound 的运行态不能漏掉任何合法后继。
- 位于边界的运行态允许截断，但只能支撑该边界内的结论。
- 只有没有运行态边界，才能作为完整闭合的有限模型。
- 删除状态、删除边、修改事件、加入不可达状态或改变模型身份均拒绝。
- 闭合图可以支持更大的 K；未闭合图的 coverage_bound 小于查询 K 时不能给出普遍性或不可达结论。

对于 V10b，本轮采用更保守的准入：非闭合图不签发整体响应通过；无完整窗口的原查询继续未决。闭合图也要按原查询的 covered_trigger_cutoff 判定，记录尾部触发是否可达。仅覆盖完整窗口的结论不能描述为“所有 K 内请求都已得到保证”；延长尾窗是另一个查询身份。

## 4. 逻辑证书

### 必经最终条件矛盾

若根节点沿 seq 的最终必经 await 要求同一物料同时位于不同符号区域，或正向请求关联观察永远不能成立，则根成功不可达。由此可证明 V10a 不可达及 V09 空真成立。检查器重新解析条件和关联，不能依赖变体后缀。

### 最终条件蕴含目标

若必经最终 await 的正向合取包含独立目标和清理的全部原子，且没有外部事件，则检查其后的稳定性：到达该 await 说明此前子树均已成功，不再有物理工作；之后仅有组合节点收尾。旧/重复报文不会修改这些目标状态，活动请求重启等故障也不能制造根成功。该规则只证明“成功则满足目标”，不证明成功可达。

### 无生产者的初始阻塞条件

若仅经过 seq 包装后的第一个实际节点是 await，其中存在初态已知为假的原子，并且没有外部事件或初始协议工作，则该原子在进入动作前不会改变。等待超时会导致全局失败，不会跳过等待继续执行。

因此可证明根成功不可达；没有触发的动作/反馈/退出/隔离性质须标记空真。V05/V06 的通过依据是初态不变量已检查且这一执行段不修改物料、授权、预留或提交。V03 不从“没有请求”自动推导，因为等待条件仍可能消费世界事实。响应窗口本身不足的查询也不因此变成有意义的响应测试。

## 5. 成功效果过近似证书

此类证书只对无外部事件、无 par 的程序开放。它使用一个符号影子状态，描述成功路径可能产生的目标相关效果：

1. invoke 按契约线性顺序应用全部物理效果，原子效果采用冻结 P2 的语义；假设此次调用成功，不假设它一定可启动。
2. seq、有限 repeat 做关系复合；每次重复使用不同激活路径。
3. await/delay 擦除等待，branch 保留所有分支。增加可能结果会使证明更保守，不能据此推出可达性。
4. with-control 在进入/成功退出处加入驱动与 writer 效果。
5. fail 不产生成功后态。

真实根成功意味着已激活子树成功结束，调用已经执行其全部成功阶段，授权及活动请求已清理。重启导致全局失败；许可丢失在晚期退出时可能留下不同 permit 值，但当前目标语言不读取 permit 或通信元数据，因此证明的是**目标相关投影**，不是整个影子状态与具体终态逐字段相等。

证书保存各节点的前态、后态集合、规则和子推导依赖。检查器采用独立的推导遍历，逐项核对原子效果与组合覆盖；它与生成器共用可信的原子效果语义，不声称两套独立设备语义。

结构归纳保证真实成功目标投影被后态集合覆盖：

- 所有过近似后态都满足目标，可证明 V09。
- 所有过近似后态都不满足目标，可证明 V10a 不可达。
- 出现未知目标值或真假混合时，不猜结论。
- 空后态集合表示成功路径不存在；V09 标记空真，V10a 是正常的不可达结论。

并发、外部事件或证明展开超限均拒绝此规则，不能用设备 ID 不同代替独立性证明。

## 6. 聚合、空真和比较资格

每份证据重新检查后才参与逐查询聚合。相反结论进入 CONFLICT 隔离，不选择其中一个作为答案。空真证明与已检查的触发见证相冲突时也拒绝。参考结论的主证据与触发证据分别保存，不能把触发来源误记为另一个证明。

真值确定率以所有适用查询为分母；空真答案单列。V10a 不可达是存在性问题的正常负答案，不按安全蕴含的空真处理。非空真答案数量也不等于算法准确率。

所有答案都标记 `sut_comparison_eligible=false`，直到参考与被测执行语义在相关范围内完成对应。不能直接把这批新语义答案代入旧 v3/v4 输出计算准确率。

## 7. 任务元数据的解释边界

数据生成器中的 `required_environment_gates` 实际收集初始为 false 的外部事实，其中包含 `class_A`、`use_mainline` 等分流条件。它不能被一律解释为“这些条件最终必须变 true”，否则会错误否定已知 B 类分流等正常任务。

本版答案针对 V01–V10b 的正式定义，V09/V10a 读取冻结的 TaskSpec.goal、根成功及清理义务。额外必经门控/工序时序若要作为独立业务要求，应补明确公式并生成新查询版本，不能仅靠字段名推导，也不能事后修改当前答案。受影响案例登记在 `source-scope-notes.json`。

## 8. 复核与后续

构造器只提出候选，最终准入器逐份重新检查，并独立重算答案、触发和空真信息。它同时验证 P1 子文件摘要、实际输入字节和归一化来源，保留构造程序快照。旧 P1/P2 包和旧答案不变。

P4 接下来扩展尚未覆盖的并发/外部变化证明、V03 证据消费性质和更多故障/响应样本；P5 再完成统一范围下的算法比较。仍未决的查询保留具体原因，不通过删难例或猜测标签来提高覆盖率。
