# P4 覆盖扩展与证明边界

P4 在固定的 P2 六阶段参考语义、P3 证据规则上扩展真值覆盖。`reference/` 与 `certification/` 保持原版本；新增规则放在 `certification_p4/`。构造器与检查器不读取 `acverify` 的预测答案。所有结论都绑定模型摘要、性质版本、输入文件和时间窗口。

这里的“已认证”是本项目的证据准入状态，不表示第三方认证，也不表示真实设备、任意 PLC 程序或三维物理已被证明正确。部分结论来自经过技术审核的证明模式及机器检查的实例前提；没有使用证明助手验证 Python 实现的完整语义。源码摘要保证规则所针对的实现未变化，本身不构成正确性证明。

## 1. 四类扩展与各自解决的问题

| 扩展 | 文件 | 可产生的结论 | 不承诺的内容 |
| --- | --- | --- | --- |
| 参考协议构造不变量、条件归纳不变量 | `invariants.py` | V01–V08 的条件性 HOLDS | 不说明外部控制器按协议执行，也不证明触发可达 |
| 外部事件保持、成功后态投影 | `event_rules.py`、`goal_projection.py` | V09 HOLDS；V10a UNREACHABLE；初始阻塞导致的空真 | 不证明并发过程可执行，不保持全部时序轨迹 |
| 新鲜反馈下的响应上界 | `response_bound.py` | 有完整响应窗口的 V10b HOLDS | 不覆盖可能持续陈旧、重启或丢失停止确认的配置 |
| 带精确等待摘要的轨迹 | `quiet_wait.py` | 反例、可达性、触发见证 | 单条合法调度不证明所有路径满足性质 |

`binding.py` 统一查询与证据的适用范围检查。旧证据仍由原 P3 检查器处理。`witnesses.py` 只补触发见证，不能把一次成功运行升级为普遍成立。

## 2. 条件归纳规则

每份不变量证书包括：被验证性质、初态检查、契约模板摘要、实际实例条件、相关参考函数的 AST 摘要、触发状态和证明类别。检查器从模型重新计算这些字段，不相信文件中自行填写的 `verified=true`。

共同前提是初态无已知性质违规、模板属于审核目录、引用与观测值类型有效、更新只来自固定参考转移。`contract-policy.json` 固定当前支持的契约版本；新增设备或修改阶段效果后不能继续套用旧证明。

| 性质 | 归纳保持的依据 | 必须检查的实例条件与边界 |
| --- | --- | --- |
| V01 取料互锁 | 接受时取得物料、源区及运动授权；抓取前的物料与停稳条件在执行阶段保持 | 源区与该设备每个 writer 冲突；源区与升降/分度运动的授权冲突；工具和输送位置的 owner 正确 |
| V02 请求关联 | 激活产生请求身份，确认成功只消费当前身份的已接受反馈 | 固定身份生成、通道接收、完成函数；这是参考执行协议的构造保证 |
| V03 证据有效性 | 通道以同一有效性谓词决定消费；状态观测只消费已知布尔值并记录当前快照 | 不将未知值当真，不重打旧数据时间戳；这不是对外部传感器采样真实性的证明 |
| V04 授权唯一性 | 所有新增授权经过冲突检查，释放只删除当前持有者的授权 | 固定仲裁规则和资源域；不把设备 ID 不同视为资源独立 |
| V05 交接一致性 | 契约的抓取、离源、支承、释放、归属提交保持阶段关系；外部移动等待相关活动结束 | 物料声明和 owner 映射正确；失败保留部分效果，不回滚物料 |
| V06 容量 | 目标预留与占用提交受容量约束；转移中间态只有一个持有者；释放不增加占用 | 机械臂只有其工具位置、工具初始为空且不能作为其他动作/外部事件目标；内部输送、外部替换目的区的局部容量不小于设备组容量 |
| V07 作用域停止 | 正常退出同时需要本次停止写入、有效 stop 反馈和实际停稳 | 同一驱动的 writer 唯一，升降/分度与该 writer 互斥；这是受前提约束的协议构造保证 |
| V08 未知停止隔离 | 超时进入隔离并保留许可；处理器不改动物料事实；退役不释放隔离资源 | 固定 stop/scan/retire 处理；只证明该处理器的义务，不保证所有请求都会触发它 |

证明义务分为初态、每类状态写入的保持性、外部事件保持性、故障/停止保持性。代码里列出的函数锚点用于定位审核对象；其中的证明模式依赖这些函数的已审核语义。它们不能因有限测试通过就被解释为自动发现的定理。

诊断集特别检查两种违反前提的情况：删除源区/writer 冲突会产生真实 V01 反例；初始工具位置已有物料会产生真实 V06 反例。两者的证书都必须拒绝。其他小模型覆盖顺序、独立并发、共享物料、分支失败取消；这些模型单列，不计入正式数据集案例数。

## 3. 成功后态投影与外部事件

对于 V09 和 V10a，只需要对“根流程能够成功时，其后态可能是什么”构造上近似集合。删除前置守卫会增加可能后态，因此可以用于证明所有成功后态都满足目标，或所有成功后态都不可能满足目标；不能用该集合存在一个好后态来证明工艺可执行。

并发分支转换为代表性的顺序组合，需要同时满足：

1. 分支写入的物料集合互不相交。
2. 共享标量字段的所有可能最终写入值相同；否则拒绝投影。
3. 历史和循环计数按设备与物料分开处理。
4. 能影响目标或任何已调用物料的外部事件不得直接删除。
5. 仅在入口初态稳定、条件只读取不会被事件修改的外部事实，或只读取此前未被修改的物料位置/支承/归属时，裁剪恒定分支；其他分支全部保留。前序写集合包含并发兄弟的所有可能写入及重复循环前一轮的所有可能写入，不能只检查文本上排列在前面的节点。

这不是偏序归约，也不是并发与顺序执行等价证明。它不保留等待时间、中间容量、可达性、错误路径或公平性，只保留相关成功后态的上近似。共享物料、不同分度目标、改变目标事实的事件均有拒绝测试。

独立的事件框架规则另行处理两种情况：最终 await 的合取包含目标和清理义务，且所有后续外部更新保持这些事实；或者初始 await 中有永远无法变真的原子条件。第二种情况会产生空真，必须明确标记，不计为成功执行覆盖。

另有无请求规则：整个程序既没有 invoke，也没有 with-control，固定参考内核便不能产生 accepted 请求，因此 V10b 空真。该判断与反馈是否新鲜无关，但仍遵守旧窗口不足查询不准入的范围政策。

## 4. V10b 响应窗口与上界

用户确定的业务要求是：已接受请求在截止前确认完成/失败，或明确进入需要人工处理的隔离状态。只看到设备 done、只发停止命令或仍在等待停止都不算合格终态。

设最大反馈可见延迟为 `L = 1 + feedback.max`，请求阶段数为 `n`，最大阶段时长为 `p`，停止确认预算为 `s`。当前审核模板使用充分上界：

```text
normal_or_abort_bound = n * p + 2 * L + 4
response_bound = normal_or_abort_bound + s + 2
```

必须满足无可选故障、无强制停止丢失、`L <= max_age`、完成条件的可变字段受许可和外部事件静默规则保护、源驱动/轴运动已隔离、初始操作历史为空，并且 `response_bound <= D`。阶段有界结束并送达新鲜结果，或者持续条件/全局取消使请求进入停止；停止流程不会重置自身计时器。停止期限后确认失败或保留资源隔离给出终态。因此将完整阶段、两次交付、控制边界与停止预算相加是保守上界。

该公式是针对固定模板的充分条件，不是最短完成时间求解器。前提不满足表示该规则不能决定，不表示请求一定超时。带延迟/故障环境的反例由合法轨迹提供。

旧查询的 `K=1000, D=1800` 没有完整响应窗口，不能将“窗口内看不到超时”记为 HOLDS。P4 保留这些原查询为 `NO_FULL_RESPONSE_WINDOW`，并接纳 P1 已登记的扩展查询：触发到 K、检查到 K+D。新旧查询拥有不同 ID。

`benchmark-view.json` 是单独版本的建议评价视图：仅替换旧窗口不足查询，保留原始档案。它改变了问题范围，必须先让被测算法和基线实现同样的触发范围、尾部检查和全局故障预算，才能使用该视图计算准确率。

## 5. 陈旧反馈等待段的精确摘要

对一条选定的合法调度，accepted 使用最短延迟，result/stop 使用最大延迟，不选择可选故障。这在故障环境允许零次故障时也是合法路径。若最大延迟超过新鲜度，每周期重新采样的保持型反馈仍可能在每次送达时都已陈旧。

等待段只能在物理工作已结束、所有在途包都是 result/stop、FIFO 及采样时间正确、只有已记录 V10b 违规、没有未覆盖监视义务时建立。检查器枚举激活资格、gate/accept/execute/enter/stop、await/delay/branch、响应截止及外部事件时间边界，绝不跨过最近边界。

归纳步骤依赖固定内核：陈旧包不能改变接收状态；其余 plant、token、监视器状态不变；所有读取当前时间的控制条件在边界内不变；未完成外部事件的非时间守卫读取同一状态。一次真实后继核对只验证归纳基例，不能代替这些结构前提。

末状态保留尚未到期的旧包，并重建等待段中实际新采样、末尾仍在途的包；省略的是已经送达且被拒绝的包，不是给旧包换新时间戳。等待端点之后继续显式执行截止 tick。诊断测试逐 tick 展开小等待段，并与 P3 已核查的长轨迹端点对照。

## 6. 准入、计数与复现

`tools/build_reference_truth_p4.py` 构造候选证据。`tools/audit_reference_truth_p4.py` 在新进程重新绑定全部模型与查询，复查每份新证据，独立汇总答案。P3 的已检查证据只在整个包、源码和证据摘要都匹配后复用，不宣称本阶段再次逐步重放了所有 P3 轨迹。

`tools/complete_reference_truth_p4.py` 在新的候选目录中，为所有非窗口原因未决项尝试完整参考图。搜索限时不构成答案；只有检查器验证状态、所有合法后继和闭合范围后才能准入。父候选包的 manifest、补充工具摘要及每次枚举的边界/资源情况单独保留。它用于处理无法仅靠语法无请求规则决定的分支案例，不改变原程序或任务目标。

输出包括 `answers.jsonl`、逐文件证据检查回执、`coverage.json`、`construction-features.json`、`remaining-obligations.json`、原始/扩展窗口登记与 manifest。未达规则前提的尝试保存于 `attempts.json`；拒绝某条证明规则不等于查询无答案，可能由其他证据决定。

安全性质 HOLDS 与触发可达分别判断。没有触发证明时 `vacuous=null`，不能改为 false；触发不可达证明与可达轨迹冲突时拒绝准入。新增结论与 P3 已认证结论不一致也必须停止审查。

报告分别给出原查询与扩展查询的真值确定率、空真/非空真/未知触发、证据类别、分场景/环境/性质计数。不能用真值确定率冒充算法准确率，不能把参考协议天然保证的性质当作变异控制程序的检错成绩。P3 已登记的 `required_environment_gates` 元数据范围说明继续有效；新增业务时序义务需先定义公式。

运行命令见 [README-reference-p4.md](../README-reference-p4.md)，实际数量见 [P4 验收报告](../artifacts/reference-p4/P4验收报告.md)。后续 P5 需完成被测语义映射、共同查询选择和相同范围重跑；P4 不改变旧算法实验结果。
