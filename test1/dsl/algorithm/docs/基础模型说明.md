# shared 与 scenes 的实验基础

当前已建立 [ac-path-v1](../datasets/ac-path-v1/README.md) 的共享契约与十二个符号场景。这里说明 cases 之前的模型基础。目前已构造全量 576 个候选案例，其中 S04-P01 及七个变体已有受限参考检查，见 [S04 试验说明](../README-pilot.md)；阶段声明与结构校验仍不等于通用路径验证。

## 六类信息的归属

| 信息 | 本轮位置 | 案例层还要提供什么 |
| --- | --- | --- |
| 语义实例与契约绑定 | `scenes/Sxx/instances.json` | 具体物料实例与参数绑定 |
| 设备/能力模型 | `shared/device-contracts`、`verification-contracts`、`state-model.json` | 选择能力并绑定实参 |
| 工艺级关系 | `scenes/Sxx/relations.json` 与共享交接/资源服务 | 选择交接边和控制作用域；不能默认任意位置可达 |
| 问题数据 | 场景定义容量、位置、类型等静态边界 | 初态、有限物料、目标、任务参数 |
| 环境模型 | `shared/environments` 和时钟配置 | 选择环境、可用扰动、观察窗口与时间界限 |
| 候选 DSL 与独立任务规格 | 共享性质目录仅提供义务模板 | `process.acp`、`task-spec.json`、实例化性质和查询 |

## 设备覆盖

八类基础设备：机器人、输送带、升降台、出料口、转台、仓储柜、物料、物料托盘。补充五类：被动支承、加工工位、去毛刺工位、焊接工位、仓储搬运机构。

所有实验契约使用独立 `ExperimentalDeviceContract` 格式，不冒充当前运行器的 DeviceSpec。机器人、输送带、物料记录了现有正式契约的来源、版本和哈希；尚未绑定真实执行器。加工工位具有装夹、抽象加工、松夹声明，取料需要确认源未夹紧。

动作模型区分取料、移离、放置、释放和交接提交。失败保留已发生效果；停止未知保持隔离。连续输送的 run=false 与实际停稳分别处理，跟踪动作继承父作用域 writer。

## 场景与审核边界

容量、槽位、设备角色和交接边均为显式实验假设。S04 使用 T0 的 `S.work → C1.entry`、`C1.exit → C2.entry` 两条机器人交接边；其余场景按候选角色定义有限连接，不是从 GLB 推断得到的空间路径。新增或修改连接需要明确修订和依赖记录。

源台座 S 在 S04 中是被动支承，不因名称叫“出料口”就默认具有自动生成物料的能力。仓储柜为被动库位，搬运由独立机构完成。材料实例由 case 创建并冻结；出料模型只能释放预登记实例。

构建 cases 时仍需审核所用场景角色与关系。加工许可、夹紧、位置、反馈等初态不能自动填 true；需要用动作或明确初始条件说明其来源。条件缺失为 U。

## 当前校验与后续接入

`algorithm/tools/validate_foundation.py` 校验引用、参数类型、阶段、资源、容量及控制绑定；对应负向测试覆盖错误契约、错误位置、名义类型、效果名称、冲突引用、writer 归属和停止隔离。它不执行状态空间探索。

S04-P01 已补齐初态、独立目标、候选 DSL，并接入有限范围参考模型探索；后续扩展通用模型构造/求解。正式契约完成后，按迁移清单逐项对齐，不直接覆盖已冻结的实验模型。当前已构造 72 个父案例及其变体，共 576 个候选输入；八个 S04 输入完成受限参考检查。其他路径真值与所有独立 oracle 结论仍待审核，见 README-corpus.md。
