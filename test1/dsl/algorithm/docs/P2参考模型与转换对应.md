# P2 独立参考模型与转换对应

本模型属于方法一五阶段实施方案的 P2。它不导入被测 `acverify` 的状态、控制器、转换函数或归约器。参考侧只沿用 P1 已审读的独立解析/绑定帮助器，设备效果由新的参考实现解释。

## 1. 实现边界

模型使用 `reference-six-phase/0.1`，以 `method1-semantics/0.2`、设备验证契约和服务契约为来源。支持 seq、par、repeat、ordered/exclusive branch、invoke、with-control、await、delay、fail；支持 transfer、transport、circulate、clamp、unclamp、process、index、lift、emit 以及 drive scope。

这是有限符号模型：支承和运动结果来自明确的契约效果，持续时间来自实验区间，不宣称与 GLB 几何、连续接触、真实设备或 PLC 实现等价。未知操作、阶段图、故障种类、非 60 Hz 时间配置和缺失初态被明确拒绝。

## 2. 状态划分

| 状态部分 | 内容 | 保持/清理规则 |
| --- | --- | --- |
| plant.materials / devices | 物理区域、支承、夹持、驱动、许可、轴位和加工记录 | 失败不回滚，只有声明的物理或外部效果修改 |
| plant.ledger / reservations / grants / commits | 局部账本、预留、独占许可、幂等提交 | 预留与容量复查原子执行；提交转占用不重复计数 |
| plant.handoffs | 最近一次交接的已完成物理阶段及请求 | 用于核对已放置但尚未提交等中间状态 |
| tokens | 节点、循环路径、父子关系、作用域、协议阶段、期限及设备事件 | 每次循环有独立激活；隔离态保留授权；未完成物理停止不能丢弃 |
| completed | 已完成请求的冻结主体、目标、epoch | 观察引用按词法循环路径解析，避免旧 done 串号 |
| mail / latches | 源保持值、采样时刻和计划交付时刻 | 源采样才产生新时间戳；按流 FIFO，不能把旧反馈换 epoch |
| events_done / faults_used | 已应用外部事件和故障预算 | 至多声明次数，无故障路径始终保留 |
| violations / triggered / uncovered_properties | 观察义务的历史结果 | 违规不会被后来成功响应抹去；缺失观察不能当作已证明 |

状态中的 request key 由静态节点和数值循环路径产生，且禁止重用；观察帧的 owner_ref 再展开为 activation/request/device/subject/epoch 五元身份。

## 3. 六阶段 tick 与时间安排

每步顺序为：外部事件、故障注入、到期报文交付、控制器快照与原子仲裁、设备物理阶段、源保持状态采样。

参考实现独立选择绝对事件日期：阶段从 s 开始，选择 `delta ∈ [min,max]`，物理完成时刻为 `s+delta-1`；同 tick 物理阶段之后采样，选择 latency，最早交付时刻为 `sample_tick+1+latency`。FIFO 可阻塞后来的报文，但不能修改其采样时间。

控制器提交后的设备接受和物理进度不等待控制器收到 accepted。设备在每个物理阶段前检查持续条件；不满足时停止推进、发布保持型 fault 并安排停止。控制器根据有效故障反馈、持续条件或超时执行协调停止。这样不会因 accepted 仍在网络中就忽略设备端的 Hold。

控制节点按 eligible tick、节点 ID、数值循环路径排序。普通条件读取控制器快照；授权和容量再检查当前原子状态。新激活节点下一 tick 才可处理。失败关闭新提交，并处理已经激活的全部分支。

采用声明的接收者兴趣采样规则：保持值在激活退休前保留，已无消费者的信号不继续产生新样本；已排队报文仍按规则交付/忽略。这不是新加入的时钟或偏序归约。参考枚举器保留绝对 tick，不使用被测归约器。

终态清理只移除不再被读取的计时/接收字段，保留父子状态、完成关联和隔离授权。存在尚未完成的物理停止时，即使控制器已进入隔离，也继续探索到该事件；不能提前把整线当成闭合。

## 4. 契约—转换—观察对应

| 来源义务 | 参考实现 | 观察与检查 |
| --- | --- | --- |
| DSL 组合与激活 | `control.composite`、`state.activate` | seq/par/repeat/branch 的子节点、激活 ID 和失败传播 |
| Pre、Hold、Completion | `plant.predicates`、`control.invoke`、`transition.plant` | 请求前检查、实际物理阶段前的 Hold、完成确认 |
| 资源互斥、预留与容量 | `plant.authorized/available/reserve` | V04、V06，双请求争抢最后容量的原子复查 |
| 抓取与交接 | `plant.effect` | capture 前 V01；每个原子效果后 V05/V06 |
| 保持反馈与身份 | `channel.emit/sample/deliver` | V03 在消费时核对；V02 核对完成请求身份 |
| 世界事实读取 | `observations.condition` | 当前快照形成新的世界观察，不改写旧报文时间；未知事实等待 |
| scope 停止退出 | `control.control_scope` | V07：退出写入、有效 stop_ack、实际停稳 |
| 停止、隔离与部分效果 | `control.stop/scan`、`plant.can_release` | V08：必要授权保留；已确认停止但交接不一致也不能释放 |
| 外部状态与载具替换 | `environment.external` | 等待无活动请求、无冲突授权/预留、无相关夹持和足够目标容量 |
| 独立目标 | `monitors.goal`、P1 `evaluate` | V09/V10a 使用 TaskSpec 和清理义务，不能读取候选自报 goal |
| 有界响应 | `monitors.bounded_response` | 保留首次有效接受时刻；stopping 不算响应；迟到结果不消除逾期 |

已验证接收的协议结果是持久协议状态。其原始采样时间和接收时间都保留到请求结束；完成时不伪造新时间戳。P2 的 V10b 根据有效接受及合法终态转换检查生命周期，不能仅把 P1 单轨迹监视器的输入当作自报的 confirmed 状态。

## 5. 试点迁移与尚待裁定的对应关系

### 同步试点单独保留

旧试点将反馈与微步状态同步处理；新模型将区间解释为设备阶段持续时间，并加入显式采样/可见性。S04 正常流程在固定单 tick 检查配置下，旧模型在 tick 48 完成，新模型在 tick 45 完成。此对照说明同名区间不等于相同时间轨迹，不能用它直接证明原来 K=256/3000 查询的等价性。

因此 160 条试点查询生成了**新的迁移查询身份**，目标性质使用完整版本；原 P1 查询及旧真值包保留。迁移记录的 `equivalence_claimed=false`、`verdict=null`，新查询也要经 P3 才能准入真值。没有将旧同步语义默认为已实现或已证明等价。

### P3 必须核查的语义选择

- 参考故障注入枚举任意已排队报文，而不只枚举队首；与被测实现的故障候选集合需要单独核对。
- Hold 在每个实际物理阶段前检查，包括 accepted 尚未被控制器观察到的时段。
- 载具替换使用服务契约完整的 quiescent 条件，不仅检查某一个区域授权。
- P1 观察帧到状态转换的对应已经有小模型与边界测试，但尚未完成一般性的实现精化证明。

这些项目是后续差异审查的依据，不预设所有差异都是被测算法错误，也不能一发现不同就修改参考答案去迁就被测输出。

## 6. 证据与推进边界

`enumerate_model` 是朴素有限枚举，明确记录 K 截断、状态/内存/时间预算、未覆盖观察以及是否闭合。小模型保存完整状态和边；`check_reference_graphs.py` 独立于枚举循环重新生成每个状态的合法后继、检查边的完整性和所有状态的可达性。

该检查仍以参考转换关系为可信语义核心，不等于证明此核心与所有设备实现一致。`replay` 也是参考模型自身的轨迹重放。实际数据集真值准入、证明证书与范围裁定属于 P3。

360 条具体执行样本选择合法的无可选故障、最短时延路径，只是运行覆盖。它们不能支持“所有路径安全”或“没有成功路径”。未闭合的原区间枚举保持未决，不通过缩小区间或把诊断配置结果替换成原查询答案。
