# 方法一 P5：逐步执行与语义对齐方案

P5 形成可复现的最终实验：共同问题、对应语义、可审核真值、相同预算的算法运行及分层统计。P4 已扩展参考答案覆盖，但旧 `acverify-tick/0.2` 与 `reference-six-phase/0.1` 仍有执行及观察差异，不能直接把两者的输出放进同一张准确率表。

本方案按五个子阶段推进。每阶段有可检查的交付；门禁失败保留具体原因，不能通过修改答案、删掉难例或调用参考引擎替代被测实现来消除差异。

## P5.1：共同范围与差异审核

已实现 `algorithm/alignment_p5/`、运行器及评分门禁，结果见 [P5.1 审核报告](../algorithm/artifacts/reference-p5/P5.1范围与语义审核报告.md)。

共同视图采用 P4 的 `benchmark-view.json`：27,495 个查询，26,970 个适用项、525 个不适用项。1,065 个旧响应窗口不足查询映射到不同 ID 的扩展窗口查询；原始记录保留。P4 全包的 1,485 个空真/触发待定条目也保留为审查义务，不能冒充触发覆盖。

冻结内容包括参考包摘要、当前被测源码、原始解析入口、查询映射、诊断选择规则和审计代码。对全部 1,080 个案例/环境组合核对输入投影；对每个场景按 ID 选择一个代表，在区间上下端点的固定正常调度下比较公共状态；另用专项诊断覆盖控制、通道、外部事件、监视器和时间边界。

这里的输入投影不包含完整解释器语义。正常轨迹一致只能证明这些路径上的公共投影一致；不能通过 24 条样例推断整线等价。边界状态探针不被算作原语料中的可达反例。证据重算与双侧轨迹重放属于技术审核，不声称另一个独立证明助手已验证整个 Python 实现。

验收：输入和范围可复现；所有发现都有来源和证据范围；评分门禁拒绝不一致或未完成的映射。P5.1 的完成不要求旧算法通过语义门禁，失败正是 P5.2 的修复输入。

## P5.2：版本化修复执行语义与性质适配

本阶段已实现新包 `algorithm/src/acverify_v3/`，并完成完整输入映射、旧诊断修复、有限双向关系和逐查询对照。见 [P5.2 验收报告](../algorithm/artifacts/reference-p52/P5.2执行语义验收报告.md)与[状态/事件对应关系](../algorithm/docs/P5.2状态事件对应关系.md)。有限模型验收不自动开放全范围评分，后续 P5.3 审核条件性论证及触发范围。

保留旧 v0.2 源码与历史实验，建立新的明确版本。基线和优化方法都使用这个新语义版本；不将旧 baseline 对新 storage 的差异混作优化收益。参考包及其内核继续冻结，被测实现不得导入参考 `successors`、性质检查器或真值证书来取得预测答案。

### 执行规则

1. **设备持续条件**：每个物理阶段前检查 sustaining conditions，包括 accepted 尚未被控制器观察到的阶段；失败后禁止继续阶段效果，进入物理停止及协议协调。控制器检查与设备检查是两个时刻的独立义务。
2. **故障选择域**：复制/旧请求注入可选择所有在途报文，保留采样时刻、载荷和规定的身份变换；FIFO、最大次数及无故障分支保持一致。不能为减少状态数只取队首。
3. **外部物料替换**：检查源载体各区域的冲突资源、活动操作、预留、持有状态，以及目的位置和设备组容量；事件等待守卫成立，不通过强制搬移破坏物料事实。
4. **停止与终止**：协议隔离不等于物理事件结束。根流程终态需满足子任务结清及无未完成物理事件；未知停止保留资源与真实部分效果。
5. **三值观察**：未知保持 Unknown；补全允许的 world 表达式，并检查否定、合取、分支等待的传播。不能把未知 drive 当成已知“不停稳”。

### 性质与事件

| 性质 | 需要对齐的义务 |
| --- | --- |
| V01 | 捕获效果发生前核对位置、实际停稳和授权；不能只依赖某个阶段恰好名为 capture |
| V02 | 成功确认的 request/activation/subject/epoch 与 accepted、反馈对应；accepted 到达不是此性质的成功确认触发 |
| V03 | 真正消费证据时记录提供者、类型、身份、有效性及采样新鲜度；单纯执行 condition_read 不是完整替代 |
| V04 | 资源拥有者和冲突关系的对应，包含请求身份与 epoch 的解释 |
| V05 | 按 reserved/captured/cleared/placed/released/committed 等阶段核对物理位置、支承、夹持、账本归属 |
| V06 | 位置/设备组的占用与预留，以及有效提交幂等性；构造保证可用论证说明，不能省掉义务 |
| V07 | 停止写入、本次有效 stop_ack、采样新鲜度及实际停稳的共同条件 |
| V08 | 超时进入合格隔离、保留许可，并核对失败处理器前后物料事实；不把独立物理运动误判为回滚 |
| V09 | 根成功必须满足独立目标与清理义务；保持假成功的定义 |
| V10a | K 内的成功目标可达性，保持时间范围、清理和独立任务目标 |
| V10b | 首次有效 accepted 的截止义务；成功、确认失败或合格人工隔离才算响应 |

对受生成协议限制、理论上不可出现的监视输入，可提交“域限制 + 保持性 + 观察对应”的证明，作为直接补字段检查的替代；不能把未在测试中出现当作不可能。

### 时间与状态对应

逐查询区分 `bound_ticks`、`covered_trigger_cutoff` 和 `checked_until`。扩展响应查询允许在 K 后继续运行至 K+D，但只核查触发范围内的请求；全局故障预算不重置。其他性质即使复用更长搜索图，也必须按自己的 K 判断违例/目标时间。

参考实现提前选择事件日期，旧实现按区间逐 tick 选择等待/发生，内部状态不能直接逐字段判等。应定义可观察状态、事件、请求生命周期和定时义务的关系，证明允许调度的双向对应，或在明确有限范围内核对完整后继/轨迹集合。内部表示可以不同，允许的行为集合和性质意义必须对应。

验收：专项差异全部解决或具有受限域证明；小模型完整后继集合检查通过；双向轨迹重放可追踪原始节点和请求；反向突变能触发拒绝；未证明的范围保留 PENDING。仅正常样例通过不能开放评分。

## P5.3：真值及触发覆盖审查

复核 P4 的来源、条件证明前提和使用范围，优先补缺失触发的短见证或不可达证书。旧原窗口不足项不能被改写为“安全”，应通过已版本化的新问题进行比较。

性质 HOLDS 与触发可达性分别记录。已认证性质但触发 Unknown 的项可在语义对齐后进入性质结论统计，同时在触发覆盖表中单列；如某项实验声称已覆盖故障处理，就必须有该处理的触发证据。空真不能计为成功工艺执行。

V02/V03/V07 等生成协议保证单列为协议一致性；静态负例保持自己的前端诊断任务，不并入 P4 的动态分母。AI 技术审核不冒称外部人工审定或设备认证。

验收：使用范围、空真、触发 Unknown、未准入及原查询替换均有逐项记录；不同实验维度不混用分母。

## P5.4：冻结公平实验并执行

在读取本轮预测结果前冻结实现、数据与性质摘要、搜索预算、内存上限、样本、随机种子、重复次数、执行顺序和恢复规则。采用相同语义下的显式搜索作为基线，storage/portfolio 作为求解优化及消融；同一案例/环境/时间查询配对比较。

全量覆盖作业与重复效率样本分开登记；样本按场景和父案例分组，不能根据当前求解结果挑选容易案例。同源变体、多性质和多个 K 不能当作独立样本。模型构造、求解、见证重放分别计时；超时记录为删失/未决，不作为正常完成耗时求加速比。

每个 worker 独立进程，不接收参考标签；评分器在预测文件冻结后再连接参考答案。作业有明确的状态：已决定、UNKNOWN、超时、资源上限、错误、未准入。恢复只在代码、输入、查询及计划摘要相同的情况下进行。

PLC 对比只有在 PLC 降低转换、场景/接口/时钟映射、性质映射和工具配置均通过准入后才运行。不能把图 SMT 或自研算法消融命名为 PLCverif/PLC 工具成绩。尚未建立 PLC 基线时明确报告未完成，不填替代数值。

验收：全部计划作业有结束记录，预测来源与证据可重放，不要求所有问题都给出确定答案。

## P5.5：最终报告与冻结

报告参考真值覆盖率、触发覆盖率、算法确定回答率、已回答准确率、全参考范围正确比例、分性质错误/未决、配对耗时/内存及重复稳定性。按场景/父案例、环境、性质和空真状态分层；不能只保留成功回答。

最终冻结包绑定源码、输入、查询、语义/性质版本、参考证据、算法运行计划、预测、评分器和图表生成程序。保留所有分歧的分类：范围差异、语义差异、参考问题、被测问题或预算未决。

完成条件分开报告：作业结束、证据有效、评价范围真值完整、被测算法全部已决定。P5 可以完成一份如实包含 UNKNOWN 的论文实验，但不能将 UNKNOWN 改成正确答案。若语义门禁仍未通过，则不能宣称正式对比实验完成。
