# AgenticComponents 前端工作台开发计划

日期：2026-10-28。前端项目根目录：`E:/project/AgenticComponents/apps`。本文先定义开发基线，覆盖界面风格、功能、数据契约、动作预览扩展点、文件结构及验收。当前交付是计划，不代表前端或真实设备动画已经实现。

## 1 目标与边界

构建基于 Next.js + TypeScript 的工业设备工作台。用户可以浏览现场资产、选择设备、查看和配置设备信息，选择已定义行为，检查执行条件并通过统一接口预览动作。界面借鉴 Open-Industry 的面板组织和信息密度，采用独立的样式与组件实现。

首期重点是单设备动作预览的完整接入链路。动作算法、IK、复杂路径与物料驱动由适配器承接，后续从 `E:/project/agent` 迁入。PLC 面板先提供程序文本及接口映射查看；终端先提供应用命令和运行日志。PLC 编译／执行、完整物理仿真、后端协作和学习型调度另行接入。

### 1.1 现有规范来源

- [接口与行为契约](E:/project/AgenticComponents/test1/docs/schema.md)：行为标识、类型、触发、条件及完成依据。
- [参数契约](E:/project/AgenticComponents/test1/docs/参数契约.md)：参数类型、必填条件、单位、修改权限、专属结构引用。
- [参数范式集合](E:/project/AgenticComponents/test1/docs/parameter_contract_examples.json)：参考片段，不是完整设备包，不能直接当作可执行资产。
- [现有 scene1 设备包索引](E:/project/AgenticComponents/test1/docs/scene1/device_specs/index.json)：当前只有传送带、机械臂、物料、托盘四类具体样例。

应用的类型枚举覆盖八类设备；没有完整定义或模型的类型显示明确的待配置状态，不伪造可执行资产。文档中的自定义元字段需要规范化适配及语义校验，不能直接交给标准 JSON Schema 验证器就宣称完整通过。

│ └ 载具        │                                 │ 条件与结果     │
├───────────────┴─────────────────────────────────┴────────────────┤
│ 资产 | PLC | 终端                                   折叠／最大化  │
│ 当前标签对应内容：资产目录／程序编辑器／日志与应用命令             │

底部标签切换同一个停靠面板的内容，不导航到另一页面，不重建三维视口，不销毁当前选择或预览。标签栏固定可见；再次点击当前标签可折叠内容区，恢复时保留高度和面板状态。

“BOM”在首期指现场资产实例树。它与底部可复用资产目录不同；完整物料清单统计、采购数据及工艺 BOM 不在首期范围。

## 3 当前功能清单

### 3.1 顶栏与文件菜单

- 项目图标占位、项目名、未保存标记；更换图标后不影响布局。
- 文件菜单：新建项目、导入项目 JSON、导出项目 JSON、导入设备定义、导入／关联 GLB。只实现浏览器可完成的文件操作，不显示虚假的本地路径保存成功。
- 首期“保存”使用浏览器本地项目存储；“导出”下载可携带的数据包。资源引用的保存规则见第 7 节。
- 全屏调用浏览器 Fullscreen API，显示进入／退出状态，处理拒绝和 Esc 退出；与浏览器窗口最大化分开。
- 顶栏预览控制作用于当前活动预览会话。按钮显示会话所属设备，切换选择不会误停止另一台设备。预览控制不标为整个产线的 PLC RUN。

### 3.2 左侧现场 BOM

- 以 `instanceId` 为键展示现场分组、设备、物料和载具；支持展开、搜索、可见性切换。
- 点击树节点与三维选择、右侧明细同步；双击定位到对象包围范围。
- 区分设备包定义与场景实例，显示同一资产的不同实例名称。
- 缺失模型、定义无效或节点未绑定时显示问题标记，可跳到右侧问题位置。
- 首期支持新增实例、重命名、移除及位姿编辑；删除活动预览相关对象前先停止并释放会话。批量编辑、复杂分组拖拽和完整撤销栈作为后续增强。

### 3.3 中央三维视口

- 轨道相机、地面网格、坐标轴、视角复位、聚焦选择和选中高亮。
- 加载 GLB 并展示模型；加载失败显示原因与占位，不让整个工作台崩溃。
- 已定义实例的位姿与属性面板同步；初期先用数值输入编辑位姿，变换 gizmo 可在下一阶段加入。
- 场景坐标统一为右手系、Y 向上、长度米；资产原坐标保留转换元数据。旋转输入的度与存储的弧度在适配层转换。
- 支持查看模型节点和关节映射状态；编辑节点绑定只影响草稿，不在预览中悄悄更换运动链。
- 视口 resize、底部标签切换和右栏更新不重复创建 renderer。模型与缓存采用引用计数或明确所有权释放。

### 3.4 底部资产面板

- 展示八类设备分类、搜索、缩略图或类型占位图、名称及定义状态。
- 区分“已加载定义”“模型未绑定”“可预览”“缺少执行器”。
- 点击查看定义摘要；“添加到现场”创建新实例，复制实例参数覆盖，不复制另一份设备定义。
- 支持导入完整 DeviceSpec 和关联 GLB；参数范式片段不能直接作为完整设备导入，需明确指出缺少的板块。
- 优先实现按钮添加；拖拽到视口放置为增强，不作为第一阶段阻塞条件。

### 3.5 底部 PLC 面板

- 首期显示／编辑项目级 ST 文本，保存编辑草稿，提供导入和导出。
- 展示所选设备的信号方向、类型及当前绑定；未绑定必需接口显示定位提示。
- 编辑器可先使用带行号的轻量文本控件，随后懒加载 CodeMirror；不要把代码编辑器打进首屏视口包。
- “运行／编译”在执行服务未接入时禁用并解释原因。前端字段校验不标成 PLC 编译通过。
- 设备动作预览通过 PreviewController 运行；在 PLC 执行器接入前不假装 PLC 文本驱动了预览。

### 3.6 底部终端面板

- 首期为应用控制台：时间、设备、请求 ID、等级、消息、结构化详情；可过滤、复制、清空视图和导出日志。
- 支持明确的应用命令，如 `help`、`clear`、`inspect <instanceId>`；通过注册表执行，不使用 eval，不连接操作系统 shell。
- 契约校验、资产加载、行为接受、暂停、完成、取消和失败均写入同一日志服务。
- 真正 PTY／系统终端需后端与权限设计，作为独立后续能力。

### 3.7 右侧设备明细与动作预览

信息按折叠分组组织：基本信息、位姿、参数、类型专属结构、接口绑定、行为预览、运行状态。

参数表根据规范生成 number/integer/boolean/string/enum 字段，显示单位、默认值来源和必填条件。修改写入 `paramOverrides`；类型、范围、引用及跨字段校验通过后才应用。`stopped_only` 在 preparing/running/paused/stopping 阶段均不可修改；允许在线修改的量经受控设定值接口提交。

行为面板按稳定 `behaviorId` 展示类型、必需参数、前置条件及完成说明。可调用动作与内部机制、观测、被动响应分开；后几类没有通用“执行”按钮。静态货架展示资源服务状态，物料和托盘展示宿主交互结果。

选择行为后填写本次动作参数，检查条件，再执行。前置条件展示满足／不满足／未知三态；未知的关键条件不能直接算满足。缺执行器时按钮显示“待接入动作实现”。

## 4 MVP 与迁移阶段的能力边界

| 能力 | 工作台 MVP | 动画迁移后 |
| --- | --- | --- |
| 面板、选择与设备参数 | 完整可用 | 继续复用 |
| GLB 展示与节点查找 | 可用，缺资产时明确占位 | 对真实资产完成映射验证 |
| 行为列表、参数校验与生命周期 | 可用 | 由真实执行反馈驱动 |
| 演示预览适配器 | 仅在显式演示模式下运行，标记为 mock | 保留用于界面及契约测试 |
| 真实机械臂 IK／输送动作 | 接口预留，未注册时不可执行 | 逐类迁入并验证 |
| PLC 程序执行 | 文本与接口查看 | 由独立 PLC 服务接入 |

MVP 必须有一个明确标记的演示会话，验证调用、暂停、取消及日志通路；不能用固定计时结束冒充真实机械臂动作成功。真实设备只有执行器已注册、结构已绑定、条件满足时才允许开始真实预览。

## 5 数据与状态架构

### 5.1 数据对象

| 对象 | 关键字段 | 持有者 |
| --- | --- | --- |
| DeviceDefinition | specId、revision、deviceType、asset、paramsSchema、typeSpecificContract、interfaces、behaviors | 领域定义库 |
| DeviceInstance | instanceId、specId、specRevision、name、transform、paramOverrides、bindings | 场景文档 |
| BehaviorContract | behaviorId、kind、argumentSchema、requiredInterfaces、preconditions、completion、executorRef、supportedControls | 定义库 |
| RuntimeSnapshot | time、instanceId、sessionId、状态、观测、信号、已用资源、质量 | 预览服务 |
| WorkspaceUiState | selectedIds、面板宽高、activeDock、折叠、搜索、当前右栏分组 | UI store |
| ProjectDocument | version、设备引用、场景实例、资源记录、PLC 文本 | 文档 store／持久化层 |

定义默认值、实例覆盖、动作参数和实际运行值不得合并为一个对象。three.js Object3D、renderer 和不可序列化句柄放在视图注册表，不放进项目 JSON 或持久化 store。

### 5.2 规范化入口

外部 JSON 先进入 `normalizeDeviceSpec()`：识别版本、映射旧字段，再进行结构与语义验证。保留源字段和迁移诊断，不静默丢弃未知信息。`params_schema` 的 `required_when`、`*_param`、关节映射、模式依赖及 `behavior_id` 引用由独立校验器处理。

原规范主要是说明文档，首期先为实际使用字段建立 TypeScript 类型和 Zod 等结构验证，再编写跨引用检查。不得用 `Record<string, unknown>` 替代整个执行接口；未知内容只能留在明确的扩展区。

预览条件来源分为：可由参数静态检查的事实、场景观测、外部授权。手动预览可以由预览服务授予本地会话权限，但必须可见并记录；缺失物料、不可达目标等条件不得通过手动模式自动改成 TRUE。

## 6 动作预览契约与动画扩展点

### 6.1 调用链

```text
右栏选择行为和参数
  → PreviewController 规范化、条件检查、版本检查
  → ExecutorRegistry 查找 executorRef
  → AnimationAdapter.prepare 绑定节点并保存运行基线
  → start / tick / pause / resume / stop
  → 观测、状态补丁与结果事件
  → 视口、右栏状态和终端同步
```

UI 不直接调用旧项目的 IK 函数；通过 Registry 和 Adapter 隔离迁移细节。同一实例默认只允许一个活动会话；若预览涉及工件或其他设备，也要声明受影响对象并检查是否被其他会话占用。

### 6.2 建议 TypeScript 接口

下面是拟实施的接口骨架，引用的领域类型将在 contracts/ 中定义：

```ts
type PreviewStatus =
  | 'idle' | 'preparing' | 'running' | 'paused' | 'stopping'
  | 'succeeded' | 'cancelled' | 'failed';

interface PreviewRequest {
  requestId: string;
  instanceId: string;
  behaviorId: string;
  definitionRevision: string;
  sceneRevision: number;
  args: Record<string, ParamValue>;
  mode: 'real' | 'mock';
}

interface PreviewIssue {
  code: string;
  message: string;
  path?: string;
  severity: 'error' | 'warning';
}

interface PreviewResult {
  requestId: string;
  status: 'succeeded' | 'cancelled' | 'failed';
  evidence: 'observed' | 'mock';
  observations: Record<string, ObservationValue>;
  issues: PreviewIssue[];
}

interface AnimationAdapter {
  readonly id: string;
  capabilities(): ExecutorCapabilities;
  validate(input: ResolvedPreviewInput): PreviewIssue[];
  prepare(input: ResolvedPreviewInput, context: PreviewContext,
          signal: AbortSignal): Promise<PreviewSession>;
}

interface PreviewSession {
  readonly sessionId: string;
  start(): void;
  tick(dt: number, simulationTime: number): PreviewFrame;
  pause(): void;
  resume(): void;
  stop(reason: string): Promise<PreviewResult>;
  result(): PreviewResult | null;
  restoreBaseline(): Promise<void>;
  dispose(): void;
}
```

`ResolvedPreviewInput` 包含解析后的只读参数、绑定目标、契约和所需资源。`PreviewContext` 提供模型节点解析、变换读写、观测与日志接口；不允许任意修改 React store。`PreviewFrame` 携带观测和视图补丁，可选进度不代表成功。

动作返回什么、允许哪些控制由 `ExecutorCapabilities` 声明，例如 supportsPause、supportsRestore、supportedBehaviors。外部仍展示统一按钮；不支持的操作禁用。节点无法解析、参数不支持或执行器缺失应在开始前诊断。

### 6.3 状态机与取消

- `idle → preparing → running`；prepare 支持 AbortSignal，用户取消后迟到的模型加载结果不能重启旧会话。
- `running ↔ paused` 仅在适配器支持时允许；paused 仍持有会话与资源。
- 停止进入 stopping，执行器确认后进入 cancelled 或 failed；停止不等于成功，清理不得让工件或设备状态失去所有者。
- 真实完成由适配器返回观测依据，控制器再对完成契约检查；`progress=1`、计时结束或 UI 按钮变化均不是独立成功证据。
- 每个 requestId 至多接受一次并产生一次终态；旧 session 的帧和回调通过 sessionId、revision 丢弃。
- “恢复初始预览姿态”与“停止”分开：先终止活动动作，再由适配器恢复基线；恢复操作只影响声明的运行对象。
- 卸载页面、移除实例、替换模型、导入新项目时取消准备和执行、解绑订阅、清理 GPU／对象 URL 资源。dispose 必须幂等，应对 React 开发模式的重复挂载。

### 6.4 文档与运行状态分离

预览保存运行基线，所有运动写入 RuntimeSnapshot／视图变换，不自动写入设备定义或 SceneDocument。若提供“记录当前姿态”，应是用户显式编辑操作，并有可回退记录。

选择其他设备时，当前预览保持其会话身份；界面展示运行中的设备，并允许回到它。切换资产／PLC／终端面板不会中断预览。

### 6.5 预览时钟

预览采用固定逻辑步长（初始建议 1/60 s），requestAnimationFrame 只驱动累计器和绘制。隐藏页暂停，不积累返回后的突发补步；超载时显示实际速率。未来更严格的仿真实验可把同一 tick 契约迁到 Worker／无界面运行器。

MockAdapter 可以用设定时长生成显式模拟状态；RealAdapter 必须报告实际位置、求解状态和交接结果。Mock 的成功结果不能进入真实动作验收统计。

## 7 项目文件与本地资源

首期使用本地 JSON 目录提供设备索引，ProjectRepository 抽象出 list/load/save/import/export，默认 BrowserProjectRepository 基于 IndexedDB。不得假设 Next.js 的 public/ 可以在浏览器运行时写入。

发布内置 GLB 放在 `public/models`；用户导入 GLB 保存 Blob 到 IndexedDB，运行时生成对象 URL，释放或替换时撤销。设备定义中的 assetId 是稳定引用，不保存临时 blob URL。跨重载恢复应从 Blob 重建 URL。

项目导入先验证版本、引用与资源存在性。首期 JSON 导出若只携带资源清单，应明确标为“项目数据”，导入时要求重新关联缺失资源；完整含资产包可随后增加 ZIP 格式。导出期间不把当前预览临时位姿当作作者保存的场景。

从现有 test1 样例导入时，通过受控导入工具生成应用数据并记录源版本，避免将原文档目录复制成第二份长期手工维护的真值源。

## 8 技术栈与模块边界

| 范围 | 选择 | 说明 |
| --- | --- | --- |
| 应用框架 | Next.js App Router + TypeScript strict | apps 作为单个前端项目根目录 |
| UI | React、CSS Modules＋主题变量、可访问的菜单／标签组件 | 工作台样式统一，组件不嵌入动作算法 |
| 三维 | three.js + React Three Fiber，可选 Drei | 便于迁移已有 agent 前端，但通过适配器隔离 |
| 状态 | Zustand，按文档／UI／预览分 slice | 不保存 renderer 和 Object3D |
| 校验 | TypeScript 类型＋结构校验库＋自定义语义检查 | 不直接把旧说明型 schema 当标准 JSON Schema |
| 代码编辑 | 轻量编辑器起步，CodeMirror 懒加载 | PLC 面板可替换 |
| 测试 | Vitest、Testing Library、Playwright | 重点验证行为与交互，不逐样式镜像实现 |

具体依赖版本在初始化时锁定并检查 peer dependencies，提交 lockfile。迁移 IK 时记录旧 three.js 版本，避免同时改算法和升级渲染库。

Next.js 的页面和布局保留服务端外壳；含 store、浏览器文件 API、Fullscreen API 和三维视口的工作台置于明确的 Client Component 边界。三维视口和重编辑器从客户端边界动态加载，避免服务端访问 window/WebGL。依据：[Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components)、[Lazy Loading](https://nextjs.org/docs/app/guides/lazy-loading)。

依赖方向：`contracts/domain → validation → application services → stores/hooks → UI`；三维实现放在独立 renderer/adapters 中，通过窄接口接入预览控制器。领域类型与校验代码不导入 React 或 three.js。

已有代码可参考：

- [IKSolver.ts](E:/project/agent/frontend/lib/ik/IKSolver.ts)：求解和 GLB 回写。

- [runtime-behavior.ts](E:/project/agent/frontend/lib/runtime-behavior.ts)：动作载荷和路径解析。

迁移先做一个 robot.move_to_pose 适配器：解析真实节点和 TCP，输出收敛状态和误差，验证暂停／停止／恢复基线；再迁入抓放和输送。旧实现主要按 progress 推进并在时间到后报告完成，迁移时要将“动画进度结束”和“动作契约成功”分开。

旧函数可作为适配器内部实现，但不得直接沿用对旧 Zustand store 或后端 API 的调用。预览结果统一回到 PreviewController，避免新旧系统各上报一次 done。不得假定名称相同的业务字段代表相同坐标系或暂停语义。

## 11 开发阶段与验收标准

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| P0 领域与样例 | 类型、规范化入口、最小完整设备和场景 fixture | 不完整片段被识别，引用与参数错误能定位 |
| P1 工作台外壳 | 顶栏、BOM、视口、右栏、底部三标签 | 布局可调整，选择同步，面板切换保留状态 |
| P2 资产与详情 | 导入 GLB/DeviceSpec、添加实例、参数表单、基本保存 | 错误导入不破坏当前项目，重载可恢复资源或提示重新关联 |
| P3 预览框架 | 请求校验、注册表、时钟、MockAdapter、日志 | 启停状态准确，未知执行器明确禁用，取消准备不产生迟到会话 |
| P4 动画迁移 | 首个真实机械臂／输送适配器 | 实际观测决定成功，暂停和恢复不重复任务，停止与恢复基线可区分 |
| P5 完整回归 | PLC 文本、绑定查看、终端及端到端测试 | 保存与预览隔离，错误可定位，资源与订阅正确释放 |

首期阶段 P1–P3 完成后即可交付可操作工作台；真实设备动作预览的完成标准属于 P4，不能用演示适配器替代验收。

### 11.1 必测流程

1. 资产添加到现场 → BOM 选中 → 视口高亮 → 右栏显示正确实例。
2. 合法／非法参数输入，默认值与覆盖值可辨，stopped_only 在预览暂停时也不可编辑。
3. 资产／PLC／终端切换不丢失选择、不重载模型、不停止会话。
4. 执行器缺失、节点缺失、前置条件不满足／未知时，禁止真实预览并给出可定位原因。
5. 重复点击执行只生成一个请求；准备中取消后加载完成不能重启；旧会话回调被忽略。
6. 真实动作未到位或 IK 未收敛时，不因动画进度达到 100% 报成功。
7. 删除对象、替换模型、导入新项目和卸载页面时终止相关会话，不残留持有对象或订阅。
8. 预览运行不改作者文档；导出时不会把临时运动状态写入永久位姿。
9. Fullscreen API 拒绝／Esc 退出、GLB 加载失败、IndexedDB 不可用时界面仍可操作并明确提示。
10. 在基准桌面尺寸和较窄窗口检查表格、菜单、焦点与键盘操作；记录示例资产、设备数与运行环境后再讨论性能。

### 11.2 完成定义

实现阶段运行 typecheck、lint、针对性单元测试及主要交互 E2E，并在生产构建中检查客户端边界和资源路径。界面截图应使用真实状态，未实现按钮必须标注或禁用。交付记录包含实际可用功能、已注册动作适配器、已验证资产和剩余接入项。
