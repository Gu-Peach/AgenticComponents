# 016 确定性 DSL、设备行为校验与滑轨挂载

开发基线为 `refactor/device-contract-library` 分支的 `a17a4a4`。第 1–5 节记录实施方案，第 6 节记录本轮实现与验证。

## 1. 目标与执行边界

用同一套引擎执行自搭设备和已发布的整场景。给定设备契约、实例几何、装配连接、初态和一份 DSL，能够确定每一步由谁对哪件物料或哪条轴执行什么动作、采用哪些参数，以及用什么证据确认完成。未来由 agent 编写确定性的 DSL，播放时直接执行已编译的工步。

| 归属 | 输入和职责 | 例子 |
| --- | --- | --- |
| 型号与实例 | 声明轴线、零位、行程、速度、允许工位、空间安装接口、抓取与加工坐标系、承载面和槽位容量 | 瓶头和瓶尾是同一瓶子的两个局部抓取坐标系。升降台底座和载物平台是两个不同部件。 |
| 场景装配 | 保存实例位姿、明确的安装父子关系、接口配对及目标支承几何 | 入库侧滑轨挂入库升降机，出库侧滑轨挂出库升降机。 |
| 任务与 DSL | 指定工件、来源、目的、每盘件数、批次、顺序与并行关系、抓取接口、工位角度、轴目标和需要的跨设备联锁 | 先横移到指定轴位置，再升至指定高度。转台到加工位后调用加工。 |
| 设备行为 | 按本次请求和设备契约执行；读取实测状态，检查自身前置、持续和完成条件，并输出有身份的反馈 | 手爪在指定接口建立吸附后才报告持有；轴到达目标且停稳后才报告到位。 |
| 运行引擎 | 解析端点与参数、调度、仲裁和停止；维护装配变换、物理接触、约束、库存和回执；依照 DSL 推进 | 同一步的命令、读数、物料身份与完成回执可在 PLC/轨迹中对应。任务书独立核对最终结果。 |

## 2. 重构前的参数入口与迁移目标

现有 `invoke()` 已将普通参数编入 `arguments`，已登记的结构化命令字段编入 `payload`。运行时按本次循环项求值、验证并建立不可变的动作请求。沿用现有语言和契约字段。扩充某个行为的字段时，同步修订契约签名、编译校验和该行为的执行入口。[DSL 编译](../../scripts/lib/declarative_frontend.py) · [场景参数校验](../../scripts/lib/scene_binding_check.py) · [动作调度](../../src/runtime/scheduler/ProcessScheduler.ts)

| 动作 | 015 完成时的状态 | 迁移后的用法与判据 |
| --- | --- | --- |
| 机械臂抓取与交接 | S04 的 `pick_and_handoff` 已传 `material`、`giver_grasp`、`receiver_grasp`，已持件放置传 `grasp`。普通抓放有按物体顶面生成轨迹的入口。 | 让普通 `grip`、`pick_and_place` 以及交接共用接口解析。按照物料 ID 和所选局部抓取接口求实时世界位姿，校验工具兼容、距离、朝向和相对速度，再建立并实测抓持。单接口旧型号可沿用唯一或契约已声明的默认接口；多接口新任务显式指定。 |
| 转台分度 | `rotate_to_station` 已接受 `angleTag=quantity(180, '°')`。S11 的流程已在 DSL 中，装配器和运行服务又限定了 0°/180°。 | DSL 传本次绝对工位角。由型号/实例声明可用工位及允许转向，行为校验目标合法，按实测角度误差、速度与装夹要求确认完成。 |
| 滑轨横移 | `move_to_position` 接受 `position_m`，单位 m，有符号，以轨道零位为起点沿局部正轴计量。S07 当前调用具名点位。 | 每组工步显式给定目标轴坐标，滑轨带动已绑定的物体，检查行程、带载净空、实测位置和停稳。 |
| 升降台升降 | `lift_to_level` 接受 `move_to_level`，单位 m，表示平台相对设备基座的目标高度。现有执行器扣除静止高度 `restHeight` 得到轴位移。 | 每组工步显式给定目标高度，升降时只有平台及其载荷沿升降轴运动。行为检验限位、实测高度和停稳。 |

下面展示**现有调用写法**。数值示例仅说明坐标语义；S07 正式任务值在实施时按各自装配零位和具名端点测得，逐组写入 DSL。

```python
invoke('head_to_tail_handoff', R1, 'pick_and_handoff',
       payload=payload('R1.pick_and_handoff', material=job.material,
                       source=C1.exit, target=R1.handoff, receiver=R2,
                       giver_grasp='head', receiver_grasp='tail'))
invoke('index_to_robot', T1, 'rotate_to_station', angleTag=quantity(180, '°'))
```

```python
# S07 两个独立动作的语法示例，数值仅作示意
with seq('position_platform'):
    invoke('position_rail', T1, 'move_to_position', position_m=quantity(0, 'm'))
    invoke('position_lift', L1, 'lift_to_level', move_to_level=quantity(1, 'm'))
```

转台、滑轨和升降台均使用绝对目标。相邻工步的目标差给出本步移动量；相同目标重放须按照行为的到位及停稳条件处理。S11 从 180° 正向回到 0° 仍须产生第二段真实旋转。新增支持旧命令别名时，让新旧入口落到同一个执行器。[S04 工艺](../../public/scene/S04/process.py) · [S11 工艺](../../public/scene/S11/process.py) · [滑轨行为](../../src/devices/linear_rail/behavior.ts) · [升降台行为](../../src/devices/lift_table/behavior.ts)

## 3. 十类设备的底部安装接口与滑轨承载接口

1. 为 015 的十类模板各声明一个可识别的底部安装接口，包含机械臂、输送带、转台、机床、出料口、物料（含托盘）、滑轨、升降台、仓储柜和人物。沿用 `interfaces[]`、`interface_id`、`capabilities.snap.role/accepts` 和唯一坐标来源。建议统一接口 ID 为 `mount_base`，作为本轮拟新增约定。现有输送端点、工具接口等继续按原角色解析。物料抓取/加工坐标系留在类型专属模型，信号留在 `signal_ports`。[设备空间接口规范](../../../test1/docs/设备契约.md) · [信号规范](../../../test1/docs/schema.md) · [空间接口校验](../../src/contracts/spatial.ts)
2. 用模型**静止姿态、设备局部 Y 向上、单位米**的自身几何求包围框。将各自拥有的网格变换到统一的设备局部系，取底面中心 `((xmin+xmax)/2, ymin, (zmin+zmax)/2)`。计入设备自己的关节部件，排除场景、其他设备和已挂载载荷。拖动、旋转、加工换形或升降不逐帧重算安装点。模型或影响尺寸的参数更换时使旧派生值失效。明确导入校准与实例变换各应用一次，编辑器、运行时和渲染端消费同一局部帧。
3. 在模型发布/导入阶段把计算值物化为现有 `local_frame`，模板缺少具体模型时用现有 pending 形式；附上可追溯的模型版本与几何来源。缺少有效几何时标明待校准并阻止依赖该接口的挂载。设备底面向下、滑座接收面向上，另取一个正交的切向基准；按现有吸附配对规则验证轴向、朝向与保留装配姿态。[帧解析](../../src/domain/resolveInterfaceFrame.ts) · [工作台吸附](../../src/domain/spatial/snap.ts)
4. 滑轨除自身底部安装接口外，增加**滑座上的移动安装接口**，建议名 `carriage_mount`。它的坐标固定在滑座局部系，由滑座安装面或型号声明的标定点给出。若模型没有独立的滑座网格，用有几何依据的移动参考帧。S07 的轨道与升降机共享模型树，按节点归属建立一次挂载，避免把整台升降机计入轨道包围框。两组连接分别为 `T1.carriage_mount ↔ L1.mount_base` 和 `T2.carriage_mount ↔ L2.mount_base`。
5. 复用项目 `connections` 中的实例 ID 和接口 ID。显式表达连接的安装语义以及哪端是移动父端，编辑时吸附、保存、重载和运行时装配使用同一条关系。已有端对端连接继续按原语义处理。验证双方角色、接口占用、单父、无环、自连接、坐标有效性及当前支持的缩放。运行期间由引擎按挂载树一次计算世界位姿，再同步到物理和画面；旧 S07 的 `mounted_device/mounted_on` 经兼容读取映射到同一关系，双份数据冲突时报出端点。[连接结构](../../src/contracts/device.ts) · [旧装配编译](../../src/domain/runtime/compileWarehouseRuntime.ts)
6. 组合运动依照“滑轨基准 → 滑座轴位移 → 挂载变换 → 升降机底座 → 平台升降位移 → 载荷相对位姿”。滑轨自身轨身固定；移动其他兼容设备也能沿同一条挂载链随动。物料的短时抓持和平台承载按各自的约束生命周期管理。释放物料后解除本次承载，升降机仍挂在滑轨上。

## 4. 逐场景迁移顺序

每项先用现有场景固定输入、观察物料身份、实测位姿和工步回执，再以通用设备工厂和条件提供者替换旧路径。真实约束继续参与验收，任何改动都可按场景独立回归。

| 顺序、现有文件 | 实施内容 | 完成证据 |
| --- | --- | --- |
| 1 · S04 [机械臂交接行为](../../src/devices/robot_arm/behavior.ts) | 将抓取和持件放置接入机械臂通用参数解析。用配置的物料接触帧、目标支承面及目标姿态验证放置；同步清除[交接编译](../../src/domain/runtime/compileHandoffManifest.ts)和[装配器](../../src/runtime/assembly/HandoffRuntimeAssembler.ts)对 `head/tail`、带端和出口方向的专用推断。 | 旧四瓶仍在出口倒置交付；改名为另外两个合法接口并换输出姿态后走同一实现。接收方对准才可转移持有权，错接口被拒绝，交接中断保留实际持有者。 |
| 2 · S11 [IndexedFixtureBindings](../../src/runtime/assembly/indexedFixtureBindings.ts) | 由 DSL 表达搬入、定位、加工、返回、搬出；设备实例提供工位与工装位置。同步替换[装配器](../../src/runtime/assembly/IndexedProcessingRuntimeAssembler.ts)内固定工位数组、准入分支、运行中判断和验收回执的固定角比较。空位、实际装夹、人员/机械臂让位、加工口与工具对准取自实时观测。 | 原四件和两次分度通过。在合法、可达的另一工位（如 90°）同步配置加工目标并修改 DSL 后可运行；角度不支持、工件未固定或工具够不到时得到对应失败。 |
| 3 · S06 [CarrierBatchRuntime](../../src/runtime/engine/CarrierBatchRuntime.ts) | DSL 已用 `item.source` 指定原槽。引擎维护每件物料的槽位、支承与去向；机械臂负责抓放和归位判定，机床负责加工位实测、互锁保持、周期及同一工件状态提交。按本次任务声明归位要求；现有 DSL 已显式调用 `move_to_pose` 并在命令载荷指定 `R1.home`，由机械臂发布实测到位。如将抓放归位整合进复合行为，先修订载荷与完成条件，再撤掉重复的归位工步。 | 九件加工后各自回到 DSL 指定槽位；中断不提前出现成品；仅释放或撤离到抓取上方时，要求归位的动作不能报完成。另设明确指定新目的槽的用例，证明机床不限制下游去向。 |
| 4 · S02 [CarrierBatchRuntime](../../src/runtime/engine/CarrierBatchRuntime.ts) | 将批次与装载要求显式归入 DSL 的生产任务。每盘下层 12、盖板 1、上层 12，共六盘。将现有 `workpiece.carrying` 的槽位、支承层、载重与部分装载策略用作物理容量，沿用预留/装载台账。由编译器按任务展开有限动作并校验可用槽位和层次，由引擎按实测放置记账。若 DSL 需要扩充每盘数量声明，先扩有限任务 schema 与静态检查，再迁移旧托盘 prefab 中的装载清单。 | 六盘各有 25 个正确身份和槽位。另测较小任务、超容量、重复槽位、错层、满盘交付和允许部分装载；物料数量或槽位变化只改任务或设备配置。[托盘行为与属性](../../src/devices/workpiece/behavior.ts) |
| 5 · S01 [FiniteBatchLifecycle](../../src/runtime/engine/FiniteBatchLifecycle.ts) | 把有限批次的入场、接纳、出口交付和移出提炼为按身份与端点工作的引擎服务，供装载/加工等场景复用。供料设备负责出料条件，引擎记录批次数量、实际支承、出口和回执。 | S01 既有 36 件交付与空盘移出通过。换小批量、改设备名仍可运行；重复请求或缺少出口接触时不会多交付。 |
| 6 · S07 [MountedAxisMotion](../../src/runtime/engine/MountedAxisMotion.ts) | 用第 3 节的显式安装关系装配。保留共享轴轨迹与带载净空算法，将与仓储角色耦合的轴驱动迁到挂载树及两个设备行为。工艺发布时按入库/出库、对接点/格位为每组记录轨道轴坐标、平台目标高度和单位；对接几何用于生成、复核这些数值。正式 DSL 显式逐组调用数值动作，继续通过具名端点接放物料。已有具名移动入口保留兼容并走同一执行与校验。 | 同一安装关系覆盖水平 X/Z 滑轨、空载和带载、平移旋转后的实例；先横移、再升降的次序和数值可从工步轨迹重建。可达任务通过；原四件保留原格位，第四件在真实载荷与横梁条件下报告不可达。[S07 原流程](../../public/scene/S07/process.py) · [目标投影](../../src/domain/runtime/DockingTargetResolver.ts) |

### S07 逐组填写轴目标

沿用先入库、后出库的两个有限循环。每个订单的格位仍是独立的任务目标。实施交付物包括下列四组的参数表及相应 `process.py` 调用。每行保留订单、端点、轨道零位、目标轴坐标、基座参考、平台目标高度及所用模型版本，两个数值都随确定性 DSL 发布。

| 组别 | 滑轨和升降台 | 参数测量目标 | 定位后的工步 |
| --- | --- | --- | --- |
| 入库接料 | T1、L1 | C1.exit | 从进料带接取本件 |
| 入库放料 | T1、L1 | 本件的 STORE.slot1–4 之一 | 放入该格 |
| 出库接料 | T2、L2 | 同一订单格位，按出库侧安装零位单独测量 | 从该格接取本件 |
| 出库放料 | T2、L2 | C2.entry | 放到出料带 |

每组先执行滑轨数值定位，再执行升降台数值定位。相同对接点可共用任务常数。若使用任务行字段，先验证有限任务展开能保留这些字段；数值到位后仍用物料与目标端点的实测关系验证能否交接。移动模型、改变格位或重设零点后重新生成或明确更新受影响的数值，并校验原值在新布局中不会误报成功。

## 5. 执行链与验收

1. **发布与编译**。从十类设备目录生成模板和场景契约快照。构建场景先解析 DSL，按设备签名验证必填字段、单位、接口归属和引用；对明确的非法角度、轴行程、超容量或挂载拓扑错误给出设备/工步/字段。签名发生变化时更新相应修订与锁定数据，保留旧包测试。[设备库构建](../../scripts/lib/device_library.py) · [场景构建](../../scripts/build-scene-catalog.py)
2. **装配与执行**。装配器读取实例、端点、受支持的能力与连接，通过设备注册表创建执行器；调度器按 DSL 产生请求，设备通过物理端口施加约束或驱动。场景验收只读取实测轨迹和独立任务目标。逐项检查编译器、装配器、行为准入与最终验收，避免把同一个工艺常量搬到另一层。[设备注册表](../../src/devices/registry.ts) · [运行时装配入口](../../src/runtime/assembly/RuntimeFactoryRegistry.ts)
3. **条件和信号**。把契约里的前置、持续和完成条件逐项映射到已声明的 `signal_ports` 或有来源的物理观测。抓持用指定物料的约束，定位用实测值和速度，交付用接收支承与占用，归位用关节/末端及停稳。把身份、目标、容差、工步和请求关联写入轨迹；命令发出、时钟到期或前一步结束都不能单独构成成功证据。暂停、重试、停止须保持实际归属，回执去重。
4. **独立装配验收**。从工作台分别导入一条滑轨、一台升降机和物料，用底部接口完成吸附；保存、重载，运行显式轴目标，查看物理帧与渲染帧。断开重跑后设备各自独立。将升降机换成另一台兼容设备、调换轨道方向或变更实例名，仅变更装配和 DSL 即可运行。验证模型原点偏置、旋转、共享 GLB 节点、空几何、占用和循环挂载。
5. **回归与退出条件**。各阶段执行场景目录构建、Python 编译器测试、TypeScript 类型检查与相关 Vitest。最终回归 S01、S02、S04、S06、S07、S11、单设备入口及自搭场景，并验证工作台吸附和 PLC 的实际完成反馈。待场景专类的最后一个调用者迁走、旧新场景和改参用例均通过，再移除相应类和导入路径。

交付顺序为参数与证据基线、S04、S11、S06、S02、S01、全类型安装接口与 S07，最后联调自搭场景。每项提供现有场景回归和至少一项改参或重组结果，交由分支验收。


## 6. 本轮实现与验证

工艺发布继续使用 `ac-declarative/0.4`。DSL 指定动作、参数、次序与批次。装配器仍负责为特定设备组合提供端点、设备工厂、物理反馈与独立验收目标。配置有效且物理可达的改参用例与原始场景共用执行器。

| 场景 | 改动与实测 |
| --- | --- |

场景源文件与单设备拼装入口分别保留了显式参数。S07 可在场景运行面板提取一组独立滑轨与升降机，选中滑轨后在“挂载定位”中设置轴目标或载入工艺 IR。滑轨的目标相对轨道零位，平台的目标高度相对升降机基座。已导入的旧整场景包按保存的版本使用；重新从场景目录添加 S07 即可使用带显式端口连接的模型包。


独立挂载定位一次运行一条滑轨及一个直接挂件。挂件可以是升降机，也可以是有兼容底部接口的物料。真实滑座网格、挂件和升降平台分别绑定运动部件；固定轨身保持静止。一个已旋转至 Z 向的滑轨在目标 −0.35 m 时带动独立物料沿 Z 移动了 0.35 m。该入口的数值输入生成同一份调度 IR，导入 IR 可指定多次数值定位。工作台可见的其他独立实体模型作为静态净空障碍；完整场景包背景与示意占位的几何范围见运行面板。S07 原整场入口继续验证平台上的自由物料、库位支承和横梁。
