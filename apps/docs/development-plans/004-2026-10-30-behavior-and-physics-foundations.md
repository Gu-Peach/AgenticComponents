# 004 Behavior and physics foundations

日期：2026-10-30

定位：下一轮开发的前置知识与职责约定，整理自“直线输送机如何确定方向、刚体如何被输送面带动”开始的讨论。本文保留前置知识，并从第 15 章开始给出本轮开发计划；实施结果见第 22 章。此前的架构与首个实验见 [003 运行引擎与设备模板](003-2026-10-30-runtime-engine-and-device-templates.md)。

## 0.目前的总执行链路

Agent／调度器：决定做什么、由谁做
↓
设备行为层：决定设备如何响应和驱动
↓
物理引擎：求解实际运动及接触结果

## 1. 首先区分四个层次

| 层次             | 核心问题                     | 典型职责                                               |
| ---------------- | ---------------------------- | ------------------------------------------------------ |
| 工艺规划/调度层  | 做什么、由谁做、先后顺序如何 | Agent 规划工艺路径，调度器分配设备与资源；当前尚未接入 |
| 设备行为层       | 设备如何响应命令             | 启停、目标速度、加减速、内部状态机、等待和完成语义     |
| 物理适配与求解层 | 给定驱动后实际如何运动       | 创建刚体、识别接触、设置表面速度、求解重力/摩擦/碰撞   |
| 渲染与观测展示层 | 如何呈现已经发生的结果       | 显示实际姿态与运行信号；不重复积分，不改写作者初始位姿 |

“行为层做规划、物理层做执行”可以用作初步理解，但行为层的规划仅指设备内部的动作决策和控制，不等于整条产线的工艺规划。物理引擎不是物料移动结果的中转站：物理求解已经推进了状态，结果交给渲染显示，并反馈到下一步行为判断。

## 2. 行为引擎具体参与什么

设备脚本读取参数、控制信号和观测，决定本步驱动。运行时负责统一调用脚本和物理后端，维持一致时序。

| 工作                                | 负责位置                                          |
| ----------------------------------- | ------------------------------------------------- |
| 默认速度、允许范围、运行模式等定义  | DeviceSpec 参数契约与实例覆盖                     |
| 判断运行许可、选择当前速度命令      | ConveyorTemplate.beforePhysics                    |
| 计算加减速后的表面速度标量          | SpeedRamp，由设备脚本调用                         |
| 管理当前设备速度、里程等独立状态    | ConveyorState / 每实例脚本                        |
| 固定步调度、会话开始/暂停/停止/清理 | RuntimeKernel、SimulationSession、RuntimeClock    |
| 输入合法性、写入来源、快照与有效性  | SignalRegistry；当前仅实现受限手动通道            |
| 任务接受、主体/请求关联、超时与终态 | ActionGateway；当前是单物料到达观察任务           |
| 发布设备意义的反馈                  | ConveyorTemplate.afterPhysics，读取实际观测后发布 |

脚本提出“当前表面应以多少速度运行”，不直接把动态物料位置加上速度乘时间。对于驱动器有额外反馈/限制的后端，实际应用速度还应从后端确认；当前实验后端直接接受经过验证的表面速度，反馈的是已应用的虚拟表面驱动，不是电机实测值。

ConveyorTemplate 是脚本工厂：create(config) 为每台设备创建独立脚本；DeviceTemplateRegistry 管理工厂，RuntimeKernel 调用脚本。创建脚本和每步运行脚本是两个职责。

## 3. 物理相关职责应如何划分

用户提出的“运输方向、速度、归一化、世界坐标转换、刚体定义/识别、实际运动求解”都在完整运行链中，但不应全部归到物理求解器。

| 事项                                 | 主责模块                     | 说明                                                       |
| ------------------------------------ | ---------------------------- | ---------------------------------------------------------- |
| 输送方向约定                         | 设备定义/建模                | 例如局部 +X；不是求解器从 GLB 外观自动推断                 |
| 目标速度大小                         | 控制输入与行为脚本           | 参数给初值与范围，运行输入可以改变目标                     |
| 加减速后的速度大小                   | 行为机制                     | SpeedRamp 产生本步表面驱动标量                             |
| 方向归一化与坐标变换                 | 空间工具、编译器、物理适配层 | 将作者坐标变成后端需要的世界坐标和方向；计算是共用数学能力 |
| 世界表面速度向量                     | 物理适配层                   | 使用本步速度标量与世界输送方向，按接触 API 约定提交        |
| 刚体的运动类型和物理属性定义         | schema/标定配置              | 声明形状、质量、运动类型、摩擦及业务角色                   |
| 创建、登记与销毁刚体                 | 物理后端/对象登记层          | 根据已验证配置创建求解器对象，保存 ID/句柄映射             |
| 判断谁碰到谁、接触在哪               | 碰撞检测与接触回调           | 引擎输出刚体 ID、子形状、接触点、法向等信息                |
| 判断某接触是否属于有效输送面         | 物理适配层                   | 用已登记角色、子形状和承载面法向过滤                       |
| 计算接触相对运动、摩擦冲量与实际位姿 | 物理求解器                   | 综合刚体线/角速度、虚拟表面速度、约束和接触属性            |
| 判断到达出口/任务完成                | 观测器与行为运行时           | 空间事实与任务身份关联；不是物理库自动理解工艺             |

可以把“物理适配 + 物理求解器”合称物理层，但代码中仍应保留边界：JoltPhysicsBackend 将领域驱动转换为 Jolt 调用，Jolt 实际求解刚体运动。

## 4. 直线输送方向从哪里来

Open-Industry 的普通输送机通常以局部 +X 为流向，设备脚本取得对应世界方向并设置表面速度。它没有必要给每件物料下发一条入口到出口的插值路径。

```text
局部输送方向 d_local = [1, 0, 0]
世界输送方向 d_world = normalize(R × d_local)
世界表面速度 v_surface = speed_actual × d_world
```

R 是设备/输送面相对世界的旋转。当前实验只支持水平输送和单位缩放，因此归一化方向可由设备绕 Y 轴的旋转直接计算。

| 设备姿态（当前右手系约定） | 局部流向 | 世界表面速度，速度为 0.4 m/s |
| -------------------------- | -------- | ---------------------------- |
| 未旋转                     | +X       | [0.4, 0, 0]                  |
| 绕 Y 旋转 +90°             | +X       | [0, 0, -0.4]                 |
| 绕 Y 旋转 180°             | +X       | [-0.4, 0, 0]                 |
| 受控停带且减速完成         | 不变     | [0, 0, 0]                    |

速度定义包括默认值、范围和单位；实际向量随运行命令、加减速和设备姿态更新。首期 allow_reverse=false，拒绝负速度；负速度反转是后续需单独支持的能力。

输送方向正确不等于物料轨迹被严格锁定。物料可能打滑、横向滑动、碰撞、转动或倾倒。均匀移动平面不会自动把偏离中心线的物料拉回中心，需要导轨/挡板等真实几何或另行声明的约束。不能为保证演示效果偷偷把横向坐标重置。

## 5. 空间端点、输送面、工艺区域的区别

| 内容         | 用途                               | 是否直接驱动物料       |
| ------------ | ---------------------------------- | ---------------------- |
| 空间端点接口 | 吸附、装配、布局连接               | 否                     |
| 输送面       | 有效承载范围、法向、流向、表面驱动 | 通过物理接触和摩擦驱动 |
| 工艺观测区域 | 入口可用、出口到达、占用等状态检测 | 否                     |

Conveyor_aankws 的入口/出口局部坐标分别为 [-0.749,0.700,0] 与 [0.751,0.700,0]。两点差归一化后是 +X，可作为与流向定义的一致性检查，但不作为运行时物料轨迹。

两个吸附端点间距为 1.500 m，有效上层皮带长度约为 1.400 m。两者描述不同几何对象，不应为了统一数值而扩张物理支承面。跨设备吸附完成也不自动证明物理承载面连续。

## 6. 坐标转换与归一化约定

设备定义保存模型/设备根坐标系下的数据。GLB 子节点自己的局部点需要先经过节点父链转换到设备根坐标系；作者工具中的“世界坐标”只有在明确了导出根与导入变换后才能直接使用。

```text
p_world = M_instance × M_import × p_device_local
```

若点属于运动关节节点，还需要插入该节点相对于设备根的实时变换。正向计算每层只应用一次；从世界刚体姿态回写渲染子节点时，应使用父节点世界变换的逆，而不能再次套用设备变换。

位置和方向不同：位置受到平移影响，方向不受平移影响。对一般可逆线性变换 A，方向采用 normalize(A × d)，面法向采用 normalize(inverse(transpose(A)) × n)。单位缩放情况下，二者均可按旋转处理。零方向、奇异缩放和不支持的变换需要拒绝，不得对零向量做归一化。

当前实现只支持水平、单位缩放、无模型导入偏移的实验；上述一般转换是后续开发规范，不能据此说当前已支持任意倾斜或非均匀缩放。当前物理适配层按旋转后的局部 +X 算流向，并没有实现任意 flow_axis 的通用驱动。

## 7. 三类刚体：声明、创建和识别

| 运动类型             | 如何运动                                | 常见用途                   | 是否被普通碰撞力推动                           |
| -------------------- | --------------------------------------- | -------------------------- | ---------------------------------------------- |
| Static 静态刚体      | 物理步中保持固定姿态                    | 地面、固定机架、固定输送台 | 不会作为普通动态物体被推动                     |
| Dynamic 动态刚体     | 由质量、惯性、重力、力及接触求解        | 箱体、工件、托盘           | 会                                             |
| Kinematic 运动学刚体 | 由控制器给定运动目标/速度，参与接触求解 | 主动升降平台、受控机构部件 | 通常按受控运动推进，不以动态受力积分决定其轨迹 |

运动学刚体需要通过后端支持的运动更新 API 驱动，让其他物体感受到正确的运动速度；不能只改渲染节点就认为有物理作用。机械臂部件也可以采用其他动态/伺服模型，运动学并非所有机械臂的唯一实现。

刚体类型由模型/执行配置声明，编译器验证，后端创建时设置相应运动类型。GLB 是显示资产，物理引擎不会自动从模型名称判断这是传送带、物料还是升降台。

“静态/动态”与“设备业务角色”分别记录。地面和输送台都可能是 Static，但只有登记了输送能力的面才施加表面驱动。碰撞层用于过滤哪些对象允许发生碰撞，也不是业务角色或运动类型的替代物。

当前实验的 JoltPhysicsBackend.box(..., dynamic) 只创建 Static 或 Dynamic，尚未提供 Kinematic 设备执行能力。它直接保存 belt/material 句柄以支持单带单物料。后续扩展应采用运行对象登记表，将 instanceId、业务角色、BodyID/子形状和句柄对应起来，并在销毁时撤销登记，避免使用已释放或复用的 ID。

## 8. 如何识别物料接触输送面的时刻

物理世界先注册输送面的碰撞体与物料的动态碰撞体。每个固定物理步由求解器处理候选碰撞和接触，不需要业务脚本逐件判断是否跨过入口点。

```text
筛选可能接触的对象
    ↓
精确接触检测，形成接触点/法向/深度等信息
    ↓
接触回调识别刚体和有效输送面
    ↓
配置该接触的表面速度
    ↓
求解摩擦、碰撞和实际运动
```

| 回调               | 作用                                     |
| ------------------ | ---------------------------------------- |
| OnContactAdded     | 新接触建立；可作为物理接触开始的通知     |
| OnContactPersisted | 接触持续；更新当前驱动速度和相关接触设置 |
| OnContactRemoved   | 接触结束；多物料实现可在此清理接触关联   |

“建立瞬间”是离散仿真步中识别到接触，不是现实连续时间下绝对精确的时间点。接触容差、预测接触和碰撞算法也会影响建立时机，因此不要求两个显示网格先明显穿透。

当前代码中 Added 与 Persisted 都调用同一个 contact 函数，先比较刚体 ID，再依据接触法向过滤有效支承面。仅靠包围盒进入或任意碰撞事件不够：撞到输送机侧面，不能也被当作站在带面上输送。

水平实验采用承载法向朝向判定（经 body1/body2 顺序修正后 Y 分量至少为 0.8）。这是当前水平场景的实现阈值；未来斜面应比较接触法向与该输送面的世界法向，而不是固定比较世界 Y。

当前 support 在每个逻辑步开始时清零，再由接触回调置为 true；含义是“本步检测到有效支承接触”，不等于完整的多物料持续接触数据库。当前物料禁用休眠以保证实验观测；推广时需结合接触缓存、移除事件、休眠/唤醒及子步边界，不能机械地把没有回调视为物料离开。

## 9. 表面速度不是给物料一次初速度

物料运动不是在进入瞬间调用一次 SetLinearVelocity 后自行滑到出口。当前处理是：有效接触存在时，向接触设置提交当前相对表面速度。

```ts
// 机制示意，实际符号取决于接触对中两个刚体的顺序。
listener.OnContactAdded = contact;
listener.OnContactPersisted = contact;
contactSettings.mRelativeLinearSurfaceVelocity = surfaceVelocity;
```

皮带刚体本身可以保持固定姿态，接触表面却具有虚拟运动速度。可以把它理解为固定位置的传送装置不断让接触面沿带方向运动；无需把整个皮带网格向前搬移。

对任一接触点，刚体自身的点速度还包含线速度和角速度作用：

```text
刚体接触点速度 = 质心线速度 + 角速度 × 接触点相对质心的位置
接触求解还考虑声明的表面运动项
```

物理求解器综合两个接触体的点速度、表面运动、法向约束及摩擦，计算物料实际速度变化。传送带脚本不用自行计算完整摩擦动力学，也不能直接把物料速度覆盖成带速。

当前适配器里的正负号用于满足 Jolt 的接触对方向约定：当皮带是 body1 或 body2 时，设置的相对表面速度符号不同。代码中出现负号不一定意味着反向输送；需要结合接触体顺序解释。

## 10. 为什么必须持续处理接触

| 场景                     | 正确解释                                                   |
| ------------------------ | ---------------------------------------------------------- |
| 物料先放在停带上，再开机 | 已有接触持续，更新接触表面速度后被带动，不需要重新“进入”   |
| 运行中改变速度           | 后续接触求解使用更新后的表面速度，物料响应受摩擦限制       |
| 运行中停带               | 表面按驱动策略减速；物料可因惯性继续运动一段距离           |
| 物料被挡板挡住           | 带面可继续运行，物料因碰撞受阻并可能打滑或转动             |
| 物料离开输送面           | 不再获得该面的接触驱动，但已有速度、重力和其他接触继续生效 |
| 物料在上方悬空或从旁经过 | 没有有效支承接触，不得因为位于投影范围就被带动             |

这也是为什么入口/出口检测不能代替接触检测。工艺区域负责解释当前阶段，碰撞接触负责实际物理作用。物料从中间位置放到带面上，同样可以被运行中的输送面带动。

## 11. “定义好了速度”与“运行中计算速度”

定义时给出默认速度、允许范围、方向和加减速配置；运行时根据输入与当前状态求本步速度。

```text
speed_mps 默认值 / speedTag 运行命令
    ↓ 唯一有效控制来源
runTag 许可与状态判断
    ↓
速度坡道求出本步表面速度标量
    ↓
坐标转换得到世界流向
    ↓
标量 × 世界流向 → 接触表面速度向量
    ↓
物理求解得到物料实际速度与位姿
```

当前 Conveyor 默认速度 0.4 m/s，软件允许范围 0–2 m/s；运行许可关闭时目标降为零。加减速按既有参考速度与时间计算。物料速度与表面速度分开读取，不能把前者直接设为后者来证明运动正确。

## 12. 当前代码位置与调用顺序

| 路径（apps 下）                                               | 当前作用                                                      |
| ------------------------------------------------------------- | ------------------------------------------------------------- |
| src/domain/runtime/compileConveyor.ts                         | 验证受限实验配置、解析参数、计算世界初始位置和朝向            |
| src/runtime/templates/DeviceTemplateRegistry.ts               | 管理设备脚本工厂                                              |
| src/runtime/templates/conveyor/ConveyorTemplate.ts            | 读取命令、执行速度坡道、发布设备反馈                          |
| src/runtime/mechanisms/SpeedRamp.ts                           | 计算驱动速度变化                                              |
| src/runtime/engine/RuntimeKernel.ts                           | 固定顺序调用脚本、物理、区域观测和任务观察                    |
| src/runtime/engine/SignalRegistry.ts                          | 当前受限手动信号通道和输出快照                                |
| src/runtime/physics/createPhysicsBackend.ts                   | 加载物理适配后端                                              |
| src/runtime/physics/jolt/JoltPhysicsBackend.ts                | 创建刚体、绑定接触回调、计算/提交世界表面速度、调用 Jolt 求解 |
| src/runtime/engine/RegionObserver.ts                          | 根据实际位姿与接触观测判断区域状态                            |
| src/runtime/engine/ActionGateway.ts                           | 对指定主体的到达、掉落、超时和取消做结果关联                  |
| src/renderer/RuntimeSceneBridge.tsx / RuntimeMaterialView.tsx | 显示运行快照中的实际物料姿态                                  |
| src/services/RuntimeController.ts                             | 为 UI 提供场景准备、运行、命令和生命周期入口                  |

实际求解器是 node_modules/jolt-physics 中的 Jolt 库，固定依赖包存放在 vendor。runtime/physics 是项目自己的适配层，不是全部物理算法源码。

当前每一步的顺序：冻结输入 → beforePhysics 提交表面速度 → 物理步进 → 读取物料和接触 → 区域判断/任务观察 → afterPhysics 发布反馈 → 渲染快照。到达后自动停带是本轮实验策略，不是物理库自动理解“到达出口应该停止”。后续更通用的工艺决策应由上层控制策略承担。

## 13. 后续开发必须遵守的约束

1. 参数、节点绑定、碰撞体、输送方向和观测区域有明确来源；不让物理引擎猜测 GLB 的业务语义。
2. 单一模拟时钟，驱动计算在物理前、实际反馈在物理后；不能各脚本各开计时器。
3. 动态物料位姿只有一个求解写入者，渲染和行为脚本不能同时写位置。
4. 区分表面速度、刚体速度和接触点速度；区分物理接触、工艺到达与交接成功。
5. 静态/动态/运动学类型与业务角色、碰撞过滤层分别定义。新增运动学能力需验证其对其他物体的实际接触作用。
6. 扩展多物料时，用 BodyID/子形状和业务身份登记表管理接触，观测须带 subjectId/tick；不能沿用全世界一个 support 布尔值。
7. 方向归一化和坐标转换只执行约定的层次，测试设备旋转、导入变换以及父子节点关系。
8. 任务完成必须属于当前请求和主体；速度设定正确、进度 100% 或经过固定时间均不能单独证明完成。
9. 保留暂停、受控停带、停止会话和恢复基线的区别。结束接触不代表物料速度立即归零。
10. 首期仍为直线、水平、单位缩放实验；弯道、斜面、运动学平台和下游交接另行定义能力与验收，不因已有概念说明而宣称支持。

### 15.1 运动表面不等于运动学刚体

Conveyor_aankws 的机架与带面碰撞体固定，推荐 motion_type=static，通过虚拟接触表面速度输送物料。不能因为“表面在运动”就把整条输送机声明为 kinematic。

kinematic 用于碰撞体本身由脚本改变位置/姿态的机构，例如升降台或旋转平台。新刚体契约应能表达 static/dynamic/kinematic；本轮生产闭环先实现 static 输送面与 dynamic 物料。kinematic 以能力开关显式预留，未完成目标更新和接触验收前拒绝运行，不伪装成 static 或动态刚体。

## 16. 新契约组织：刚体与输送面分别声明

建议使用 type_specific_contract.physics.bodies[] 统一声明物理对象，以适应一个设备包含多个刚体。每个 body 有稳定 body_id、motion_type、role、coordinate_space、local_pose、collider 和接触材料来源。单刚体物料也使用此结构，避免另设第二套字段。

conveying_surface 增加 body_ref；它引用 bodies 中的承载刚体，并声明该刚体上的输送区域、法向、流向和驱动通道。不是所有 static 刚体都具有输送能力，地面不会因运动类型相同而被误当作传送带。

最小结构示意（引用的参数须在完整 schema 中声明；这是待实现格式）：

```json
{
  "physics": {
    "bodies": [
      {
        "body_id": "belt_body",
        "motion_type": "static",
        "role": "conveying_support",
        "coordinate_space": "device_local",
        "local_pose": {
          "position": [0.0005, 0.65, 0],
          "rotation_quaternion": [0, 0, 0, 1]
        },
        "collider": {
          "kind": "box",
          "length_param": "length_m",
          "width_param": "width_m",
          "thickness_param": "deck_thickness_m"
        },
        "contact_material_ref": "belt_contact"
      }
    ],
    "contact_materials": {
      "belt_contact": { "friction_param": "surface_friction", "restitution": 0 }
    }
  },
  "conveying_surface": {
    "surface_id": "main_belt",
    "body_ref": "belt_body",
    "coordinate_space": "device_local",
    "flow_axis": [1, 0, 0],
    "normal": [0, 1, 0]
  }
}
```

示意局部位姿对应现有 0.7 m 带高和 0.1 m 厚度，不能泛化为所有可调尺寸设备的固定坐标。正式实现应由结构化位姿规则从 surface_height_m、deck_thickness_m 等参数派生中心，不重复维护两个独立高度。运行器不 eval 字符串公式。

本轮所用 schema 版本建议升级为契约 1.3，具体发布前应同时更新解析器、校验器和数据。旧 1.2 实验继续保留明确兼容入口；新版本缺少物理定义时拒绝真实运行，不静默退回固定 fixture。

## 17. Conveyor_aankws 的补充计划

1. 保留两个吸附端点和已有参数。interfaces 仍只负责空间连接，不增加信号绑定或工艺驱动能力。
2. 以 conveying_surface.flow_axis/normal 为输送方向与法向的唯一权威。旧 motion_model.axis 在迁移期作为兼容引用/一致性检查，不能两处分别修改。
3. physics.bodies 显式声明 belt_body 为 static，定义其局部位姿、碰撞尺寸、材料与业务角色；地面由场景物理配置创建，不混进每台设备实例。
4. conveying_surface.body_ref 校验必须存在且角色支持输送；复合碰撞体未来还需明确子形状范围，不能让侧面、支脚或整个包围盒都获得驱动。
5. 输送方向与承载面法向单位化且正交；后端根据实例和导入变换计算世界方向，表面速度大小保持 m/s，不随视觉缩放被意外放大。
6. 实现时优先保证水平单位缩放，改变流向/倾斜/缩放时须有明确能力检查；不能让 schema 接受 +Z 流向而后端仍暗中使用 +X。
7. 观测区域采用显式坐标/形状或受约束的派生规则，随设备变换，不能继续依赖只对原实验箱体适用的硬编码中心区间。

## 18. engine_block 物料建模计划

### 18.1 已确认的文件事实

当前目录只有 engine_block.glb，没有 schema.json。GLB 为 2.0，大小 707604 字节，一个节点、一个 mesh，无骨骼和动画；节点名为 Mesh [00Sg]。依据 POSITION accessor 边界及节点变换做的初步包围盒检查：

| 项目 | 值（模型单位按 glTF 米解释，实际尺度仍需确认） |
| --- | --- |
| X 范围 | 约 -0.198586 ～ 0.198586 |
| Y 范围 | 约 0.000001 ～ 0.300001 |
| Z 范围 | 约 -0.245000 ～ 0.245000 |
| 包围尺寸 | 约 0.397172 × 0.300000 × 0.490000 m（X/Y/Z） |

这些是几何事实，不提供质量、密度、摩擦、真实重心或允许载荷。现有目录构建脚本要求每个设备子目录有 schema.json；目前直接重新生成目录会因 engine_block 缺少 schema 而失败。实施时优先补草稿定义及对应校验策略，不用临时伪造完整参数绕过。

### 18.2 需要的设备契约

- device_type=workpiece，asset 指向同目录 GLB，记录文件哈希与模型根映射。
- 按所选碰撞近似声明 length_m/width_m/height_m、mass_kg、friction、restitution 等必要参数，能力未启用的字段不强制填写。
- physics.bodies 中声明一个 dynamic 物料刚体，正质量、碰撞形状、局部位姿、接触属性和质心/惯性策略。
- 初期用明确标为 approximation 的 box 碰撞代理；不把任意 GLB 三角网格直接当可用的动态碰撞体。后续如有孔洞、凸起或接触失真，再评估 convex/compound，未支持的形状必须拒绝。
- 物料保持被动：不增加自己的 run/execute 运动入口；由接触或外部持有关系驱动。状态信号按需由引擎投影。
- 初版无吸附需求时 interfaces=[]。底部支承参考属于物料几何/放置模型，不是空间连接接口。

### 18.3 必须解决质心与模型原点差异

该模型原点接近底面，而包围盒中心在局部 y≈0.15。若采用均匀 box 代理并用盒心近似质心，应明确这是仿真近似，不能假定是真实发动机零件的重心。

```text
物理刚体世界位姿 = 实例世界变换 × 导入变换 × 刚体局部位姿
模型根世界位姿 = 物理刚体世界位姿 × 刚体局部位姿的逆 × 导入变换的逆
```

这里“模型根”指作者实例根；如果渲染器更新的是导入后的资产根，应按该节点的实际父链使用对应变换，避免重复应用导入变换。物料旋转时偏移也随之旋转，不能始终只减去世界 Y 上的 0.15。

放置时通过支承参考点对齐带面：模型底面靠近 y=0.700，刚体中心应约为带高 + 半高 + 初始接触间隙。不能复用旧 0.1 m 箱体的质心高度 0.78。

### 18.4 物料与带面适配

默认朝向下物料宽约 0.49 m，当前带宽 0.5 m，总余量约 0.01 m。不能仅因包围盒数字小于带宽就保证稳定输送；需检查碰撞边界、侧向间隙、初始偏移和可能的旋转。是否改朝向或使用其他带宽，需要实验记录，不能静默缩小模型。

物料质量需要用户数据或明确标注的仿真实验设定，不能沿用旧箱体 0.2 kg 并宣称真实质量。草稿可以缺失 mass_kg；目录/结构校验允许展示草稿，但运行前必须解析出合法正质量。对应地要分开“设备定义合法”和“实例可运行”的校验，当前导入器会直接检查必填参数完整性，需要调整。

## 21. 实施顺序与验收

1. 确认 engine_block 的模型尺度、质量来源、碰撞代理和支承方向；新增可展示草稿，避免缺 schema 使目录构建中断。
2. 先在参数/设备契约中确定字段和迁移规则，再写 Conveyor 与 engine_block schema、结构校验器和运行前完整性校验。
3. 重构刚体描述与 BodyRegistry，分别验证 static/dynamic 创建及销毁；kinematic 明确为未支持或完成专门移动平台验收后再开放。
4. 从契约编译输送方向、表面和真实物料；验证局部/世界坐标转换与质心偏移。
5. 接触回调按登记身份工作，工艺观测按主体工作，最后接入真实 GLB 运行和基线恢复。

验收必须包括：改变设备绕 Y 旋转后输送方向一致；同为 static 的地面不驱动物料；侧面碰撞不被误认为顶部输送；物料离开和再次接触正确更新；两个物料的支承状态互不串扰；错误 body_ref/质量/形状或未支持运动类型拒绝运行；engine_block 不陷入带面，旋转后模型/碰撞代理仍重合；任务到达关联正确；重置不改变作者文档。

记录带宽余量、物料质量、代理碰撞误差与实验条件，不将正常一次输送推断为所有姿态均稳定。运行 npm test、类型检查、lint、生产构建和真实模型浏览器测试；截图应同时能辨认实际物料与输送面。

## 22. 本轮实施结果

已发布 Conveyor_aankws 0.6.0 与 engine_block 0.1.0，采用契约 1.3。physics.bodies 声明 Static 输送刚体和 Dynamic 物料；conveying_surface.body_ref 绑定承载对象，方向来自已验证的 flow_axis/normal。kinematic 可在结构中表达，但当前编译器/后端明确拒绝运行；没有将其降级为 static。

engine_block 没有默认质量，可作为草稿展示、添加和保存；运行前必须填写正质量。其固定盒代理尺寸约 0.397172 × 0.300000 × 0.490000 m，刚体局部中心 [0,0.1500005,0]，采用 uniform_box 惯性近似。场景运行直接更新选定物料实例的渲染根，使用完整逆绑定变换，不创建第二份替代箱体。物料几何/原点不因运行被改写。

BodyRegistry 已按业务实例/bodyId/Jolt ID 登记；ConveyorContacts 已从后端拆出，按刚体和子形状对登记有效接触。每个物理子步清理并重建接触观测，所有动态体暂禁用休眠，步末查询来自最后子步；多物料接触隔离和离开带面清除已测试。复杂休眠缓存、任意凸体/复合体、运动学平台仍是后续扩展。

界面支持添加两种真实资产、选择运行物料、填写质量、显式“物料放到入口并对齐”，再启动输送。放置是一次作者编辑；运行不会偷偷把场景中的任意物料瞬移到带面。运行只作用于选中输送机和物料，其他场景设备不参与该物理世界。停止/重置后真实物料恢复作者位姿，停止时最后的运行快照仍用于诊断。

实际支持范围仍为水平、单位缩放、局部 +X/+Y 的直线输送。其他方向会明确拒绝，避免忽略契约。姿态求解会读取导入和刚体局部变换，接触后端接收归一化的世界方向和法向。物料包围投影越出带宽或承载长度会拒绝启动；该检查不等于任意动态姿态都保证稳定。
