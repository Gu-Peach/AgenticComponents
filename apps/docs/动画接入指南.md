# 动画迁移接口

接触式 Conveyor 场景实验已通过 RuntimeController → SimulationSession → RuntimeKernel → ConveyorTemplate/Jolt 路径接入，详见 development-plans/003-2026-10-30-runtime-engine-and-device-templates.md。下文的 AnimationAdapter 描述仍用于旧单行为预览；它不会自动为新场景实验提供物理世界。两条路径互斥，停止/重置语义分别明确。

工作台已完成编辑界面和预览框架。真实运动实现由你后续迁移，当前没有把 Mock 作为设备动作执行器注册。

## 1 从哪里接入

| 文件                                                  | 用途                                               |
| ----------------------------------------------------- | -------------------------------------------------- |
| `src/contracts/device.ts`                             | DeviceDefinition、行为和参数契约、场景实例         |
| `src/contracts/preview.ts`                            | AnimationAdapter、PreviewSession、上下文与结果类型 |
| `src/runtime/adapters/agent/registerAgentAdapters.ts` | 集中注册真实执行器，当前为空                       |
| `src/runtime/PreviewController.ts`                    | 请求/版本/条件检查、生命周期、结果核验             |
| `src/runtime/ObservationSource.ts`                    | 后续设备/传感器状态的接入源                        |
| `src/renderer/SceneObjectRegistry.ts`                 | three 对象到窄节点读写接口的桥接                   |

调用方向：右侧行为面板 → PreviewController → ExecutorRegistry → AnimationAdapter → PreviewSession → 节点变换与观测反馈。UI 不直接调用 IK 函数。

## 2 定义到执行器的映射

设备定义的 `behaviors[].executorRef` 必须等于适配器的 `id`。

旧 `robot_arm_1` 导入后，抓放行为的执行器引用为 `agent.robot_pick_place`；模板机械臂的引用为 `agent.robot_arm.pick_and_place`。这是两份不同定义的不同引用，迁移时明确统一或分别注册，不按名称模糊匹配。

```ts
// src/runtime/adapters/agent/registerAgentAdapters.ts
import { robotPickPlaceAdapter } from "./robotPickPlaceAdapter";

export function registerAgentAdapters(registry: ExecutorRegistry) {
  registry.register(robotPickPlaceAdapter);
}
```

建议先完成单设备 `move_to_pose`，验证节点、单位、关节限位、TCP 和到位误差，再迁入抓放组合动作。旧 DeviceSpec 原文在 `definition.source`，关节结构在 `typeSpecificContract`；不要从 UI 组件或其他项目全局 store 取配置。

## 3 生命周期实现约定

| 方法                              | 执行器负责什么                                                            |
| --------------------------------- | ------------------------------------------------------------------------- |
| `capabilities()`                  | 支持的行为 ID、暂停和恢复基线能力                                         |
| `validate(input)`                 | 参数/结构/算法支持检查，返回带路径的诊断，不产生动作                      |
| `prepare(input, context, signal)` | 解析节点、记录基线、创建求解器；异步步骤检查 AbortSignal；不开始运动      |
| `start()`                         | 本次会话开始；资源和节点已准备完成                                        |
| `tick(dt, simulationTime)`        | 固定步长推进，更新节点并返回最新观测；progress 只用于 UI                  |
| `pause()` / `resume()`            | 暂停/恢复同一会话，不重复接受命令                                         |
| `stop(reason)`                    | 确认运动终止，返回当前 requestId 的 cancelled 或 failed；不返回 succeeded |
| `result()`                        | 未终止返回 null；到位/失败返回终态证据                                    |
| `restoreBaseline()`               | 恢复 prepare 时记录的运行姿态，与“停止”是两个操作                         |
| `dispose()`                       | 幂等清理监听、求解器与临时资源，不释放视口拥有的 GLB 资源                 |

prepare 取消后迟到的会话会被立即 dispose，不能重新 start。节点读写还会检查会话代次和对象归属。控制器保留最后一个已完成会话，便于用户恢复基线；下一次启动或重置时释放它。

## 4 节点坐标和所有权

上下文提供 `hasNode(instanceId, nodeName)`、`readNode()`、`writeNode()`、`log()`。`$root` 表示场景实例根节点；其他名称在该根节点下精确查找。GLB 节点重名须在迁移时消除歧义。

NodePose 的 position 为节点相对父节点的局部平移；quaternion 为 `[x,y,z,w]` 的局部四元数。引擎场景 Y 向上，长度米。IK 若在世界坐标求解，适配器必须自己完成局部/世界坐标转换，并处理设备根变换、GLB 单位和 TCP 偏移。

当前 MVP 只将当前实例列入 `affectedInstanceIds`，一次只运行一个会话。跨设备抓放物料不可偷偷改写另一实例：后续需扩展请求的受影响对象声明、校验目标存在性，并在动作开始前统一获得这些对象的使用权。此处尚无多设备资源调度器。

运动结果只写入视图和 RuntimeSnapshot，不修改 `project.instances[].transform`。不要把 Object3D、求解器、回调或 Blob URL 放入项目 JSON。

## 5 前置条件与完成证据

条件来源支持 parameter、observation、authorization。默认仅授予本地预览授权 `local_preview=true`，不会自动授予物料存在、工位空闲或目标可达。

迁入传感/设备状态后，在运行集成层调用：

```ts
observations.publish(instanceId, {
  device_ready: true,
  material_at_input: true,
  gripper_empty: true,
});
```

行为里的 `preconditions[].key` 要与这些事实键对应。观测未知时真实预览被阻止。旧字符串条件如 `material_at(input_process_port)` 目前保留为 `legacy:...` 观测键，需由迁移器显式映射；没有 eval 或表达式猜测。

真实适配器成功时示例：

```ts
return {
  requestId: input.request.requestId,
  status: "succeeded",
  evidence: "observed",
  observations: { at_target: true, ik_converged: true, tcp_error_m: 0.0006 },
  issues: [],
};
```

对应的 `completionChecks` 至少声明所需布尔事实，例如 `at_target=true`、`ik_converged=true`。数值误差是否小于阈值目前由执行器计算布尔事实；条件 DSL 首期仅实现严格相等，尚无任意比较表达式。控制器会检查 requestId、evidence 和全部完成条件，进度 100% 不构成成功证据。

不要直接沿用旧项目“elapsed >= duration → done”的物理成功逻辑。若真实动作要模拟时长，仍应分别报告时间进度和实际达到目标的观测。

## 6 需要由迁移阶段补齐的内容

- 将模板标定成完整设备定义，并将 `template` 设为 false；这不是自动转换步骤。
- 原始关节/节点、坐标转换、TCP、工作空间、负载以及完整参数校验。
- 把旧字符串条件与效果映射为结构化条件及完成观测。
- 传感观测的实时更新和失效/新鲜度策略；当前观测源是接入槽，不能当作分布式实时状态系统。
- 真实 IK/输送算法、暂停和停止语义、资源范围。
- 如需在线速度设定，扩展明确的 setpoint 通道；目前预览期间作者文档整体只读。
- PLC runtime 是另一服务入口，不通过当前 ST 文本面板冒充执行。

## 7 验证迁入的执行器

至少验证：节点缺失拒绝、错误目标拒绝、前置条件未知拒绝、prepare 取消无迟到运动、暂停不推进、停止不成功、到期未到位不成功、恢复基线、重复点击只接受一次、预览不改变项目 JSON。已有 `tests/preview.test.ts` 可作为测试入口。

## 机械臂运行接入

契约1.4的 robot_UR10 采用 RobotProgram 和 robot.articulated@1 模板，沿用同一个 RuntimeController/SimulationSession/RuntimeClock。RuntimeKernel 组合运行程序，ConveyorProgram 保留出口观察和停带策略，RobotProgram 管理机械臂任务。编译场景以 kind 区分，机器人空载预览无需物理后端。

RobotKinematics 是唯一FK，CcdPositionIK只返回目标关节解及收敛结果，JointTrajectory以固定逻辑步推进执行态。RobotSceneBridge仅将执行态q投影到当前GLB克隆关节，不在渲染中重新求解；停止/重置恢复源节点局部旋转。完整GLB父链、根变换与TCP偏移参与计算。

物理抓放使用运动学工具与动态物料之间的Jolt固定约束；没有把物料改为TCP子节点。持有状态来自GraspService/约束，释放后等待指定支承与停稳观测。携物阶段可用 move_to_pose.subject=held_material 求解物料中心位置，support_clearance会根据旋转后外形提高释放高度。position_only不保证工具朝向，因此当前工具明确采用允许所有朝向的虚拟球形捕获，不声称是真实夹爪。

运行面板支持关节目标、带坐标系的TCP目标、空载任务、受控保持/恢复及固定约束抓放。所有命令走统一网关并冻结参数、校验唯一请求ID。当前手动API拥有任务握手写权，PLC信号执行尚未接入；缺失外部条件维持无效。
