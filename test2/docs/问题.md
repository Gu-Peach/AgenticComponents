## 研究点二目的

将三维场景转化为智能体能够查询、理解和推理的工艺语义环境，支持它根据工艺需求，规划出具体设备、操作对象、操作位置及工步依赖。

## 三个子研究点回答的问题

2.1：场景中需要表达哪些信息，才能支撑工步规划？
2.2：智能体如何利用这些信息，推理出每一步由谁、对什么、在哪里执行？
2.3：如何将工步方案准确转换为符合契约和语法要求的 DSL？

## 2.1 建模目的

针对三维场景中的几何与设备信息难以直接支撑智能体工艺推理的问题，构建设备实例、契约能力、操作对象、空间目标及协作约束的场景语义表示，建立工艺需求与场景实体之间的关联，为智能体的设备选择、空间目标绑定和工步衔接提供可查询、可解释的依据。

场景模型要解决的是“三维空间事实与工艺操作之间缺少明确关联”的问题。

例如，场景中存在机械臂 R1、输送线 C2 和 C4。知道它们的坐标和尺寸，还不足以回答：

- R1 可以操作 C2 上的哪些物料？
- 托盘需要移动到哪里，才能开展抓取？
- C4 上哪个位置适合作为放置目标？
- 从 C2 到 C4 的物料转移，需要哪些设备行为？
- 哪些空间或交接条件尚未确认？
  因此，场景模型要建立的是：

设备实例 → 契约能力 → 可作用对象 → 操作位置 → 协作关系 → 适用条件

这条关联链，才是帮助智能体从“看见设备”进一步理解“能够怎样组织设备完成工艺”的关键。
